* Scope

This note evaluates NoneCap as one narrow solver provider behind [[id:star-captcha-000-broker-router][STAR-CAPTCHA-000]]. It does not define the overall CAPTCHA taxonomy and does not imply that hCaptcha is the only challenge StarIntel actors encounter.

NoneCap currently advertises active =hcaptcha= and =hcaptcha_enterprise= solve types. Its documentation reserves names for reCAPTCHA, Turnstile, and FunCaptcha, but reserved names are not active capabilities and must not be registered.[fn:capability]

* Provider Summary

NoneCap is an hCaptcha-focused hosted application programming interface[fn:api] operated by Lunium AB in Sweden. The public =v1= contract uses JavaScript Object Notation over Hypertext Transfer Protocol Secure with bearer authentication.[fn:bearer]

| Capability | Current public contract |
|------------+-------------------------|
| Create | =POST /v1/solves= |
| Blocking create | =POST /v1/solves?wait=N=, where =N= is 1 through 90 seconds |
| Retrieve | =GET /v1/solves/{id}= |
| Long poll | =GET /v1/solves/{id}?wait=N= |
| Cancel | =DELETE /v1/solves/{id}= |
| List | =GET /v1/solves= with cursor pagination |
| Account balance | =GET /v1/me= |
| Feedback | =POST /v1/feedback= |
| Authentication | =Authorization: Bearer <key>= |
| Active challenge types | =hcaptcha= and =hcaptcha_enterprise= |

A solve may be =pending=, =solving=, =solved=, =failed=, =cancelled=, or =expired=. The contract returns queue and resolution timing and reports credits charged after terminal completion.

* Billing, Retention, and Disclosure

NoneCap charges successful hCaptcha challenge rounds. A challenge can require multiple rounds, so budget reservation is a bounded variable amount. Failed, expired, and cancelled solves are documented as uncharged.

Solve records are retained by the provider for approximately thirty days. Target uniform resource locators, site keys, timing, status, and billing metadata therefore leave the local boundary. Provider keys, returned tokens, proxy credentials, and Enterprise data must never enter durable StarIntel messages.

* Strengths

- Narrow and explicit hCaptcha contract.
- Long polling and cancellation map cleanly to actor runs.
- Structured states, errors, timing, balance, and feedback.
- Bearer authentication avoids key-in-query exposure.

* Risks

- Service maturity and reliability history remain limited.
- Create does not document a provider idempotency key.[fn:idempotency]
- Provider retention creates a disclosure dependency.
- Variable challenge rounds make cost estimation approximate.
- Reserved future types could be mistaken for active capabilities.

* StarIntel Decision

Retain NoneCap as the hCaptcha reference adapter, not the global CAPTCHA reference provider. Enable only exact hCaptcha capabilities after contract fixtures, security review, operator budget, and live-canary approval.

* Test Requirements

- Every HTTP status and solve state.
- Standard and Enterprise mapping.
- Duplicate delivery and ambiguous submission.
- Long-poll deadline calculation.
- Cancellation race and already-terminal conflict.
- Bearer key, result token, proxy, and Enterprise-data redaction.
- Reserved challenge names never become runtime capabilities.
- Opt-in bounded live canary on an operator-owned page only.

* Footnotes and Glossary

[fn:api] Application programming interface: A documented network boundary through which software submits requests and receives structured responses.

[fn:bearer] Bearer authentication: A method where possession of a secret token in the authorization header authenticates the caller.

[fn:capability] Capability: A precise issuer, challenge family, variant, context requirement, and result kind that an actor advertises as supported.

[fn:idempotency] Idempotency: The property that repeating one logical request does not create an additional provider job or charge.
