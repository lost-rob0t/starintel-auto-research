- [[file:../../design/star-server/QUASAR-002-clog-hybrid-prototype.org][QUASAR-002 CLOG Hybrid Prototype Architecture]]
- [[file:../../design/star-server/QUASAR-003-graph-document-command-protocol.org][QUASAR-003 Graph Document and Command Protocol]] — blocked on prototype evidence

Quasar is a basic typed graph editor first. Its core is graph-document editing, layout, persistence, import, export, undo, and typed node and edge operations. Quasar extensions and external integrations own optional actions and transforms. Star-Lang may contribute compatible type libraries, document specifications, predicates, relations, identifiers, and import or export contracts, but it does not provide Quasar transforms. Domain servers, distributed actors, evidence workflows, and large-scale projections are optional integrations rather than prerequisites for the editor.

The selected prototype baseline is now SBCL, Common Lisp, CLOG, and a hybrid Cytoscape.js composite component. CLOG owns browser bootstrap and ordinary UI controls while Cytoscape retains high-frequency graph interaction in the browser. The canonical graph, graph operations, undo, action discovery, action execution, and persistence remain in a CLOG-independent Common Lisp core. React, TypeScript, Tauri, and a formal public graph protocol are deferred until prototype evidence shows they are required. The earlier TypeScript client research remains an extraction option rather than the immediate implementation baseline. The reserved protocol design is =QUASAR-003= and remains blocked until manual edits, batches, undo, persistence, session reconstruction, and one action have been exercised.

The actor architecture now has two required execution tiers. Quasar's browser edition remains usable without a local service and runs only bounded, explicitly limited worker actors. A separate Common Lisp runtime provides the true persistent supervisor tree, background runs, durable journals, native integrations, and plugin lifecycle through the same UI and a versioned =ActorRuntime= protocol. Both tiers submit validated graph-operation batches through the canonical command and undo path.

The operational user interface is now split into two coupled surfaces: the typed graph investigation workbench and a situational-awareness dashboard shell. The dashboard stores layouts, panel instances, variants, map state, refresh policy, and bounded projection configuration; it does not become a second canonical object model. Both surfaces share stable identifiers, selections, queries, revisions, actions, runs, evidence references, permissions, and drill-down paths.

The completed Star-Lang foundation defines a bounded declarative Common Lisp language for durable analysis runs, explicit actor effects, capability routing, checkpoint replay, and declared condition and restart handling.

The specification/domain loop defines digest-locked data-only libraries, additive typed-document extension, explicit source/predicate/destination relations, immutable attached datasets, actor contracts, and keyed domain-server manifests. Domain servers are the Star-Lang declaration layer over cl-gserver/Sento managed components; they own bounded aggregate authority and indexes rather than creating one actor per document.

The logic integration adds an engine-neutral =star-logic= protocol above =star-prolog= and the proposed =star-rules= runtime. Star-Lang compiles =reason= forms into immutable capability-routed logic-call nodes and pins the selected backend before execution.

The research loop[fn:research-loop] follows the order recorded in the canonical idea backlog unless a dependency requires a different order.

This loop compares mature intelligence and open-source intelligence platforms, extracts reusable product patterns, maps those patterns onto the current StarIntel architecture, and proposes the next focused design.

** TODO Loop 002: Collection Actors

- [[file:../../research/star-server/STAR-RESEARCH-002-awesome-osint-research-backlog.org][STAR-RESEARCH-002 Awesome OSINT Research Backlog]]

This loop now has a 48-point source-derived queue covering catalog foundations, collection-actor families, analysis workflows, operator interfaces, provider validation, and continuous source-drift maintenance. The Awesome OSINT directory is treated as a discovery inventory; every provider must still be classified as an actor, manual source, dataset, workflow, visualizer, library, or rejection before implementation.

** REVIEW Loop 003: Budgeted Supervised Prolog Inference Actors

- [[file:../../research/star-server/STAR-RESEARCH-003-budgeted-supervised-prolog-inference-actors.org][STAR-RESEARCH-003 Budgeted Supervised Prolog Inference Actors]]

This loop selects the Expert-System Actor Framework idea and defines one testable =star-server= vertical slice: a Common Lisp authority actor supervising an isolated Prolog worker, with typed Target and actor-manifest schemas, multidimensional budgets, named queries, proof documents, deterministic replay, monitoring triggers, and tightly gated LLM research integration.

** REVIEW Loop 004: Internal Prolog Server Library

- [[file:../../research/star-server/STAR-RESEARCH-004-internal-prolog-server-library-swi-nprolog.org][STAR-RESEARCH-004 Internal Prolog Server Library: SWI-Prolog and N-Prolog]]

This continuation defines the internal =star-prolog= library boundary. SWI-Prolog MQI is the reference process backend, an optional =libswipl= C shim is deferred for trusted low-latency work, and Sasagawa N-Prolog is supported as a one-shot process backend for compatibility, portability tests, and experimental distributed logic. The library owns typed terms, declared query sessions, capability negotiation, supervision, cancellation, budgets, pooling, proof normalization, and engine conformance profiles.

** REVIEW Loop 005: Star-Lang Logic Integration and LISA Performance

- [[file:../../research/star-lang/STAR-LANG-RESEARCH-021-star-logic-runtime-integration.org][STAR-LANG-RESEARCH-021 Star-Logic Runtime Integration]]
- [[file:../../research/star-server/LISA-RESEARCH-001-performance-and-feature-extension.org][LISA-RESEARCH-001 LISA Performance and Feature Extension]]
- [[file:../../design/star-server/STAR-ADR-002-hybrid-logic-runtime-model.org][STAR-ADR-002 Hybrid Logic Runtime Model]]

This loop selects a hybrid performance model. SWI-Prolog remains the default recursive, tabled, constrained, and named-query backend. A redesigned LISA-derived =star-rules= engine is reserved for persistent small-delta forward chaining after strict allocation, latency, correctness, proof, isolation, and replay gates pass. N-Prolog remains an explicitly pinned compatibility backend. Star-Lang sees only =star-logic= capabilities and immutable selected-backend plan fields.

** REVIEW Loop 006: Discord Watch Common Lisp Port

- [[file:../../research/star-server/STAR-RESEARCH-005-discord-watch-common-lisp-port.org][STAR-RESEARCH-005 Discord Watch Common Lisp Port]]

This loop selects the Discord Self-Bot Collection Actors idea and audits the existing JavaScript prototype. It defines a Common Lisp supervised collection core with machine-enforced target scope, credential leases, deterministic Discord-native IDs, raw-event and checkpoint journals, reliable RabbitMQ publishing, and replaceable Node, Python, and native Common Lisp session adapters. The final runtime is a purpose-built passive Common Lisp Gateway adapter rather than a full port of the archived Discord.js selfbot API.

** REVIEW Loop 007: BEAM/LFE Large-Scale Ingest Contingency

- [[file:../../research/star-server/STAR-RESEARCH-008-beam-lfe-large-scale-ingest-contingency.org][STAR-RESEARCH-008 BEAM, Erlang, and LFE as a Large-Scale Ingest Contingency]]

This loop is intentionally research-only. The current Common Lisp actor ingest remains authoritative. BEAM/OTP is kept in reserve for a future point where measured cl-gserver/Sento behaviour shows that runtime concurrency, supervision, multi-node operation, observability, or mailbox behaviour is itself the limiting factor. Erlang is the conservative ready-to-use BEAM language; LFE remains a serious Lisp-native option because it targets the same runtime and StarIntel can build missing tooling if the eventual runtime payoff justifies that work.

** RESEARCHING Loop 008: Thunder Audio and Weather-Correlation Geolocation

- [[file:../../research/star-server/STAR-RESEARCH-009-thunder-audio-weather-geolocation.org][STAR-RESEARCH-009 Thunder Audio and Weather-Correlation Geolocation]]

This loop now has a captured transcript attachment and a concrete reproduction program. The YouTube URL remains the execution target; =SnbkIm56TfI.en.srt= is attached input evidence. The transcript-derived baseline is a 20–250 Hz RMS envelope, slant-range sound-arrival model, relative amplitude model, window-local normalization, smoothing, unknown-time sweep, cosine similarity, FFT acceleration, a coarse 5 km world grid, and coarse-to-fine refinement. Six bounded branches separately validate the lightning-feed contract, acoustic model, signal extractor, search/scorer, false positives, and blind reproduction. The video's reported 5 km best-point result remains a source claim until the blind reproduction gate passes.

** REVIEW Loop 009: Evidence-Aware Intelligence Graph Seeds

- [[file:../../research/star-server/STAR-RESEARCH-010-evidence-aware-intelligence-graph-seeds.org][STAR-RESEARCH-010 Evidence-Aware Intelligence Graph Seeds]]

This compact loop groups seven related seeds instead of expanding them into seven projects. It keeps claim-level contradiction, unanswered questions, corroboration-aware deduplication, actor capability discovery, temporal relation qualification, graph-rarity ranking, and raw-data replay in one evidence-aware graph research direction. Provenance and replay are the strongest foundational candidates; unanswered-question records remain experimental.
