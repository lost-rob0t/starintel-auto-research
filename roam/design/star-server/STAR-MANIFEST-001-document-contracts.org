#+title: STAR-MANIFEST-001 Actor and Dataset Manifest Document Contracts
#+description: Separate camelCase wire contracts for executable actor declarations and dataset catalog, storage, lineage, and flow bindings.
#+status: DRAFT
#+filetags: :starintel:design:star-server:manifest:actor:dataset:org-roam:

* Decision

Actor Manifest and Dataset Manifest are separate StarIntel document schemas. They must not share one generic manifest field map.

All fields inside their wire-level =data= objects use camelCase. Existing v0.9 snake_case manifest fields are migration input, not the target contract.

* Actor Manifest boundary

Actor Manifest describes executable behavior and deployment requirements. Its field groups are:

- identity: =actorId=, =label=, =description=, =actorVersion=, =protocolVersion=, =specCompatibility=
- behavior: =roles=, =accepts=, =produces=, =inputPorts=, =outputPorts=, =routing=
- implementation: =implementation= and =runtime=
- dependencies and configuration: =dependencies=, =configuration=, =optionsSchema=
- authority and limits: =capabilities=, =permissions=, =datasetRestrictions=, =resources=, =rateLimits=, =budgetLimits=
- delivery and failure policy: =mailboxPolicy=, =retryPolicy=, =deadLetterPolicy=, =restartPolicy=, =loopDetection=, =errorPolicy=
- lifecycle: =healthChecks=, =readiness=, =shutdown=, =checkpointing=

=implementation= must contain at least one implementation locator: =inlineSource=, =entrypoint=, =package=, =uri=, =builtInId=, or =serviceUrl=.

** Prohibited instance membership

Actor Manifest must not contain =documentIds= or legacy =document_ids=. An actor declares accepted and produced document types through =accepts= and =produces=; it does not enumerate document instances.

Concrete document membership belongs to Dataset Manifest. Per-run document references belong to execution requests, run records, or checkpoints.

Actor Manifest validation must reject =documentIds= and =document_ids= as unknown properties.

* Dataset Manifest boundary

Dataset Manifest describes catalog and data-lake state. Its field groups are:

- identity: =datasetId=, =name=, =description=, =datasetVersion=, =specCompatibility=
- membership and schema: =documentIds=, =documentTypes=, =schemaRefs=, =predicateRegistryRef=
- storage: =storageBindings=, =storageLayers=
- derived data: =indexes=, =materializations=, =embeddings=
- execution bindings: =actorBindings=, =flowBindings=
- graph references: =graphRefs=
- governance: =lineage=, =validationPolicy=, =statistics=, =accessControl=, =retentionPolicy=, =publication=, =migrationHistory=

=flowBindings= declares ports, routes, mailbox keys, buffering, backpressure, retries, and dead-letter destinations. It does not embed an executable workflow.

=graphRefs= points to separate =star-graph= documents or records graph materializations. Executable workflow semantics belong to =star-graph=, not Dataset Manifest.

* Compatibility

Do not mutate frozen historical schema artifacts in place. Introduce the separate contracts in the next schema version, provide explicit migration from v0.9 shared manifest fields, and regenerate maintained language bindings and conformance fixtures from the same canonical schema.

* Implementation gate

Before implementation, freeze exact nested object shapes, required fields, enum values, and schema conditions in this node. Every maintained specification library must then receive the same positive and negative fixtures, including a negative Actor Manifest fixture containing =documentIds=.

* Glossary

[fn:actor-manifest] A declarative description of an executable actor's interface, implementation, runtime, authority, and lifecycle policy.
[fn:dataset-manifest] A declarative catalog of dataset membership, storage, derived representations, lineage, and execution bindings.
[fn:star-graph] A separate executable workflow or graph contract referenced by manifests where needed.
