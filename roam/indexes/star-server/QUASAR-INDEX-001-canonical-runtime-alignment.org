* Why the Split Exists

The former QUASAR-004 page combined canonical authority, standalone browser behavior, Auto-Dig fork governance, protocol layering, graph renderer scale, validation, and migration sequencing.

Those are different architectural questions with different evidence and implementation owners. They are now separated so a reviewer can approve one without accidentally approving the others.

The old QUASAR-004 path remains valid and now points to the narrow canonical-runtime decision.

* Migration and Validation Order

The earlier migration list is moved here because it spans several focused designs rather than belonging to canonical runtime authority alone.

1. Review QUASAR-004, QUASAR-005, QUASAR-006, and QUASAR-007 independently.
2. Verify current =quasar= repository topology and update stale repository documentation.
3. Audit current code against the QUASAR-003 unblock evidence checklist.
4. Promote QUASAR-003 to =REVIEW= only when observed evidence is sufficient.
5. Build initial =star.graph.v1= and =quasar.control.v1= conformance fixtures[fn:conformance-fixture].
6. Narrow =quasar-ui= roadmap wording to the approved QUASAR-005 web-edition scope.
7. Replace permissive Auto-Dig bridge payloads with the approved QUASAR-006 typed contract.
8. Add QUASAR-007 graph-scale benchmark fixtures and select safe renderer tiers from measurements.
9. Add crash/replay evidence for any multi-document durable batch claim.
10. Move additional durable operations behind canonical =quasar= authority only after the relevant focused designs and protocol contracts are approved and validated.

* Footnotes and Glossary

[fn:index] Index: A navigation file that groups related research/design documents and their dependencies so reviewers can find the authoritative decision for each subject.

[fn:quasar] Quasar: The StarIntel graph workspace and runtime family used for investigation, document review, actor runs, graph projection, and dataset navigation.

[fn:common-lisp] Common Lisp: The Lisp language used by the canonical Quasar runtime and StarIntel actor infrastructure.

[fn:conformance-fixture] Conformance fixture: A fixed test input and expected normalized behavior used by multiple implementations to prove they interpret a shared protocol consistently.
