* URI Direction

The canonical STAR URI family is:

#+begin_example
star://<authority>/<resource-kind>/<resource-path>
#+end_example

Examples:

#+begin_example
star://gserver.starintel.actor/document/01K...
star://gserver.starintel.actor/service/starintel-mcp
star://gserver.starintel.actor/actor/user-hunt
star://gserver.starintel.actor/actor/quasar/user-hunt
#+end_example

Everything following =/actor/= is an actor resource path. The protocol does not preserve fixed old =domain= or =address= fields.

Legacy:

#+begin_example
star://domain:address:actor-name
#+end_example

is accepted only through bounded compatibility/migration code. Migration requires an explicit new target URI or mapping.

* Footnotes and Glossary

- *STAR URI* — Canonical transport-neutral =star://= identity using RFC 3986 hierarchical authority/path syntax.
- *Authority* — Stable logical owner/resolver of a STAR namespace, independent from its current network endpoint.
- *Resource path* — Hierarchical segments following the resource-kind segment, interpreted by the owning resource contract.
- *Compatibility input* — A legacy syntax accepted for migration but not emitted as the new canonical identity.
- *Durable dataflow* — RabbitMQ-backed distributed work/document/event flow with settlement and retry semantics.
