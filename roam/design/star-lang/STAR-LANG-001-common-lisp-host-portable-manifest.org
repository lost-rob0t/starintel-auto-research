* APPROVED Decision

Current-generation Star-Lang is a closed declarative language implemented only in Common Lisp.

For the current generation, Common Lisp owns parsing, source locations, origin chains, semantic validation, normalized IR, canonical manifest generation, lifecycle rules, deterministic execution, conditions, restarts, durable recovery, document construction, and runtime adapters.

No other external language may provide a current-generation Star-Lang parser, compiler, semantic engine, normalized-IR producer, dispatcher, or runtime.

Versioned JSON may cross process and language boundaries. JSON is an interchange format, not a second current-generation Star-Lang implementation.

This node approves the current-generation implementation language and architecture. It does not claim that every implementation acceptance criterion is complete.

* RESERVED Future Direction: StarLang Self-Hosting

Self-hosting is not denied as a possible future or next-generation StarLang direction.

A later generation may investigate moving some or all compiler stages into StarLang itself, including a staged bootstrap from the canonical Common Lisp implementation. This possibility does not modify the current-generation implementation contract and is not an active roadmap item.

Planning authority is reserved to nsaspy:

1. no self-hosting research plan, roadmap, design, prototype, migration, or implementation effort may begin without explicit nsaspy authorization for that effort;
2. autonomous agents and repository automation must not infer permission to start self-hosting work from this section;
3. permission to plan does not itself authorize implementation;
4. an authorized plan must define the target generation, trusted bootstrap base, compiler-stage ownership, conformance tests, migration boundaries, rollback strategy, and compatibility relationship to the current Common Lisp compiler;
5. the Common Lisp implementation remains canonical unless and until a later explicit architecture decision changes that authority.

The architectural intent is therefore: current generation stays Common-Lisp-hosted; future self-hosting remains possible but dormant until nsaspy explicitly activates planning.

* APPROVED Current-Generation Architecture

#+begin_src text
source bytes
  -> Common Lisp closed parser
  -> Common Lisp parsed tree with spans
  -> Common Lisp semantic validation
  -> Common Lisp normalized IR
  -> Common Lisp runtime
       +--> direct handlers
       +--> cl-gserver adapter
       +--> transport adapters
       +--> versioned JSON boundaries
#+end_src

* APPROVED Parser Boundary

The Common Lisp parser must:

1. accept exactly one top-level unit;
2. recognize only Star-Lang grammar;
3. reject reader evaluation, unrelated dispatch syntax, dotted lists, and package-qualified names;
4. avoid interning attacker-controlled identifiers;
5. attach pathname, line, column, byte offset, and span length;
6. preserve origin chains through imports;
7. emit structured conditions;
8. perform no implicit network access;
9. pass parsed declarations through semantic validation before binding.

Import resolution is separate and injected. It verifies exact identity, version, and digest before compilation.

* APPROVED Core Semantics

- documents are typed and versioned;
- relations have explicit source, predicate, and destination;
- inheritance is additive;
- field access is explicit rather than dot syntax;
- actor contracts declare accepted and produced types;
- agent tools are declared capabilities;
- dataflows compile into named deterministic stages;
- persistence is explicit;
- transient values cannot be stored without conversion;
- commands carry correlation, causation, attempt, deadline, and idempotency identity;
- delivery is at least once and never claims exactly once;
- lifecycle completion and transport settlement remain separate;
- cancellation is cooperative and durable;
- actor readiness is a routing fact, not language truth.

* APPROVED Runtime Shape

The primary current-generation runtime is standalone and deterministic. cl-gserver and transports are optional Common Lisp adapters.

#+begin_src text
normalized command
       |
       v
Common Lisp deterministic dispatcher
       +--> direct registered handler
       +--> cl-gserver actor-of/tell adapter
       +--> external transport adapter
#+end_src

The dispatcher owns lifecycle, idempotency, deadlines, retries, cancellation, output publication, and terminal replay.

* APPROVED Recovery Model

Typed Common Lisp conditions expose explicit operator decisions such as retry, delayed retry, alternate compatible actor, verified cache use, offline continuation, optional-stage skip, branch abort, and correlation cancellation.

A restart is not durable by itself. Selecting one appends a serializable run decision before execution continues.

- Go implementation: DENIED for current-generation Star-Lang.
- Any other external current-generation Star-Lang parser, compiler, or runtime host: DENIED.

- Arbitrary host-language escape: DENIED.
- Dot syntax: DENIED.
- Actor frameworks as the semantic core: DENIED.
- Research-node schema extensions: DENIED.

External clients may consume versioned JSON through APIs and transports. They do not implement current-generation Star-Lang.

StarLang self-hosting is not included in the external-host denial list; it is the separately governed future direction above.

* APPROVED Implementation Order

1. keep the existing Common Lisp workflow green;
2. make source spans and origin chains first-class;
3. package the implementation as explicit ASDF systems;
4. replace shell digest and URL calls with injected Common Lisp ports;
5. freeze canonical manifest hashes and fixtures;
6. expose deterministic standalone execution;
7. bind optional cl-gserver execution;
8. add end-to-end compile, execute, replay, and recovery tests;
9. extract stable Common Lisp packages from the research repository.

Implementation progress is tracked in [[https://github.com/lost-rob0t/starintel-auto-research/issues/47][issue #47]].

Self-hosting work is intentionally absent from this implementation order unless nsaspy separately authorizes a future-generation planning effort.

* APPROVED Acceptance Criteria

These criteria define current-generation completion; they are not all claimed complete by this architecture decision.

- all current-generation Star-Lang implementation code is Common Lisp;
- malformed source never interns package symbols;
- every semantic error reports an exact span;
- imported declarations retain an origin chain;
- identical input produces byte-identical manifests;
- direct and cl-gserver execution produce equivalent lifecycle traces;
- redelivery does not reinvoke terminal work;
- publication resumes after injected failure;
- restarted runtimes reconstruct pending and terminal state;
- no research or application type leaks into the StarIntel schema;
- no alternate external-language current-generation Star-Lang implementation exists in the repository.

* APPROVED Change Rule

The Common Lisp language decision is final for current-generation Star-Lang. Do not add or restore another current-generation external implementation language without a new explicit reversal from nsaspy.

Future StarLang self-hosting is permitted as a potential direction, but planning it requires explicit nsaspy authorization and must not be started autonomously.
