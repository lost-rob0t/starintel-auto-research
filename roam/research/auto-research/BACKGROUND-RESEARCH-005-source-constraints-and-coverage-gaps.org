* Research Question

Which expected background-report capabilities are not available as unrestricted public bulk data, and how should StarIntel represent those gaps rather than inventing unsupported actors?

* Executive Finding

*KEEP GAPS FIRST-CLASS.* A self-sourced system can reproduce a large share of court, property, business, licensing, sanctions, nonprofit, aircraft, government-award, and public-registry research, but several commercial-broker capabilities do not have equivalent unrestricted public bulk sources.

StarIntel should publish =unsupported=, =query-only=, =credentialed=, =restricted-use=, and =jurisdiction-dependent= capability states rather than silently falling back to scraping or implying completeness.

* FBI Criminal-History Gap

The FBI Identity History Summary process is not an arbitrary third-party criminal-history lookup for private citizens. The FBI states that a person can obtain their own record and that it does not provide another person's arrest record through that process.

Actor implication:

- no =fbi-third-party-rap-sheet= capability
- allow =import-subject-provided-fbi-identity-history= as an evidence-import capability
- use court and corrections sources for independent public-record research

* State DMV and Driver-Record Gap

Motor-vehicle personal information is not an unrestricted national public dataset. The Driver's Privacy Protection Act generally restricts disclosure of personal information from state motor-vehicle records while enumerating specific permissible uses.

Actor implication:

- no public nationwide DMV-person mirror
- represent driver-record acquisition as jurisdiction-specific and purpose/credential dependent
- source profiles must declare the required request path and authorization context
- do not infer eligibility merely because a state offers an online driver service

* NSOPW Automation Gap

The Department of Justice NSOPW is a federation over jurisdiction registries. DOJ explicitly states that it does not provide a public web service or API for programmatic searches and that the browser interface is the only NSOPW search surface.

Actor implication:

- no =nsopw-api= capability
- no claim of a downloadable national NSOPW database
- prefer jurisdiction-native registry adapters
- retain NSOPW only as an optional bounded browser/search capability if later source terms and operator policy allow it

* SAM.gov Scraping Constraint

SAM.gov provides APIs and Data Services file extracts. Its terms prohibit automated gathering and web scraping of the interactive site.

Actor implication:

- use official APIs and public extracts
- never implement the normal SAM source actor by scraping the interactive website
- source-profile validation should reject an adapter that declares the browser site as its ordinary bulk-acquisition method when the extract/API exists

* FEC Individual-Contributor Use Constraint

Federal Election Commission data includes bulk individual-contribution records with contributor name, employer or occupation, location, date, amount, and committee information. The FEC separately states that individual-contributor information from reports may not be sold or used for commercial purposes or solicitation.

Because the intended background-report product can be commercial, individual-contributor records require a source-use policy gate before they are included in a paid report. This is a source-specific restriction; it does not apply automatically to every FEC dataset or every non-individual committee record.

Actor implication:

- mirror capability and report-export capability are separate decisions
- tag FEC individual-contributor source records with a restrictive-use policy marker
- commercial report export must not silently include source data whose declared use policy forbids that use
- committee, candidate, filing, enforcement, and other FEC datasets should be evaluated separately rather than blanket-disabled

* Commercial Contact-Enrichment Gap

No federal or state public source discovered in this pass provides an equivalent to the broad current-phone, historical-phone, email, utility, credit-header, and proprietary-address-history aggregation commonly sold by commercial investigative data brokers.

Public sources can still produce contact candidates from:

- professional-license records
- business filings
- court documents
- government filings
- property and recorder records
- public websites and documents

But those observations are fragmented and uneven. Auto Dig must expose this as a coverage gap rather than label a report complete merely because public-record sources were exhausted.

* State Court Fragmentation

Federal court discovery has PACER and RECAP, but state and local courts remain fragmented across state systems, county clerks, municipalities, vendors, and separate court types.

Actor implication:

- coverage is measured per jurisdiction and court family
- a completed Franklin County search does not imply statewide Ohio court coverage
- unresolved court families produce explicit gaps

* Bulk Availability Is Source-Specific

The absence of a documented bulk endpoint does not prove that none exists, but it does prohibit advertising a mirror capability until verified.

Current examples requiring further protocol research include:

- Ohio eLicense bulk/API access
- Ohio UCC bulk access
- FINRA BrokerCheck supported programmatic or bulk surface
- many county property and recorder systems
- many state sex-offender registries

The capability catalog should expose =research-needed= until the request/result contract is verified.

* Coverage-State Vocabulary

Every expected source family should resolve to one of:

- =mirrored-current=
- =mirrored-stale=
- =query-available=
- =query-failed=
- =credentialed-unavailable=
- =restricted-use=
- =browser-only=
- =manual-only=
- =source-not-found=
- =source-retired=
- =research-needed=
- =not-applicable=

A report can then state which evidence families were actually searched instead of emitting a false binary =background-check-complete= state.

* Research Gaps

- Research public and licensed telecom/contact datasets separately from government records.
- Build the fifty-state court and corrections source catalog and quantify actual coverage.
- Research state DMV access programs as credentialed source profiles without assuming nationwide equivalence.
- Profile each FEC dataset's applicable source-use rules so policy is attached at dataset granularity.
- Determine whether supported FINRA BrokerCheck bulk or API access exists for investigative use.

* Footnotes and Glossary

- *Coverage gap*: An expected evidence family that could not be acquired or verified for the requested scope.
- *Restricted-use*: Source data that is public to inspect but carries source-specific limits affecting a requested downstream use.
- *Query-only*: A source that supports targeted lookup but has no verified complete mirror surface.
