* REVIEW Objective

Define one durable contract that can describe Ohio state systems, county systems, delegated vendor portals, static files, APIs, dashboards, form-driven searches, document archives, and explicit coverage gaps without creating a schema fork for each county.

* REVIEW Invariants

1. A search result is never a verified source profile.
2. Every verified profile links to official ownership or delegation evidence.
3. Every profile is scoped to one government unit or component and one source family.
4. One endpoint may support multiple profiles when its authority or coverage differs.
5. One profile may contain multiple acquisition endpoints when they are one logical source.
6. Raw evidence and retrieval events are immutable.
7. Profile revisions are append-only and supersede prior revisions.
8. A source profile does not imply complete route coverage.
9. Negative findings are evidence-bearing assessments, not empty fields.
10. Review state is separate from acquisition state.
11. Current, historical, and future-effective content are measured separately.
12. Personal-data fields and access restrictions are recorded before acquisition is authorized.

* REVIEW Official Status

=:official-status= is one of:

- =:verified-official=
- =:verified-delegated=
- =:candidate-official=
- =:candidate-delegated=
- =:unverified=
- =:rejected=
- =:retired=

Promotion to =:verified-official= requires evidence from the government-controlled domain, an authoritative registry, or an authenticated official publication.

Promotion to =:verified-delegated= requires an official government page or document linking the vendor system to the government unit or component.

A matching logo, organization name, or search-engine result is insufficient.

* REVIEW Review State Machine

#+begin_example
:candidate
   -> :evidence-collected
   -> :verification-pending
   -> :reviewed
   -> :active
   -> :changed
   -> :reviewed
   -> :retired
#+end_example

Rejected candidates move to =:rejected= with a reason and retained evidence.

Only the Source Profile Authority may write canonical profile revisions. Workers submit proposals.

* REVIEW Validation Rules

A profile revision is invalid when:

- the government unit cannot be resolved
- the route is missing
- no locator exists
- verified status lacks ownership evidence
- delegated status lacks an official delegation link
- the preferred adapter does not advertise the needed capability
- temporal coverage is asserted without evidence
- a partial source is marked complete
- a browser-required source is assigned to a non-browser worker
- authentication requirements are omitted after observation
- content hashes or retrieval events are missing for promoted evidence
- review fields are self-approved by the proposing worker

* REVIEW Versioning and Migration

- profile identifiers remain stable across revisions
- locator identifiers remain stable while the logical endpoint remains the same
- vendor migrations create a new locator and successor relationship
- retired profiles remain queryable
- contract migrations are explicit and deterministic
- unknown fields from a newer contract are preserved when possible and never silently discarded

* REVIEW Ohio-Specific Extensions

Ohio-specific fields may exist only under an extension namespace:

#+begin_src lisp
(:extensions
 (:ohio
  (:state-system :ohio-laws
   :effective-version-kind :current
   :county-geoid "39049"
   :board-of-elections-code nil)))
#+end_src

An Ohio extension cannot replace generic fields required by the national source-profile contract.

* REVIEW Acceptance Criteria

1. one schema describes state and county sources
2. verified status always has ownership evidence
3. route coverage and profile lifecycle remain separate
4. negative findings require a completed search plan
5. temporal completeness is explicit
6. partial current-year sources cannot be marked complete
7. proposals and canonical writes are separated
8. profile revisions are replayable and append-only
9. Ohio extensions do not fork the national schema
10. the contract supports the adapter capabilities defined in =STAR-GOVDATA-DESIGN-003=

* REVIEW Required Fixtures

- verified official Ohio domain
- verified delegated county vendor portal
- rejected lookalike domain
- source with API and browser interfaces
- source with incomplete current-year data
- future-effective law version
- source with login-only write functions but public read functions
- source migration with retained predecessor
- negative finding with complete search plan
- profile proposal replay using the same idempotency key
