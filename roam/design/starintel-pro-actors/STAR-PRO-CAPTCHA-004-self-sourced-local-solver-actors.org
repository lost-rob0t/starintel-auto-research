#+title: STAR-PRO-CAPTCHA-004 Self-Sourced Local Solver Actors
#+description: Actor design for local OCR, audio, image-selection, geometry, browser-application, model-registry, benchmark, corpus, and operator-fallback CAPTCHA capabilities behind the existing authorized StarIntel broker.
#+status: REVIEW
#+filetags: :starintel:design:starintel-pro-actors:captcha:self-hosted:actors:common-lisp:onnx:ocr:audio:vision:security:uml:synthetic-data:

* Decision

Add self-sourced local solver capabilities to =starintel-pro-actors= and route them through the existing =CaptchaBrokerActor= and =CaptchaRunSupervisor=.

Do not create a second CAPTCHA broker and do not expose a public solve API.

The control plane remains Common Lisp. Specialized inference engines run as bounded local workers behind typed actor contracts. Model training/export may use framework-specific tooling offline, but production authorization, routing, lifecycle, result typing, deadlines, and secret references remain in the Common Lisp actor plane.

Initial capability actors:

- =LocalCaptchaSupervisorActor=;
- =LocalOcrActor=;
- =LocalAudioActor=;
- =LocalVisionActor=;
- =LocalGeometryActor=;
- =LocalBrowserApplyActor=;
- =LocalOperatorActor=;
- =LocalModelRegistryActor=;
- =LocalCaptchaCorpusActor=;
- =LocalCaptchaBenchmarkActor=.

The first implementation slice is a fake strategy followed by Tesseract-backed OCR on synthetic and operator-owned fixtures. Everything else is added only after the contract, sandbox, resource-limit, secret-reference, abstention, and downstream-verification path works end to end.

* Core Invariants

1. The existing broker performs authentication, =captcha:solve= authorization, target-policy checks, exact capability matching, and deadlines before a local solver receives work.
2. Local recognition actors receive bounded artifact references, not arbitrary target URLs.
3. Recognition actors have no general outbound network access.
4. Only the authorized source/browser runtime applies session-bound results or bounded interaction actions.
5. Tokens, cookies, answers, coordinates, selection sets, proofs, raw challenge media, and browser state remain ephemeral or represented by bounded opaque references.
6. Every local model or engine is hash pinned, provenance recorded, and capability scoped.
7. Every strategy can abstain.
8. Recognition success is not target acceptance; the source runtime records downstream acceptance separately.
9. Local speculation is compute-budgeted and bounded; no uncontrolled model fan-out.
10. Unknown challenge families remain =unsupported= until an exact local capability is registered and benchmarked.
11. Training/benchmark jobs are outside the solve hot path and cannot silently promote a model.
12. External paid providers are exact-capability fallbacks only when explicitly enabled by policy.

* Actor Responsibilities

** LocalCaptchaSupervisorActor

Owns one local attempt lifecycle and never bypasses broker eligibility.

Responsibilities:

- validate the exact local capability selected by the broker;
- resolve a pinned strategy/model from =LocalModelRegistryActor=;
- reserve local compute slots;
- enforce attempt deadline and cancellation;
- dispatch to one or more explicitly configured local strategies;
- merge or compare candidate results when an ensemble is configured;
- enforce calibrated confidence threshold;
- return =lowConfidence= or =unsupported= instead of inventing an answer;
- cancel child workers on deadline or caller cancellation;
- emit redacted resource/outcome telemetry.

It does not fetch arbitrary target pages.

** LocalOcrActor

Owns =textAnswer= recognition for exact OCR capabilities.

Default strategy order:

1. bounded preprocessing and Tesseract;
2. optional second OCR engine only when policy and registry enable it;
3. consensus/calibration;
4. abstain or local-operator escalation below threshold.

OCR support never implies image-selection, behavioral, browser-bound, or puzzle support.

** LocalAudioActor

Owns bounded audio transcription through a pinned local ASR worker, initially =whisper.cpp=.

It enforces encoded-size, decoded-duration, channel-count, sample-rate, and wall-clock ceilings before inference. Raw audio is not written to ordinary StarIntel documents.

** LocalVisionActor

Owns exact =selectionSet= or model-derived =coordinates= capabilities backed by pinned ONNX models or another separately approved local runtime.

It registers the exact label vocabulary, preprocessing contract, and output schema. A generic image classifier is not eligible for a task whose result requires multiple selections or geometry unless a fixture-backed strategy explicitly maps those outputs.

** LocalGeometryActor

Owns deterministic preprocessing/localization capabilities backed by OpenCV-style primitives. It may crop, segment, normalize, or produce an exact coordinate or bounded interaction result for a verified fixture family.

It does not advertise wildcard slider, rotation, or puzzle support.

** LocalBrowserApplyActor

Applies a previously produced typed result or bounded action inside the authorized source context when the result binding requires same-session execution.

It receives:

- opaque browser-session reference;
- opaque result reference or exact bounded action;
- capability/application instruction;
- target-policy ID;
- request/attempt IDs.

It does not receive permission to browse unrelated URLs. It never exports the full browser profile or cookie jar into a normal actor message.

** LocalOperatorActor

Provides local human-review fallback for explicitly authorized low-confidence or unknown rows.

The queue stores only bounded artifact references and expires them. Operator decisions are typed results with actor identity and timestamp. No remote vendor disclosure occurs.

** LocalModelRegistryActor

Maintains runtime eligibility for engines, models, preprocessors, and calibrated strategies.

Required fields:

- =modelId=;
- =strategyId=;
- semantic version;
- immutable content hash;
- source/provenance URL or local derivation;
- license metadata;
- engine version;
- preprocessing fingerprint;
- compatible exact capability IDs;
- expected input schema;
- output/result kind;
- fixture-set fingerprint;
- calibration fingerprint;
- resource profile;
- current state;
- promotion time and reviewer;
- rollback predecessor where applicable.

Production workers must never auto-download a model when a solve request arrives.

** LocalCaptchaCorpusActor

Owns deterministic synthetic corpus manifests and approved imports, not production model promotion.

Every durable sample records:

- source class;
- generator/version/seed where synthetic;
- asset and license provenance;
- exact ground truth;
- process/region annotations when applicable;
- renderer or preprocessing fingerprint;
- train/validation/test split;
- retention class.

Live production artifacts do not automatically become training data.

** LocalCaptchaBenchmarkActor

Runs offline or explicitly scheduled frozen fixture suites and emits promotion evidence. It cannot mutate the active model pointer by itself. Promotion is an explicit registry operation after review.

* Strategy Pattern

Local solvers use a strategy interface so actor orchestration does not depend on a specific inference engine.

#+begin_src common-lisp
(defgeneric strategy-supports-p (strategy challenge artifact-descriptor))
(defgeneric strategy-solve (strategy solve-context))
(defgeneric strategy-cancel (strategy attempt-id))
(defgeneric strategy-model-fingerprint (strategy))
(defgeneric strategy-resource-profile (strategy))
#+end_src

=STRATEGY-SOLVE= returns a normalized candidate object, never a raw provider-shaped payload.

#+begin_src common-lisp
(defstruct local-solve-candidate
  result-kind
  result-ref
  confidence
  confidence-model-id
  strategy-id
  model-fingerprint
  preprocessing-fingerprint
  latency-ms
  cpu-ms
  peak-memory-bytes)
#+end_src

The exact implementation can use CLOS strategy objects registered inside each capability actor. Engine invocation stays behind the strategy object.

* Multi-Step Action Contract

A local reasoning/puzzle strategy, if added later, never receives unrestricted browser control. It may emit only actions declared by an exact capability schema, such as a tile identifier, symbolic submit action, or a bounded coordinate region when symbolic actions are impossible.

#+begin_src json
{
  "allowedActions": [
    {"type": "clickTile", "tileIds": [0,1,2,3,4,5,6,7,8]},
    {"type": "submit"},
    {"type": "abstain"}
  ],
  "maximumSteps": 6
}
#+end_src

The source runtime owns application and may reject any action that violates the target policy, capability schema, deadline, or state transition.

The local solver never emits arbitrary URLs, JavaScript, shell commands, unrestricted navigation, credentials, cookies, or new network requests.

* Local Solve Sequence

#+begin_src plantuml
@startuml
participant "CaptchaRunSupervisor" as Run

participant "Sandbox Worker" as Worker
participant "EphemeralSecretStoreActor" as Secrets
participant "Source/Browser Runtime" as Source

Run -> Local : captchaLocalSolveRequest
Local -> Models : resolve exact capability + pinned strategy
Models --> Local : eligible strategy + limits + calibration
Local -> Secrets : read bounded challenge artifact
Secrets --> Local : ephemeral artifact handle
Local -> Solver : solve(exact capability, artifact handle)
Solver -> Worker : bounded inference
Worker --> Solver : typed candidate + resource metrics
Solver --> Local : normalized candidate
alt confidence passes
  Local -> Secrets : write typed result
  Local --> Run : captchaLocalSolveSucceeded(resultRef)
  Run -> Source : apply exact resultRef in original context
  Source --> Run : accepted / rejected / expired / inconclusive
else low confidence
  Local --> Run : captchaLocalSolveFailed(lowConfidence)
end
@enduml
#+end_src

* Concurrency and Backpressure

Local work is cheaper than paid work but can still exhaust the host if unbounded.

Use independent semaphores or actor pools for:

- OCR CPU workers;
- audio CPU/GPU workers;
- vision CPU/GPU workers;
- browser contexts;
- benchmark/training jobs;
- local operator queue.

The broker sees current local concurrency as capability health. If every local worker is saturated and the deadline cannot be met, the capability is temporarily ineligible rather than spawning unlimited processes.

Training and benchmark jobs use separate lower-priority resource pools so they cannot starve production solve actors.

* Worker Isolation

Recognition workers run with:

- no general network egress;
- dedicated unprivileged UID/service account;
- read-only model store;
- writable ephemeral scratch directory only;
- strict file-size and decoded-media limits;
- CPU quota;
- memory maximum;
- process count maximum;
- wall-clock timeout;
- no access to repository credentials, RabbitMQ credentials, browser profiles, or unrelated secrets;
- explicit model path from the registry, never a request-controlled path.

Nix should pin engines and fetch hashes where practical. systemd service/slice limits should enforce the production resource envelope.

* Media Validation

Validate before decoding and validate again after decoding.

Image limits include:

- accepted content types;
- maximum encoded bytes;
- maximum width and height;
- maximum total pixels;
- maximum frame count for animated formats;
- decode timeout;
- normalized output format before model input.

Audio limits include:

- accepted codecs/content types;
- maximum encoded bytes;
- maximum decoded duration;
- maximum channels;
- maximum sample rate;
- decode timeout;
- normalized PCM format before inference.

Reject malformed or over-budget media before it reaches the model.

* Model Promotion State Machine

#+begin_src plantuml
@startuml
[*] --> discovered
discovered --> quarantined : fetched/built + hash recorded
quarantined --> benchmarked : sandbox + frozen fixture suite pass
benchmarked --> experimental : reviewer promotes
experimental --> verified : owned-system canary + calibrated acceptance evidence
experimental --> invalidContract : schema/resource/safety failure
verified --> degraded : drift or known limitation
verified --> disabled : operator/security action
verified --> invalidContract : contract mismatch
degraded --> verified : repaired + re-benchmarked
invalidContract --> quarantined : new immutable build only
disabled --> experimental : explicit re-enable + review
@enduml
#+end_src

An in-place model file replacement is forbidden. New bytes mean a new fingerprint and promotion cycle.

* Corpus and Training Boundary

Training and benchmarking are separate from production solving.

Allowed durable corpus classes:

- deterministic synthetic StarIntel fixtures;
- first-party operator-owned fixtures;
- open datasets/benchmarks after license review;
- operator-labeled samples with explicit provenance;
- explicitly authorized real captures only when a bounded retention/provenance decision permits them.

Production challenge artifacts are ephemeral by default and are not silently recycled into training.

Corpus and training jobs cannot receive browser-session refs, cookie bundles, provider credentials, solved tokens, or other secret-bearing operational context.

* Security Audit

** Threat model

High-value assets include:

- authenticated source browser sessions;
- cookies, tokens, proofs, answers, selections, and coordinates;
- target authorization policy;
- model store and promotion authority;
- local compute resources;
- actor/RabbitMQ identity and routing;
- corpus provenance;
- operator review artifacts.

Potential adversaries include an untrusted target response, malicious media payload, poisoned model artifact, compromised worker process, spoofed actor message, and accidental operator misconfiguration.

** Findings and controls

| Finding | Severity | Control | Design disposition |
|---------+----------+---------+--------------------|
| arbitrary URL could turn system into a solve relay | HIGH | local solver accepts artifact refs only; broker validates target/purpose before capture | CLOSED BY DESIGN |
| browser/session secret leakage | HIGH | opaque session/result refs; browser apply inside source context; no cookie jar in actor payload | CLOSED BY DESIGN |
| malicious model supply chain | HIGH | immutable hashes, quarantine, no runtime auto-download, benchmark sandbox, explicit promotion | CLOSED BY DESIGN |
| decompression/media bomb | HIGH | pre/post decode ceilings plus process memory/time limits | CLOSED BY DESIGN |
| local compute denial of service | HIGH | per-class worker pools, broker eligibility from capacity, systemd/cgroup quotas, deadlines | CLOSED BY DESIGN |
| worker breakout sees repository/service credentials | HIGH | dedicated UID, no-network recognition sandbox, minimal filesystem, no broker/browser secrets | CLOSED BY DESIGN |
| unrestricted model-generated browser action | HIGH | typed family-specific action schema; source runtime owns application; no arbitrary JS/navigation | CLOSED BY DESIGN |
| model overconfidence forces bad answers | MEDIUM | calibrated threshold, abstention, downstream verification, no silent online retraining | CLOSED BY DESIGN |
| artifact retention leaks sensitive context | MEDIUM | ephemeral handles, TTL, redacted telemetry, explicit corpus promotion only | CLOSED BY DESIGN |
| capability widened by generic model | MEDIUM | exact capability registration includes result kind, binding, label/output schema, fixture fingerprint | CLOSED BY DESIGN |
| poisoned or unlicensed corpus | MEDIUM | immutable corpus manifests, source class, license/provenance metadata, explicit import review | CLOSED BY DESIGN |
| operator fallback becomes unbounded archive | MEDIUM | bounded queue, expiry, local disclosure only, audit identity | CLOSED BY DESIGN |
| stale model/engine silently changes behavior | MEDIUM | immutable fingerprints and state machine; no in-place replacement | CLOSED BY DESIGN |

Security verdict: APPROVED for the design boundary with the invariants above as mandatory requirements. Any implementation that permits arbitrary URL submission, general network egress from recognition workers, runtime model auto-download, raw cookie/profile transport, unrestricted model-generated browser control, or unbounded media/compute invalidates this approval.

* Test Plan

** Unit and fake tests

- broker rejects unauthorized local solve;
- local actor rejects a challenge whose exact capability does not match;
- malformed artifact metadata is rejected;
- oversized encoded image is rejected;
- decoded pixel ceiling is enforced;
- oversized or long audio is rejected;
- model hash mismatch is rejected;
- model path cannot be request controlled;
- low-confidence result abstains;
- candidate result-kind mismatch is rejected;
- out-of-schema multi-step action is rejected;
- cancellation terminates child worker;
- deadline terminates child worker;
- duplicate actor delivery is idempotent;
- raw result never appears in telemetry;
- raw cookie/browser profile never appears in a local solver message;
- unavailable capacity makes a capability temporarily ineligible;
- benchmark job cannot promote a model by itself;
- production solve does not add artifacts to a corpus automatically.

** Fixture tests

- synthetic distorted-text fixtures;
- multilingual text fixtures where enabled;
- owned audio fixtures;
- synthetic image-selection fixtures;
- coordinate/localization fixtures;
- corrupted image/audio fixtures;
- safe bounded decompression regression fixtures;
- model corruption/hash mismatch fixture;
- corpus provenance/license fixture;
- source-session application fixture on an operator-owned test page;
- vendor-published test-key integration fixtures where applicable.

** Canary gate

Canaries are opt-in and restricted to operator-owned or explicitly authorized targets. A canary must set:

- exact target policy;
- exact capability;
- maximum attempts or steps;
- deadline;
- model fingerprint;
- resource ceiling;
- artifact-retention TTL;
- expected downstream verification outcome.

No paid provider is required for CI or for self-sourced canary validation.

* Footnotes and Glossary

- *Self-sourced solver* — A local capability whose inference and primary benchmark path do not require a per-solve external CAPTCHA service.
- *Local recognition worker* — A sandboxed process that receives a bounded artifact/model reference and performs one exact inference operation without deciding target authorization.
- *Exact capability* — A solver contract matched on challenge family/variant/version, required fields, result kind, binding, action schema, and current validation state.
- *Model fingerprint* — Immutable content identity for a model/engine build tied to its benchmark and calibration evidence.
- *Abstention* — A normal terminal local outcome indicating insufficient confidence or unsupported capability.
- *Bounded action schema* — Capability-specific finite set of allowed source-runtime actions; excludes arbitrary navigation, JavaScript, shell commands, and credential changes.
- *Same-session application* — Applying a result/action through the original authorized source browser/session when acceptance depends on that context.
- *Opaque result reference* — Short-lived handle for sensitive result material that keeps raw tokens/cookies/answers out of ordinary actor messages.
