* REVIEW Objective

Make Ohio the first state executed from the generated jurisdiction catalog.

The program produces immutable self-describing subjects, CAS-linear independent reviews, and time-bounded atomic coverage gates for Ohio and all 88 counties. It records authority, identity, methods, scope, refresh, provenance, applicability, gaps, and history.

* REVIEW Runtime Contracts

The run pins independently reviewed runtime contracts:

#+begin_example
source-contract-id      = star.govdata.source-profile
source-contract-version = 1.0.0
applicability-contract  = ohio-route-applicability@1.0.0
protocol                = star.government-data.v1.1
#+end_example

Design-document versions, envelope protocol, payload schemas, source-record contract, applicability contract, and policy snapshots are distinct.

* REVIEW Architecture

Ohio is one state-scoped run over reusable actors/adapters. Governments/components are records and bounded job keys, not permanent actors.

Required authorities: Identity, Deployment, Profile, Search Plan, Gap, Route Assessment, Coverage Gate, Independent Review, Raw Artifact, Rate/Lease, plus provenance/coverage ledgers, domain/fingerprint pools, registry, and bounded workers.

Subject, review, and gate writers are disjoint. Coverage Ledger cannot synthesize completion. =PIPELINE-003/004= require approval before implementation.

* REVIEW Scope

Included: Ohio and 88 counties; official/delegated/shared/regional systems; all sixteen routes; Franklin first complete pilot; fingerprint-driven diverse counties; history in every wave; immutable reviews/gates.

Deferred: exhaustive subcounty governments; production crawling/normalization; automatic records requests; credential/terms/payment/control bypass; unauthorized protected data; unbounded history; continuous scheduling before acceptance.

* REVIEW Identity and State Seeds

The identity set includes Ohio, counties, and discovered auditors, recorders, clerks, election boards, sheriffs, engineers, treasurers, courts, commissions, health districts, and planning bodies. Each component records parent, function, authority, geography, evidence, confidence, and applicability topology.

State seeds include Ohio portal, Laws, Legislature, OhioBuys, Checkbook, OGRIP/OSIP/LBRS, Secretary of State, Supreme Court, Auditor, archives/retention, and records/open-meetings law. Checkbook is discovery/reconciliation evidence only.

* REVIEW Route and Historical Contracts

Route semantics come from one independently reviewed applicability contract. State substitution requires rule permission and proved scope.

Every wave records first/last observations, predecessor/successor, redirects, migrations, retired domains, archives, visible dates, and current/prior/future-effective distinctions.

* REVIEW Execution Waves

** Wave 0

Load GEOIDs; verify state identity/domains; capture legal/retention/archive authorities; create unresolved candidates; collect bounded platform/delegation/service/court/health fingerprints; record history.

A reviewed passed Wave 0 gate binds exact subjects/reviews and variation evidence. No county is complete.

** Wave 1

Profile state seeds and county crosswalks. A reviewed passed gate requires reviewed profile/deployment or blocked/unsupported subjects; source/applicability contract and policy bindings; adapter manifest/runtime bindings; rate/pagination/file/browser/auth/scope/artifact policy; raw evidence; Checkbook non-completeness; and history.

** Wave 2: Franklin

Franklin =39049= is the first complete county.

Its jurisdiction gate binds:

- reviewed =star.govdata.source-profile@1.0.0= contract snapshot
- reviewed applicability contract, policy, manifest set, and runtime set
- all sixteen exact route assessments/reviews
- all required subject reviews
- exact profile, deployment, search, subfamily, gap, evidence, and artifacts
- canonical basis schema/algorithm/time/hash, freshness deadline, and valid-through

It passes only with reviewed required subfamilies, no nonterminal states, evidence-bearing not-applicable, completed reviewed negative chains, fenced attempts, deterministic replay, zero unexplained truncation, and zero unresolved required manual review.

Independent Review reviews the gate. Only a currently valid reviewed passed gate counts as completion.

** Wave 3

Candidates: Cuyahoga =39035=, Hamilton =39061=, Lucas =39095=, Delaware =39041=, Athens =39009=, Vinton =39163=, Hancock =39063=.

Selection maximizes platform/vendor, authority hosting, publication maturity, office fragmentation, shared services, court/health topology, geography/size, and archive/migration variation. It retains a mid-sized non-large-metro or western/northwestern agricultural case unless equivalent coverage is proved.

Each county needs a reviewed current jurisdiction gate. A reviewed Wave 3 gate binds county gates, selection evidence, and metrics.

Pass requires no schema fork; at least 70% reusable-platform coverage of supported successful endpoints; reusable one-off semantics/fixtures; deterministic replay; zero unexplained truncation/stale lease acceptance; reconciled deployments; metrics within policy ceiling; and current negatives.

** Wave 4

Use at most eight active county runs with versioned batching and lease dimensions. Each county requires a reviewed current gate. State completion requires a reviewed state gate binding all 88 current county gates under one source/applicability contract and policy snapshot.

** Wave 5

Expand archives, reconcile migrations, establish refresh/retirement, define tombstones/replacements, reconcile captures, and acquire bounded history. Changes create new subject/review/gate revisions.

* REVIEW Courts and Freshness

Court coverage binds county courts, clerks, and authoritative linked local-court assessments. No unified API is not not-applicable.

| Class | Maximum age | Routes |
|-------+-------------+--------|
| high | 30 days | feeds, meetings, procurement, permits, operational metadata |
| medium | 90 days | open data, finance, elections, safety, public records |
| low | 180 days | identity, GIS, property, courts, archives |
| legal | next effective date or 180 days | law/policy |

Completion becomes false after gate valid-through or bound review invalidation without waiting for an expiry write.
