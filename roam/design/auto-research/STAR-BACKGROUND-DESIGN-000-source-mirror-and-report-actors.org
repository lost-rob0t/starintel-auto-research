* Objective

Translate the self-sourced background-report research into one actor design that Auto Dig can implement without inventing new source semantics, bypassing the government-data revision protocol, or advertising unverified adapters.

This design enumerates the actors. Implementation belongs in the Auto Dig/runtime repositories after the design and source contracts are accepted.

* Parent Protocol

This design is a specialization of the government-data actor system, not a replacement.

The following parent responsibilities remain authoritative:

- source profile and deployment revisions
- immutable artifact authority
- retrieval-event provenance
- rate and lease authority
- durable jobs and lease-bound attempts
- adapter registry and manifests
- source-contract versions
- independent reviews and coverage gates
- checkpoints and replay
- explicit gaps and failure states

Background actors add source-family implementations, person/entity resolution, evidence findings, and report assembly.

* Actor Manifest Requirements

Each source actor manifest must declare:

- stable actor and capability identifier
- source-family identifier
- source-contract ID/version
- execution class: mirror, delta, query, parser, resolver, assessment, report
- accepted input and emitted output types
- network hosts and method classes
- credential class if any
- cost unit if any
- source-use policy markers
- cadence/freshness expectation
- timeout/retry/concurrency defaults
- maximum requests, bytes, records, pages, and runtime
- raw-artifact policy
- checkpoint strategy
- idempotency key strategy
- parser schema versions
- supported and unsupported variants
- fixture IDs
- live-probe requirement
- current capability state

=PROFILE_REQUIRED= and =RESEARCH_REQUIRED= actors may exist as disabled manifests or scaffolds, but capability discovery must not advertise them as runnable.

* Supervision

Background Domain Supervisor uses =:rest-for-one= across ordered authority groups:

1. control and capability projection
2. mirror registry/acceptance/scheduler
3. query dispatch
4. resolution authority
5. coverage authority
6. report/export policy

Workers and parsers use one-for-one supervision beneath their family supervisors. A malformed IRS archive cannot restart PACER workers; a PACER authentication failure cannot stop NPPES mirroring.

* Scheduling

Mirror schedules follow source release behavior rather than one global cron:

- Ohio voter: daily after statewide package availability
- FAA aircraft: daily after source refresh window
- FAA airmen: monthly
- NPPES: weekly incrementals plus monthly full/deactivation reconciliation
- SEC bulk: nightly
- IRS TEOS/990: source publication checks on monthly/partition cadence
- LEIE: monthly
- OFAC: source-change polling plus delta retention
- SAM exclusions: public extract publication checks
- FCC ULS: transaction cadence plus full reconciliation when source contract supports it
- USAspending: scheduled partitioned bulk jobs

The scheduler emits no job when the remote release fingerprint matches the already accepted release.

* Acceptance Criteria

1. Every researched source family maps to an actor, an explicit disabled scaffold, or an explicit unsupported fixture.
2. Bulk-capable sources use mirror actors rather than per-subject remote lookup as the normal path.
3. Query-only sources never claim complete source coverage.
4. Mirror releases are immutable and current projections are rebuildable.
5. Delta sources reconcile against later authoritative snapshots.
6. Source roles and source-specific status semantics survive normalization.
7. Resolution is assertion-based and reversible.
8. Contradictions and source dependence remain first-class.
9. Report sections pin a coverage-basis revision.
10. Report findings trace to source records, retrieval events, and raw artifacts.
11. Unsupported actors fail capability validation rather than silently scraping alternatives.
12. Restricted-use source records cannot bypass export policy markers.
13. Actor crashes cannot advance release acceptance or report coverage state without committed evidence.
14. Deterministic replay reproduces report findings from pinned artifacts and versions.

* Footnotes and Glossary

- *Pinned authority*: A stable actor owning serialized canonical state for one domain responsibility.
- *Source worker*: A restartable actor that performs bounded acquisition or parsing but does not directly own canonical state.
- *Disabled scaffold*: An actor manifest/code shell present for integration planning but omitted from runnable capability discovery until its source contract is verified.
- *Coverage basis*: Immutable record of which source profiles, releases, queries, freshness states, gaps, and policy markers support one report revision.
