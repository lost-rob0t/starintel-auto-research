* Research question
Which reusable Common Lisp library boundaries should be built first so the same code can support MCP clients, MCP servers, LLM tooling, execution plans, provider adapters, and the final StarIntel Meta MCP package inside one monorepo?

* Constraint
The final application package must be a consumer of reusable libraries, not the place where protocol/runtime/provider logic is first implemented.

* Candidate library boundaries to validate
- MCP protocol/types and JSON-RPC transport primitives.
- MCP client library.
- MCP server library.
- Capability/provider registry.
- Execution-plan AST and executor.
- Concurrent task/actor runtime adapter.
- Search result/provenance model.
- Search fusion/dedup/ranking library.
- HTTP search provider adapters.
- MCP-provider adapter layer.
- StarIntel MCP client adapter.
- Optional A2A protocol library later, separate from Meta MCP.
