#+title: STAR-PRO-CAPTCHA-003 2Captcha Multi-Family Adapter
#+description: Exact-capability StarIntel Pro Actor design for the broad 2Captcha asynchronous task API, with per-family mappers, typed results, disclosure controls, contract drift, and a separate hCaptcha probe.
#+status: REVIEW
#+filetags: :starintel:design:starintel-pro-actors:captcha:2captcha:adapter:multi-family:uml:

* Decision

Implement =TwoCaptchaAdapterActor= as a broad asynchronous provider adapter. Each challenge family is an independently verified capability. The adapter is no longer globally disabled merely because hCaptcha documentation is uncertain.

hCaptcha remains disabled until a current contract probe passes. Verified reCAPTCHA, Turnstile, Arkose, GeeTest, Amazon, image/text, coordinates, grid, rotate, draw-around, drag-and-drop, or other family mappers may be enabled independently.

The adapter accepts only broker-normalized messages and has no public solve route.

* Generic Provider Contract

| Broker operation | 2Captcha operation |
|------------------+---------------------|
| =submitSolve= | =POST /createTask= |
| =pollSolve= | =POST /getTaskResult= |
| =cancelSolve= | unsupported unless a family contract later proves it |
| =getBalanceOrQuota= | =POST /getBalance= |
| =reportOutcome= | family-specific correct/incorrect operations |
| =healthSnapshot= | balance probe plus local circuit and contract state |

Callbacks are excluded from version one. Polling keeps the inbound server surface closed.

* Contract Records

Each enabled family has a versioned record containing:

- =capabilityId=;
- provider task type;
- normalized required fields;
- provider request mapping;
- expected result kind and required fields;
- proxy, cookie, user-agent, and network-binding requirements;
- execution/disclosure class;
- cost model;
- official retrieval date;
- request/result fixture fingerprint;
- state: =verified=, =experimental=, =degraded=, =invalidContract=, or =disabled=.

A generic provider account being healthy does not make every task mapper valid.

* Candidate Capability Families

The design can host exact mappers for:

- reCAPTCHA v2, v3, and Enterprise;
- Cloudflare Turnstile;
- Arkose Labs FunCaptcha;
- GeeTest variants;
- Amazon and Web Application Firewall challenge families;
- DataDome and Imperva/Incapsula families;
- Friendly Captcha, MTCaptcha, ALTCHA, Prosopo, CaptchaFox, Tencent, Yandex SmartCaptcha, and other documented vendor tasks;
- image-to-text, text questions, rotate, coordinates, grid, draw-around, and drag-and-drop;
- hCaptcha only after its independent probe passes.

This is an adapter framework, not an assertion that every listed mapper is already approved or implemented.

* Result Mapping

| Task output | Normalized result kind |
|-------------+------------------------|
| issuer response token | =token= |
| WAF clearance value | =token= or =cookie= |
| text answer | =textAnswer= |
| selected image cells | =selectionSet= |
| points, rectangles, or polygons | =coordinates= |
| rotate, slider, or drag actions | =interactionPlan= |
| score/assessment data | =assessment= where the contract truly returns it |
| family-specific object | =customTypedResult= with versioned schema |

The validator rejects a result kind that does not match the capability registration.

* hCaptcha Contract Probe

On explicit operator request, the adapter performs a bounded probe against an operator-owned test page or provider sandbox:

1. use configured candidate task type and fields;
2. require a provider task identifier;
3. retrieve the terminal result;
4. confirm token field and variant behavior;
5. record redacted fixtures and contract fingerprint;
6. advertise the exact hCaptcha capability only after success.

The probe has a strict maximum cost and never runs automatically on each startup. Historical names are configuration candidates, not trusted constants.

* Human-Assisted Disclosure

The provider may use human workers. The actor declares =executionClass: humanAssistedVendor=. The broker routes only when target policy permits this class.

The adapter discloses only fields and bounded artifacts required by the exact task mapper. It does not send full authenticated pages, unrestricted browser snapshots, or cookies unless an approved capability and policy explicitly require them.

* Idempotency and Cancellation

The generic contract does not document create idempotency or universal cancellation. Journal before =createTask=, record =taskId= immediately, attach duplicate deliveries to the existing attempt, and never automatically recreate an ambiguous task.

Local cancellation stops polling and deletes local result material. The task may complete and charge, so normalized cancellation reports =providerCancellationSupported: false= and =chargePossible: true=.

* Contract Drift State UML

#+begin_src plantuml
@startuml
[*] --> disabled
disabled --> probing : operator requests bounded probe
probing --> verified : request/result fixture passes
probing --> invalidContract : unsupported or schema mismatch
verified --> degraded : failure threshold exceeded
degraded --> verified : recovery probe passes
verified --> invalidContract : required field or result kind drifts
invalidContract --> probing : operator approves reprobe
verified --> disabled : operator disables
@enduml
#+end_src

Only =verified= capabilities are advertised to the broker.

* Testing

- Generic create, processing, ready, balance, feedback, and errors.
- One mapper and result validator fixture per enabled family.
- Every normalized result kind.
- hCaptcha disabled, successful probe, failed probe, and drift.
- One family drift does not disable unrelated verified families.
- Duplicate, ambiguous create, and local cancellation.
- Disclosure-policy denial before context dereference.
- Provider key, challenge artifact, and result redaction.
- No callback listener.
- Per-family opt-in live canaries with individual cost ceilings.
