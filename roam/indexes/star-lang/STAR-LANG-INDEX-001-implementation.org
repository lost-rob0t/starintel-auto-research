* Final Language Decision

Common Lisp is the sole approved Star-Lang implementation language.

Every alternate parser, compiler, semantic engine, dispatcher, and runtime implementation is DENIED.

The language and architecture decision is final. The implementation remains active until its acceptance ledger is complete.

- [[file:../../design/star-lang/STAR-LANG-001-common-lisp-host-portable-manifest.org][STAR-LANG-001 Final Common Lisp Architecture]]

* Runtime Repository

The durable actor runtime systems live in a dedicated Common Lisp-only repository so this research repository and =starintel-server= stay free of live runtime implementation.

- [[file:../../design/star-lang/STAR-LANG-003-star-lang-runtime-repository-provisioning.org][STAR-LANG-003 StarLang Runtime Repository Provisioning]]
- Repository: [[https://github.com/lost-rob0t/star-lang][lost-rob0t/star-lang]] (GPL-3.0, public, SBCL-first)

The real Common Lisp prototype implementation (65 files, ~15K LOC) now lives in =lost-rob0t/star-lang= under =prototype/= with all 24 test suites passing under SBCL. The prototype is organized as a transitional =starlang-prototype= ASDF system; the 15 target =star-*= and =starlang-*= systems are scaffolded placeholders to be filled incrementally by splitting the prototype along its natural boundaries.

No Racket, Scheme, Guile, or other alternate Star-Lang parser or runtime is retained.

Generated Python and TypeScript bindings are permitted boundary artifacts. They consume versioned JSON contracts and do not implement Star-Lang.

* Current Work Order

1. keep the Common Lisp workflow green;
2. make source spans and origin chains first-class compiler data;
3. package the Common Lisp implementation as explicit ASDF systems;
4. replace shell-backed digest and retrieval calls with injected Common Lisp ports;
5. add one top-level Common Lisp test runner;
6. freeze canonical manifest fixtures;
7. validate direct and cl-gserver lifecycle equivalence;
8. add end-to-end replay and recovery tests;
9. extract stable Common Lisp packages after boundaries stabilize.

* Invariants

- Star-Lang implementation code is Common Lisp only.
- Untrusted =.star= source never enters the Common Lisp reader.
- No unrestricted =EVAL= enters compilation or execution.
- Normalized IR does not contain cl-gserver object types.
- Versioned JSON is an interchange format, not another implementation.
- Direct execution works without cl-gserver.
- Actor systems remain optional Common Lisp adapters.
- Research nodes never extend the StarIntel schema.
- Auto-dig and Quasar consume contracts rather than defining them.
- Alternate implementation languages remain DENIED.

Move this index to =APPROVED= only after the implementation tracker is complete and the Common Lisp workflow validates the final package layout.
