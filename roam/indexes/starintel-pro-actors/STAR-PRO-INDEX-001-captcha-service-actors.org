* Scope

This index connects the provider-neutral StarIntel[fn:starintel] CAPTCHA[fn:captcha] subsystem across research, design, implementation, local self-sourced solving, external providers, transport, publication, and future operational work.

Core detection, authorization, exact matching, budgets, idempotency, secret references, cancellation, and downstream verification belong to =starintel-server=.[fn:star-server] External providers, local recognition engines, local browser workers, and manual-review actors belong to separately deployable =starintel-pro-actors= capabilities.[fn:pro-actors]

The subsystem is restricted to operator-owned systems, accessibility workflows, quality assurance, and explicitly authorized automation. It exposes no public raw solve endpoint.

* Research Findings Carried Forward

- Challenge issuer, family, variant, integration version, result kind, binding, solver actor, and provider are independent axes.
- The catalog is open-world and preserves =custom= and =unknown= until evidence supports narrower classification.
- Provider or local-model completion is not target acceptance; downstream verification records =accepted=, =rejected=, =expired=, =replaced=, or =inconclusive=.
- Sensitive tokens, cookies, answers, coordinates, selections, proofs, interaction plans, and challenge media remain ephemeral and are represented by opaque references.
- Provider/model capability drift is local to the exact capability unless shared runtime state fails.
- Current transport research favors Sento mailboxes for same-process actors and RabbitMQ for durable work crossing process/container/host boundaries; ZeroMQ remains deferred from that critical path pending its own evidence gates.
- Self-sourced local solving should be preferred for exact OCR/audio/image/geometry capabilities when calibrated local accuracy and source-context fidelity pass policy.
- Local solvers must abstain below calibrated thresholds and must not become a generic arbitrary-target bypass service.
- Paid providers remain fallback candidates only for exact rows that local capabilities cannot satisfy and that policy explicitly allows.

* Non-Goals

- Browser fingerprint fabrication or anti-detection stealth.
- A public arbitrary-target solve endpoint.
- Proxy rotation designed to evade target controls.
- Automatic authorization based on challenge type.
- Persisting provider credentials, raw results, session cookies, proxy credentials, authenticated browser material, or challenge corpora without explicit bounded provenance/retention.
- Treating every anti-bot block as a CAPTCHA.
- Guessing an issuer when evidence is insufficient.
- Ranking by price before hard authorization, context, disclosure, exact capability, and contract checks.

* Footnotes and Glossary

[fn:starintel] StarIntel: A local-first actor-based platform that collects, normalizes, links, searches, and analyzes authorized data while preserving provenance.

[fn:captcha] CAPTCHA: Completely Automated Public Turing test to tell Computers and Humans Apart; this index also covers adjacent browser, device, behavioral, proof-of-work, and Web Application Firewall challenges.

[fn:pro-actors] StarIntel Pro Actors: Separately deployable paid-service, browser, recognition, manual-review, and enrichment actors outside the generic server core.

[fn:star-server] StarIntel Server: The Common Lisp control, routing, persistence, authorization, search, and actor-hosting service.

- *Exact capability* — A solver contract matched on issuer, family, variant, version, required fields, result kind, binding, execution/disclosure class, and current contract state.
- *Opaque result reference* — A short-lived identifier permitting one bounded secret read without putting sensitive result material in an actor message or document.
- *Self-sourced solver* — A locally operated solver strategy whose recognition/inference and optional operator fallback do not require a paid external CAPTCHA service.
- *Transport-neutral envelope* — Application message contract that does not expose RabbitMQ exchange/queue identifiers or ZeroMQ socket topology as domain semantics.
