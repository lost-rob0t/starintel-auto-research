* Implemented Boundary

The approved child-identity policy now has an executable enforcement component at =scripts/child_identity_firewall.py=.

The component:

- accepts structured JavaScript Object Notation[fn:json] input only;
- removes child names and direct identifying fields from child records;
- replaces child identities with case-local pseudonyms;
- generalizes exact child ages into approved age bands;
- rejects child-name query fields and queries containing known child identifiers;
- rejects named minor targets;
- removes names from identity targets whose adult status is unresolved;
- rejects named adult targets below the approved legal-status threshold;
- rejects child identifiers tied to another case;
- scans final exports independently after sanitization;
- emits violation codes and paths without echoing prohibited values;
- reports redaction counts by category.

* Non-Execution Boundary

The implementation contains no:

- network client;
- browser or crawler;
- AutoDig integration;
- court, archive, news, or search adapter;
- real-case selector;
- national dataset importer;
- canonical StarIntel writer;
- public-record request sender.

It can process only input explicitly supplied by a caller. This preserves the user's actor-only and no-AutoDig directive.

* Command Interface

Sanitize a supplied structured artifact:

#+begin_src sh
python scripts/child_identity_firewall.py sanitize input.json result.json \
  --case-id synthetic-case-001 \
  --known-child-identifiers-file restricted-identifiers.json
#+end_src

Scan an already generated export:

#+begin_src sh
python scripts/child_identity_firewall.py scan export.json report.json \
  --case-id synthetic-case-001 \
  --known-child-identifiers-file restricted-identifiers.json
#+end_src

Exit status =0= means the artifact passed. Exit status =2= means the firewall blocked it. Exit status =3= means input or execution failed.

The violation output never contains the prohibited identifier itself.

* Synthetic Test Coverage

The file =tests/test_child_identity_firewall.py= covers:

1. child-record pseudonymization and direct-identifier removal;
2. exact-age generalization;
3. child identifiers in evidence text and source locators;
4. unsafe child-name queries;
5. explicit child-name query fields;
6. unknown-age named targets;
7. verified adult charged targets;
8. minor alleged offenders;
9. cross-case child identifiers;
10. current-case child identifiers;
11. export leakage detection;
12. export rejection for unverified named targets;
13. safe redacted exports;
14. absence of network and AutoDig dependencies.

All fixtures use fictional synthetic values. No real child or adult case is represented.

* Continuous Enforcement

The workflow =.github/workflows/child-identity-firewall.yml= compiles the firewall and runs the synthetic unit tests[fn:unit-test] on every pull request and on pushes to =main=.

A failing privacy test blocks the workflow. This is independent from the Org-roam pages and electronic-publication workflows.

* Known Boundary

Deterministic checks can remove structured identifiers and identifiers supplied through the restricted known-identifier input. They cannot prove that arbitrary free text contains no indirect identifying combination.

The approved independent privacy-review actor remains required before any future real output. This implementation does not authorize live research, real-case use, or publication.

* Footnotes and Glossary

[fn:json] JavaScript Object Notation, or JSON: A text format for representing structured objects, lists, strings, numbers, true-or-false values, and empty values.

[fn:unit-test] Unit test: An automated check that exercises one small software component with controlled input and verifies its exact output or failure behavior.
