* APPROVED Final Decision

Common Lisp is the sole approved implementation language for current-generation Star-Lang.

For the current generation, Common Lisp owns:

- the closed =.star= parser;
- source locations and origin chains;
- semantic validation;
- normalized IR construction;
- canonical manifest generation;
- lifecycle and delivery semantics;
- deterministic dispatch;
- durable recovery;
- document construction;
- direct execution;
- optional cl-gserver integration;
- the public Star-Lang API.

This is a final language and architecture decision for the current generation. There is no active current-generation language-selection gate and no retained competing current-generation implementation.

This decision does not claim that every implementation acceptance criterion is complete. Remaining implementation hardening is tracked in [[https://github.com/lost-rob0t/starintel-auto-research/issues/47][issue #47]].

* FUTURE DIRECTION: Self-Hosting Is Not Denied

StarLang self-hosting is not prohibited as a possible future or next-generation direction.

A future generation may investigate a compiler implemented partially or fully in StarLang, including staged bootstrap paths from the current Common Lisp compiler. That possibility does not alter the current-generation architecture and does not make self-hosting an active goal, roadmap item, implementation task, or migration requirement.

The authorization boundary is strict:

1. planning, research, roadmap creation, design work, prototyping, or implementation work whose purpose is StarLang self-hosting may begin only after explicit authorization from nsaspy for that effort;
2. autonomous agents, maintainers, and research loops must not infer authorization merely because this direction is permitted;
3. authorization to plan self-hosting does not automatically authorize implementation;
4. each approved future effort must state its scope, generation target, bootstrap/trust model, conformance strategy, and relationship to the canonical Common Lisp compiler;
5. until a later explicit architecture decision replaces this one, the current Common Lisp implementation remains canonical.

This section changes self-hosting from a banned direction to a reserved future direction under nsaspy-controlled planning authority.

* DENIED Current-Generation Alternatives

** DENIED Racket

Racket is not a current-generation Star-Lang implementation target, conformance runtime, parser frontend, expansion oracle, tooling oracle, or fallback host. The Racket implementation path is not retained for the current generation.

** DENIED Scheme and Guile

Scheme and Guile are not current-generation Star-Lang implementation targets, portability witnesses, fallback runtimes, or conformance implementations. Their implementation paths are not retained for the current generation.

** DENIED Other Host Languages

C, C++, Rust, Python, JavaScript, TypeScript, Nim, Java, Go, and every other external language are denied as current-generation implementations of the Star-Lang parser, compiler, semantic engine, dispatcher, or runtime.

External programs may exchange versioned JSON messages or call an API. Generated boundary bindings do not make those programs Star-Lang implementations.

The separate future possibility of StarLang self-hosting is governed by the explicit authorization rule above and is not an alternate current-generation host.

* Current-Generation Architecture

#+begin_src text
.star source
    |
    v
Common Lisp closed parser
    |
    v
Common Lisp semantic compiler
    |
    v
Common Lisp normalized IR and runtime
    |
    +--> canonical JSON at system boundaries
    +--> cl-gserver adapter
    +--> transport adapters
#+end_src

The current-generation implementation remains Common Lisp from source parsing through execution. JSON is an interchange format, not a second implementation language.

* Hard Boundaries

1. Current-generation Star-Lang source is not arbitrary Common Lisp source.
2. Untrusted source never enters the Common Lisp reader.
3. No unrestricted =EVAL= or reader evaluation enters compilation or execution.
4. Source identifiers remain strings until validated.
5. Core IR remains independent of cl-gserver object types.
6. Field access remains explicit; dot syntax is denied.
7. Actor readiness affects routing, not program validity.
8. Research nodes never become StarIntel object types, predicates, fields, or schema extensions.
9. Auto-dig and Quasar consume Star-Lang contracts and do not define its semantics.
10. No alternate external-language current-generation Star-Lang implementation is retained in the repository.
11. Future self-hosting work cannot be autonomously promoted from possibility to plan; explicit nsaspy authorization is required.

* Approval Rule

The Common Lisp selection is approved and final for current-generation Star-Lang. Do not reopen the current-generation host-language comparison, add another current-generation host implementation, or restore alternate-language conformance runtimes without a new explicit decision from nsaspy that directly reverses this approval.

Future StarLang self-hosting is permitted as a potential next-generation direction, but no self-hosting planning, research program, roadmap, prototype, or implementation may be initiated without explicit nsaspy authorization for that effort.

* Result

Common Lisp language ownership and architecture are APPROVED and canonical for current-generation Star-Lang.

Implementation completion remains =IMPLEMENTING= until the active acceptance ledger is complete.

External alternate current-generation implementation languages remain DENIED. StarLang self-hosting is reserved as a possible future direction under explicit nsaspy-controlled planning authority.

* Footnotes and Glossary

- *Current-generation StarLang* — The presently approved StarLang architecture whose parser, compiler, semantic engine, IR producer, dispatcher, and runtime are implemented in Common Lisp.
- *Self-hosting* — A future architecture in which some or all of the StarLang compiler is implemented in StarLang itself and bootstrapped from a trusted prior compiler.
- *Planning authority* — Permission to begin research, roadmap, design, or prototype work for self-hosting; under this decision it exists only when nsaspy explicitly grants it for a specific effort.
- *Canonical compiler* — The implementation that defines current compiler authority and conformance expectations. The Common Lisp compiler remains canonical until an explicit later architecture decision changes that authority.
