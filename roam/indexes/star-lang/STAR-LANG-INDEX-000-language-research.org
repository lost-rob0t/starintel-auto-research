* Final Selection

Common Lisp is the sole approved Star-Lang implementation language.

The parser, compiler, semantic engine, normalized IR producer, dispatcher, recovery system, document runtime, and execution runtime are Common Lisp.

Every alternate implementation language is DENIED.

Versioned JSON remains available at system boundaries. JSON does not constitute another Star-Lang implementation.

* Ordered Decisions

** APPROVED Loop 000: Language Design Foundations

Define the bounded source, checked IR, effects, capabilities, durable execution, recovery, actor, reasoning, and testing model.

** APPROVED Loop 001: Common Lisp Baseline

Implement the shared fixture with ordinary macros, explicit registries, inspectable expansion, and no unrestricted =EVAL=.

** DENIED Loop 002: Racket Embedded Baseline

The Racket implementation path is denied. Its prototype and tests are removed.

** DENIED Loop 003: Racket =#lang starintel=

The dedicated Racket language path is denied. Its reader, package, examples, and tests are removed.

** DENIED Loop 004: Scheme or Guile Baseline

The Scheme and Guile implementation path is denied. Its prototype and tests are removed.

** APPROVED Loop 005: Final Language Decision

Common Lisp is approved as the sole Star-Lang implementation language. No competing implementation is retained.

** APPROVED Loop 006: Specification Libraries and Domain Servers

Define digest-locked imports, additive extension, relations, typed actors, domain servers, indexes, and resolver boundaries.

** APPROVED Loop 007: Normalized IR and cl-gserver Binding

Keep =send= in core IR and lower it to =tell= only in the optional Common Lisp adapter.

** APPROVED Loop 008: Core Surface and Wire Protocol

Compile closed =spec-library= syntax into qualified schema IR and versioned boundary contracts.

** APPROVED Loop 009: Canonical JSON

Emit byte-stable JSON for process and transport boundaries without creating another language implementation.

** APPROVED Loop 010: Message Lifecycle and Delivery Semantics

Define correlation, causation, attempts, deadlines, idempotency, acknowledgements, retries, errors, and cancellation without claiming exactly-once execution.

** APPROVED Loop 011: Deterministic Dispatcher

Execute lifecycle rules through the Common Lisp state machine and standalone runtime.

** APPROVED Loop 012: Transport Port and Settlement

Separate lifecycle outcomes from broker settlement and resume interrupted publication.

** APPROVED Loop 013: Optional cl-gserver Runtime Adapter

Preserve direct execution and add replaceable Common Lisp actor-system binding and runtime-directory capabilities.

** APPROVED Loops 014-017: Remoting and Recovery

Define BBP domain remoting, endpoint materialization, worker and dispatcher idempotency, and durable runtime journals.

* Preserved Invariants

1. all Star-Lang implementation code is Common Lisp;
2. source parsing is closed and does not execute host forms;
3. identifiers remain strings until validated;
4. document schemas, persistence, actor, tool, agent, and dataflow contracts remain explicit;
5. relations retain source, predicate, and destination positions;
6. field access remains explicit and dot syntax is denied;
7. normalized IR contains no cl-gserver object types;
8. lifecycle and transport settlement remain separate;
9. delivery is at least once and does not claim exactly once;
10. terminal duplicates replay without handler reinvocation;
11. runtime liveness affects routing rather than program validity;
12. research nodes never become StarIntel object types, predicates, or fields;
13. Auto-dig and Quasar consume contracts rather than define Star-Lang semantics;
14. alternate implementation languages remain DENIED.

* Promotion Result

The language decision is final. =STAR-LANG-001= is APPROVED for Common Lisp and owns the active implementation slot.

Do not reopen language comparison or add another implementation language without a new explicit reversal from nsaspy.
