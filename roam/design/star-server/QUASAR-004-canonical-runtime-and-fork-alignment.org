* Decision

=lost-rob0t/quasar= is the canonical Quasar[fn:quasar] repository and runtime. It owns migrated durable workspace operations, the versioned command channel, privileged local execution, persistent actor supervision, and runtime integration authority.

=lost-rob0t/quasar-ui= is the web-based Quasar implementation and standalone web edition. It owns browser presentation, mobile behavior, Cytoscape[fn:cytoscape] integration, local offline behavior, and browser-limited workers. It may own local state while disconnected or running as a standalone web application, but it does not overrule the canonical =quasar= command channel for migrated connected operations.

=lost-rob0t/auto-dig-quasar= remains the Auto-Dig[fn:auto-dig] variant and fork[fn:fork] of =quasar-ui= until a separate approved migration moves Auto-Dig integration behind a narrow adapter in canonical =quasar=. Until then, Auto-Dig-specific code must remain isolated, version-pinned, and upstream-synchronized.

=lost-rob0t/starintel-auto-research= owns this decision record, the evidence trail, and the public review pages.

* Problem

The repository set now has working software in three places and architecture text from multiple phases. Without this decision, an agent can reasonably infer three incompatible positions:

1. the original Common Lisp[fn:common-lisp] and CLOG[fn:clog] prototype text owns canonical graph state;
2. the browser roadmap owns all canonical graph state and rejects a Common Lisp backend path;
3. the newer =quasar= repository owns migrated durable operations through a Common Lisp control plane while preserving the web UI.

The third position is now selected.

* Authority Model

| Subject | Authority | Notes |
|---------+-----------+-------|
| Migrated durable document and graph mutations | =quasar= command channel | Connected operation treats Common Lisp runtime results as authoritative. |
| Standalone browser editing | =quasar-ui= web edition | Must keep local-first operation when =quasar= runtime is absent. |
| Renderer interaction | Browser =GraphViewAdapter=[fn:graph-view-adapter] | High-frequency movement can stay local until a committed command boundary. |
| Persistent actor supervision | =quasar= runtime | Browser workers are bounded local actors, not the full supervisor tree. |
| Deep research semantics | ADARD[fn:adard] in StarIntel auto-research | Quasar may invoke and display runs but does not redefine evaluation or promotion. |
| Auto-Dig host bridge | =auto-dig-quasar= until migration | Bridge must become typed and must not redefine canonical graph semantics. |
| Published design authority | =starintel-auto-research= | Approval/changelog tables live here. |

* Required Invariants

1. One mutable subject has one durable writer at a time.
2. Cytoscape is a renderer, never a database.
3. Renderer adapters may propose commands but cannot bypass validation.
4. Actor and provider outputs return proposed graph-operation batches, not hidden mutations.
5. Browser standalone mode must keep working without =quasar=.
6. Connected migrated operations must route through canonical =quasar= commands.
7. Auto-Dig-specific code remains isolated from generic Quasar packages.
8. Generic graph, command, action, storage, and renderer fixes found in Auto-Dig should flow upstream.
9. Deep-research candidates, evaluation, review, and promotion remain ADARD semantics.
10. Storage documentation must distinguish logical command atomicity from crash-safe physical persistence.

* Web-Edition Scope

The =quasar-ui= JavaScript-only roadmap and package-boundary ADR are preserved for the standalone web edition. They must be narrowed where they imply that no canonical Common Lisp runtime can exist.

Acceptable web-edition claims:

- the web application opens, edits, imports, exports, and runs limited local actions without a server;
- =core= contracts stay independent of React, Cytoscape, storage engines, network transports, and provider integrations;
- optional runtime integration fails closed;
- browser-held credentials and privileged network access should be reduced, not expanded.

Rejected web-edition claims:

- the browser permanently owns all canonical operations after a subject is migrated into =quasar=;
- Common Lisp runtime integration is prohibited rather than optional;
- downstream forks may redefine command semantics instead of referencing shared schemas.

* Canonical Command Layers

This design reserves four protocol layers. Exact schemas belong to =QUASAR-003= after evidence review.

#+begin_src text
star.graph.v1
  graph document
  graph operation
  graph command batch
  revision expectation
  command result / rejection
  inverse metadata
  conformance fixtures

quasar.control.v1
  runtime capabilities
  workspace snapshot
  migrated document and graph mutation commands
  actor runtime commands
  privileged tool commands
  reconnect and replay events

auto-dig-quasar.v2
  host dataset/run context
  tipline and correction commands
  Auto-Dig actor findings
  references to star.graph.v1 and quasar.control.v1 objects

star.research.v1
  ADARD research request
  evidence, source, claim, and reviewer records
  cancellation and budget events
  promotion result
#+end_src

=auto-dig-quasar.v2= must not copy =star.graph.v1= semantics into a host-only dialect. It should reference or embed shared command/result objects.

* Fork Rules

=auto-dig-quasar= remains valid when all of these are true:

| Rule | Requirement |
|------|-------------|
| Isolation | Auto-Dig-specific code stays under =src/auto-dig/= or clearly marked small integration patches. |
| Pinning | Auto-Dig host records the exact fork commit and upstream commit. |
| Upstream sync | Sync uses merge commits and validation, not force-push or silent history rewrite. |
| Generic fixes | Generic Quasar fixes get an upstream issue or pull request unless documented impossible. |
| Typed bridge | Host bridge rejects unknown method payloads after =auto-dig-quasar.v2=. |
| No semantic fork | Auto-Dig does not define a second graph command model. |

* Renderer Scale Boundary

Large graph handling must not change canonical authority.

#+begin_src text
canonical quasar commands
        |
        v
stable graph projection snapshot
        |
        +--> Cytoscape editable adapter
        +--> WebGL overview adapter
        +--> WebGPU / WASM tiled adapter
        +--> table / map / timeline projections
#+end_src

The renderer adapter may select a safe view tier before loading a graph. If a graph is too large for the editable Cytoscape tier, Quasar should open a coarse projection first, then let the user filter, tile, or focus before enabling expensive edit mode.

* QUASAR-003 Unblock Rule

=QUASAR-003= should no longer wait only for the old prototype path. It should be unblocked or superseded when the current repositories provide evidence for:

- manual node and edge mutation;
- committed movement;
- inspector edits;
- batch commands;
- undo and redo;
- save and reopen;
- session reconstruction;
- one actor or action producing a proposed command batch;
- Common Lisp and JavaScript fixture compatibility.

Evidence may come from =quasar=, =quasar-ui=, or =auto-dig-quasar= as long as the exact commit and test command are recorded.

* Validation Gates

| Gate | Required proof |
|------|----------------|
| Topology proof | =quasar= repository state, submodule/import status, and frontend pin are documented. |
| Command fixture proof | Same fixture and command batch normalize identically in JS and Common Lisp. |
| Storage proof | Crash between multi-document writes does not expose a false committed batch. |
| Runtime proof | Browser actor and Common Lisp actor return equivalent proposed command batches for a deterministic fake actor. |
| Auto-Dig proof | Host bridge loads dataset, edits document/relation, reloads, and reports exact fork/upstream versions. |
| Scale proof | Graph-size guard chooses safe renderer tier before loading a dangerous graph. |
| Publication proof | =scripts/sync.py --check=, =scripts/publish-pages=, and =scripts/check-pages-links.py _site= pass. |

* Migration Order

1. Approve or edit this decision.
2. Verify current =quasar= topology and update stale repository docs.
3. Use current implementation evidence to unblock or supersede =QUASAR-003=.
4. Generate or hand-author initial =star.graph.v1= conformance fixtures.
5. Narrow =quasar-ui= roadmap and ADR wording to web-edition scope.
6. Replace =auto-dig-quasar.v1= =unknown= payloads with typed =auto-dig-quasar.v2= method contracts.
7. Add graph-scale benchmarks and renderer-tier gates.
8. Only then move more durable operations behind the canonical =quasar= command channel.

* Non-Goals

- Do not delete the web edition.
- Do not rewrite the Auto-Dig fork before adapter migration is approved.
- Do not migrate to an unrelated framework because of the name =Quasar=.
- Do not make Cytoscape carry massive corpus overviews alone.
- Do not let research-node UI become a second ADARD implementation.

* Footnotes and Glossary

[fn:quasar] Quasar: The StarIntel graph workspace. In this design, =lost-rob0t/quasar= is the canonical runtime and repository for migrated operations.

[fn:cytoscape] Cytoscape: The browser graph rendering library used by Quasar for graph editing and interaction.

[fn:auto-dig] Auto-Dig: The StarIntel static research and dataset-review system that embeds a specialized Quasar fork.

[fn:fork] Fork: A repository derived from another repository so it can carry local changes while periodically merging upstream updates.

[fn:common-lisp] Common Lisp: The Lisp language used by the canonical Quasar runtime and StarIntel actor infrastructure.

[fn:clog] CLOG: A Common Lisp web application library that can host browser sessions and communicate over WebSockets.

[fn:graph-view-adapter] GraphViewAdapter: A renderer interface that lets Quasar swap graph rendering implementations without changing canonical command semantics.

[fn:adard] ADARD: Adaptive Research DAG, the StarIntel automatic-research system that owns bounded research candidates, evidence, review, and promotion semantics.
