* Design Decision

Create one provider-neutral observability semantic boundary before any concrete logging/export backend becomes authoritative.

The application/runtime model owns typed =ObservationContext=, =OperationalEvent=, =MetricObservation=, =SpanObservation=, and =AuditRecord= values plus narrow sink/read ports. Structured local logs, syslog, OTLP/OpenObserve, and operator diagnostics are projections/adapters over those values.

#+begin_example
HTTP / Rabbit / StarLang ingress
          |
          v
validated transport trace context
          |
          v
ObservationContext
 correlation + trace/span + runtime/component + safe refs
          |
          +------------------------------+
          |                              |
          v                              v
server application/runtime       StarLang actor/runtime semantics
          |                              |
          +---------------+--------------+
                          |
                          v
                typed observations
         events / metrics / spans / audit
          |          |          |
          v          v          v
      local log   snapshots   audit sink
          |                     |
          +----------+----------+
                     |
                     v
             optional adapters
          syslog / OTLP / OpenObserve
#+end_example

Observability is never a scheduler, actor registry, lease authority, persistence authority, authorization engine, or alternate control plane.

* Typed Semantic Values

** ObservationContext

The context is immutable and passed explicitly. It composes with the existing =service-call-context= instead of replacing its principal/scopes/deadline semantics.

Minimum fields are:

- existing =correlation-id=;
- optional validated W3C =trace-id=, current =span-id=, parent span, and trace flags;
- bounded policy-filtered =tracestate= when retained;
- runtime instance ID;
- component ID and generation when applicable;
- optional safe principal reference;
- optional request/message/mutation reference;
- optional target/job/schedule/lease reference;
- attempt number and absolute deadline when applicable.

Credentials, Authorization/cookie headers, raw request/document bodies, secret values, database clients, transport objects, and actor references are forbidden.

** OperationalEvent

A versioned closed event contains timestamp, service, component, stable event name/class, severity, outcome/reason class, optional bounded duration, =ObservationContext=, and an event-kind-specific allowlisted attribute record. The public constructor does not accept an arbitrary free-form metadata map.

** MetricObservation

A metric observation contains stable metric name, instrument kind, numeric value, unit, timestamp, and bounded low-cardinality labels.

Allowed dimensions describe classes such as component type, operation type, outcome, rejection reason, dependency type, lane/queue class, or protocol. Principal, target, document, request/message, trace/span, lease, URL, and arbitrary error-string identities are forbidden metric dimensions.

** SpanObservation

A span records trace/span/parent identity, stable operation name, start/end or duration, status, component identity, and bounded safe attributes. OTLP span types are exporter representations, not the core value type.

** AuditRecord

An audit record is a security/governance fact with its own durability semantics. It contains timestamp, safe principal reference/class, action, resource class/reference, outcome, policy/decision reference when available, correlation/trace context, runtime/component identity, and fence/generation when relevant. It never embeds the protected resource payload or credential material.

* Ports and Failure Semantics

** Best-effort observation sink

Conceptual interface:

#+begin_example
emit-event(sink, event)   -> emitted | dropped | sink-unavailable
emit-span(sink, span)     -> emitted | dropped | sink-unavailable
record-metric(sink, obs)  -> recorded | dropped | sink-unavailable
#+end_example

These operations are bounded and failure-isolated from authoritative application execution. Saturation may drop according to configured policy, but the implementation records bounded dropped/suppressed counters.

** Durable audit sink

#+begin_example
append-audit(sink, record)
  -> committed | rejected | outcome-unknown | unavailable
#+end_example

Audit acknowledgment, idempotency, append-only/tamper-evident behavior, retention, and unknown-outcome semantics are explicit. Whether a specific authoritative operation must fail closed on unavailable audit requires a separate operator-approved policy for that operation class. Ordinary log/export failure never silently acquires that authority.

** Metrics/snapshot readers

Existing runtime/resource owners expose typed counters/read models through narrow ports. Observability aggregates them but does not own or duplicate their state.

* Trace Propagation

** HTTP

The HTTP adapter parses and validates W3C =traceparent= and optional =tracestate=, applies configured trust-boundary policy, and constructs normalized trace context. Invalid tracing headers cannot crash the request. Raw header strings do not enter core/application logic.

The existing =X-Correlation-ID= behavior remains independently useful and is preserved.

** Rabbit and message envelopes

Versioned envelope metadata carries normalized correlation/trace fields. Producers serialize current typed context; consumers validate it and create a child processing context/span. Individual payload schemas do not each invent telemetry fields.

** StarLang actor/domain runtime

StarLang owns actor lifecycle, mailbox, dispatcher, supervision/restart, and semantic external-call instrumentation. If propagation requires additional StarLang semantics, add the smallest closed/versioned StarLang extension and compile it into the runtime plan. Common Lisp consumes that runtime observation seam; it does not scrape Sento internals and infer a shadow actor model.

** Trust boundaries

Inbound =tracestate= is untrusted, bounded, and policy-filtered. StarIntel never places PII/credentials in it. A configured external/acquisition boundary may restart trace identity while preserving StarIntel correlation separately.

* Metrics Ownership

Instrumentation is emitted at the authoritative decision point. Metric authorities remain:

- #34 thread ownership/allocation;
- #35 Sento lane/dispatcher allocation;
- #36 mailbox/admission pressure, rejection, and drops;
- #37 lifecycle/dependency state;
- #42 component generation/readiness;
- Rabbit owners for connection/channel/settlement/retry/DLQ state;
- CouchDB/outbox owners for pool/conflict/retry/backlog state;
- target scheduler/recovery owner for attempts/lateness/recovery;
- lease owner for conflict/renew/revoke/stale-fence outcomes;
- HTTP/application boundary for request/status/authn/authz/rate-limit outcomes.

Observability cannot infer a queue drop only after work disappears; rejection/drop telemetry is coupled to the real admission result.

* Structured Logging and Syslog

Server #121 becomes the first structured-log/event projection over =OperationalEvent= plus explicitly safe audit summaries. Human-readable compatibility output may remain, but machines consume the versioned structured contract.

Server #122 remains transport-only remote syslog. It receives already-sanitized typed/projection values and cannot redefine the event schema.

* OTLP and OpenObserve Adapter

Server #128 is an optional adapter over canonical events, metrics, and spans. OpenObserve is supported through its OTLP ingestion compatibility; no OpenObserve-specific event model enters the core.

Configuration belongs to the #38 closed data-only deployment configuration and uses secret references resolved inside the exporter boundary. Executable init Lisp remains trusted extension code, not normal telemetry configuration.

When observability is absent/disabled:

- no exporter object exists;
- no exporter worker/thread starts;
- no outbound connection opens;
- no export secret is resolved;
- no OpenObserve/collector dependency becomes a startup requirement;
- authoritative application behavior is unchanged.

When enabled, queues/batches/timeouts/retries are bounded. OTLP retry handling distinguishes retryable failures from permanently bad telemetry and accounts for dropped records. Exporter outage cannot indefinitely block StarIntel application/actor work.

* Operator Diagnostic Snapshot

Diagnostics are an operator-authorized application service composed from typed runtime/component read models. A bounded snapshot may expose lifecycle/readiness, component IDs/types/generations, dependency health, thread/lane allocations, mailbox/dispatcher pressure, Rabbit/CouchDB/outbox health, target/lease/recovery summary counters, and observability sink queue/drop/export state.

The service excludes credentials, secrets, raw request/document bodies, policy-restricted target values, arbitrary process memory, and raw database/actor handles. HTTP is only a projection over this service.

* Privacy and Boundedness

1. Event/audit field allowlists are semantic, not regex cleanup after serialization.
2. Unknown/forbidden fields fail before sink invocation.
3. Strings/collections have hard size/count ceilings.
4. Sensitive values are absent from sink inputs, not merely hidden by one renderer.
5. Metric dimensions are low-cardinality by schema.
6. Export queues, batches, retries, and timeouts are bounded.
7. Trace state is bounded/filterable at trust boundaries.
8. Diagnostic snapshots are bounded and paginated/summarized where needed.
9. Telemetry cannot trigger acquisition, DNS, actor creation, or hidden product effects.

* Adversarial Review

Rejected alternatives:

1. *OTLP as the internal API* — couples core correctness to one telemetry protocol/SDK and makes disabled operation harder to prove side-effect-free.
2. *A standalone #121 logging schema* — duplicates #46 semantics and leaves metrics/traces/audit with incompatible correlation fields.
3. *Correlation ID equals trace ID* — destroys proper parent/span semantics and conflates two useful identifiers.
4. *High-cardinality metric identities* — turns metrics into an identity database and operational cardinality hazard.
5. *Audit is just log severity =AUDIT=* — provides no durable append/commit proof.
6. *Raw request/document bodies for debugging* — creates a telemetry exfiltration path.
7. *Common-Lisp-only actor instrumentation* — violates StarLang ownership and creates a shadow lifecycle model.
8. *HTTP scrapes process globals for diagnostics* — bypasses explicit runtime/component ownership and is race-prone.
9. *Eager OTLP initialization* — violates default-off zero-side-effect semantics.
10. *Exporter backpressure becomes product backpressure* — makes a telemetry outage a StarIntel availability outage.
11. *Executable init as ordinary config* — conflicts with #38's data-only config/secret-ref boundary.
12. *#121 AUTO-RAGE wording means approval* — issue text cannot cross the operator-only implementation gate.

** Slice 1 — pure semantic values and allowlist validation

No HTTP, actor, Rabbit, CouchDB, network, exporter, file, or thread effects.

Mandatory RED on untouched =starintel-server/master=:

#+begin_example
ctx = ObservationContext(
  correlationId="c-1",
  traceId="4bf92f3577b34da6a3ce929d0e0e4736",
  spanId="00f067aa0ba902b7")

makeOperationalEvent(
  name="security.authentication.denied",
  context=ctx,
  attributes={action="authenticate",
              authorization="Bearer super-secret"})

=> forbidden-observation-field("authorization")
=> fake sink call count = 0
=> serialized/rendered outputs contain zero bytes of "super-secret"
#+end_example

A post-hoc redaction test over a free-form log string is not valid GREEN.

Sibling REDs cover unknown attributes, oversize values, invalid trace/span IDs, forbidden high-cardinality metric labels, deterministic schema/version, and copy/immutability of context values.

** Slice 2 — HTTP/service W3C trace propagation

Preserve existing correlation behavior and add validated adapter-level W3C propagation. A fake downstream application operation receives normalized explicit context; rebinding unrelated globals does not change it.

** Slice 3 — one authoritative bounded metric vertical

Instrument a realized queue/admission owner after #36. Saturation/rejection increments at the same authoritative decision, uses bounded labels, and creates no second queue/state authority.

** Slice 4 — structured log projection (#121)

Render canonical events to stable structured local output and retain useful human-readable compatibility output. Secret tests are inherited from the canonical constructors.

** Slice 5 — StarLang runtime/actor instrumentation (#49)

Implement actor lifecycle/mailbox/supervision/dispatch observations in StarLang without message bodies; prove schema/projection compatibility with StarIntel fixtures.

** Slice 6 — durable audit seam

Implement =AuditSink= protocol and fake conformance tests before selecting a concrete sink. Prove ordinary sink success/failure cannot masquerade as durable audit commit.

** Slice 7 — OTLP/OpenObserve adapter (#128)

Depends on canonical semantics and #38 configuration realization. Mandatory RED: absent/disabled observability yields exporter-constructor, network, worker/thread, and secret-resolution call counts all equal to zero.

** Slice 8 — operator diagnostic snapshot

Compose typed read models behind operator authorization. Mandatory RED: unauthorized invocation reaches zero snapshot-source callbacks and response fixtures contain no secret/body fields.

* Acceptance Criteria

- one end-to-end HTTP/message/application flow can preserve correlation plus W3C-compatible trace lineage without ambient-global authority;
- StarLang owns actor/runtime instrumentation semantics;
- events, metrics, spans, and audits are typed/versioned rather than arbitrary maps;
- forbidden secrets/sensitive bodies cannot reach sink inputs;
- metric labels are bounded-cardinality by contract;
- queue/resource metrics are emitted by authoritative owners without duplicate state;
- best-effort exporter failure cannot change normal application results;
- durable audit has explicit commit/outcome semantics and is not inferred from log success;
- diagnostics are operator-authorized application read models;
- #121/#122/#128 consume the canonical semantic model;
- disabled OTLP/OpenObserve has zero exporter/network/thread/secret-resolution initialization;
- observability config follows #38 data-only/secret-reference semantics;
- no product telemetry or StarIntel-owned reporting endpoint is introduced.

* Dependencies and Blockers

- Pure semantic values can begin independently only after explicit operator implementation approval.
- Production explicit context/snapshot composition should consume #39/#40/#42 realization rather than local substitutes.
- Queue/lifecycle metrics consume #34-#37/#42 authorities.
- StarLang actor/runtime instrumentation is owned by StarLang #49.
- OTLP configuration consumes #38's closed deployment configuration contract.
- Concrete audit durability requires selection of a sink plus explicit fail-closed operation policy.

Dependencies constrain realization order; none grant approval.

* Unresolved Operator Decisions

- Which ingress/acquisition trust boundaries restart/filter inbound =tracestate=?

These do not block design review. They block the corresponding policy/production slices.

* Footnotes and Glossary

[fn:projection] A transport/format representation derived from canonical typed semantics without becoming a second source of truth.

[fn:best-effort] A bounded observation path allowed to drop/fail under documented policy without changing the authoritative application result.

[fn:fail-closed-audit] An explicitly approved operation policy in which lack of a durable audit commit prevents the corresponding authoritative effect.
