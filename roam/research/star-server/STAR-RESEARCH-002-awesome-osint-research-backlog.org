* Purpose

This note turns the Awesome OSINT[fn:osint] directory into a bounded research backlog for StarIntel[fn:starintel]. It does not assume that every listed website deserves an actor[fn:actor]. Each research point must decide whether the useful result is an automated actor, a manually opened source, a versioned dataset[fn:dataset], a reusable workflow[fn:workflow], a visualizer[fn:visualizer], or a rejected integration.

The backlog is deliberately organized around source families and platform capabilities rather than copying hundreds of links into the repository. Individual providers are examples to investigate inside each point, not pre-approved dependencies.

* Source Snapshot

- Upstream directory: https://github.com/jivoi/awesome-osint/blob/master/README.md
- Snapshot commit: =53cc84638b2b621de18ec64ca6c85699db2e3b5d=
- Snapshot reviewed: 2026-07-30
- Upstream scope includes general and national search engines, data-breach search, specialty search, dark-web indexes, document and code search, social networks, identity research, domain and network research, web archives, media analysis, geographic research, news, fact checking, data sources, monitoring, visualization, maritime sources, threat intelligence, gaming platforms, music services, and training resources.

The upstream list is an inventory, not evidence that a provider is alive, accurate, automatable, lawful for a specific use, or compatible with StarIntel. Those questions remain part of this backlog.

* Classification Gate

Every provider reviewed under this backlog must receive exactly one primary classification:

- =actor=: a machine-callable capability with typed input and output documents
- =manual-source=: useful to an analyst but unsuitable for reliable automation
- =dataset=: a source that should be periodically imported and versioned
- =workflow=: a repeatable composition of existing actors or manual checkpoints
- =visualizer=: a read-only presentation for a result type
- =library=: reusable local software embedded behind an actor boundary
- =reject=: dead, duplicative, unsafe, unverifiable, contractually unusable, or strategically irrelevant

Every accepted actor candidate must record its authentication[fn:authentication], cost, quota[fn:quota], rate limit[fn:rate-limit], target types, result types, provenance[fn:provenance], failure behavior, cache policy, and execution location.

* Priority Model

- =P0=: required foundations before a large connector catalog can remain coherent
- =P1=: high-value source-family research that can produce collection actors or datasets
- =P2=: analysis, orchestration, and operator-interface research enabled by the sources
- =P3=: validation and maintenance work that prevents the catalog from becoming stale or fictional

* Recommended First Research Wave

The first execution wave should not start by wrapping the largest number of providers. It should establish the catalog and then prove several different source shapes:

1. =F-01= through =F-08= as one foundation study.
2. =C-01= general and federated web search.
3. =C-09= document and file search.
4. =C-18= username identity correlation.
5. =C-19= staged person, email-address, and phone-number enrichment.
6. =C-21= domain and network research.
7. =C-23= image, video, and geographic research.
8. =C-24= publication, news, archive, and monitoring sources.
9. =A-04= capability-aware query planning.
10. =V-01= and =V-02= liveness and provider-contract auditing.

This wave covers web pages, structured services, downloadable files, identity pivots, technical infrastructure, media, historical sources, and maintenance. That breadth is more useful than implementing ten nearly identical search wrappers.

* Completion Rule for Each Backlog Point

A point may move from =DRAFT= only when its focused research note contains:

- the exact research question and scope
- candidate providers and source citations
- actor, manual-source, dataset, workflow, visualizer, library, or rejection decisions
- typed inputs and outputs
- authentication, cost, quota, and rate-limit findings
- evidence and provenance behavior
- failure, retry, caching, and partial-result behavior
- security and permission boundaries
- at least one reproducible test or documented reason testing was impossible
- a direct recommendation for implementation order or rejection

* Footnotes and Glossary

[fn:osint] Open-source intelligence (OSINT): Information collected from publicly available sources and analyzed for an investigative or decision-making purpose.

[fn:starintel] StarIntel: The local-first intelligence platform in this repository that stores typed documents, preserves sources, connects entities, runs actor-based collection and analysis, and exposes the result through search and graph interfaces.

[fn:actor] Actor: A small independent software unit that owns its state and processes messages one at a time. In this note, an actor wraps one bounded collection, enrichment, analysis, export, or maintenance capability.

[fn:dataset] Dataset: A named, versioned collection of records and attachments with declared sources, scope, and processing rules.

[fn:workflow] Workflow: A repeatable ordered or parallel composition of capabilities, with explicit inputs, outputs, checkpoints, and failure behavior.

[fn:visualizer] Visualizer: A read-only presentation component specialized for a result type, such as a timeline, map, graph, table, or media viewer.

[fn:authentication] Authentication: The process by which a provider verifies the identity or credential of a caller, such as an application key, login session, or signed request.

[fn:quota] Quota: A provider-imposed maximum amount of use during a stated period, such as requests per minute or searches per month.

[fn:rate-limit] Rate limit: A rule restricting how quickly requests may be sent to a provider.

[fn:provenance] Provenance: The recorded origin and processing history of information, including where it came from, when it was observed, and which operation produced or changed it.

[fn:api] Application programming interface (API): A machine-readable contract through which software sends requests to and receives structured responses from another system.

[fn:circuit-breaker] Circuit breaker: A failure-control pattern that temporarily stops calls to an unhealthy provider after repeated errors and later allows a bounded test request.

[fn:socmint] Social-media intelligence (SOCMINT): Collection and analysis of information published through social-network, messaging, forum, and community platforms.

[fn:ip] Internet Protocol (IP): The addressing system used to identify network interfaces and route traffic across computer networks. An IP address is a numeric network identifier such as =192.0.2.10= or =2001:db8::10=.

[fn:dns] Domain Name System (DNS): The distributed naming system that maps domain names to network records such as addresses, mail servers, and delegated name servers.

[fn:bgp] Border Gateway Protocol (BGP): The routing protocol through which large networks announce which internet address ranges they can reach.

[fn:precision-recall] Precision and recall: Two evaluation measurements. Precision asks what fraction of returned matches are correct; recall asks what fraction of all relevant matches were found.
