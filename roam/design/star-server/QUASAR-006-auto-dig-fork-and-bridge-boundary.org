* Decision

=lost-rob0t/auto-dig-quasar= remains the Auto-Dig[fn:auto-dig] specialization and fork[fn:fork] of =lost-rob0t/quasar-ui= until a separately approved migration replaces the full fork with a narrower adapter[fn:adapter] against canonical =lost-rob0t/quasar=.

The fork may carry Auto-Dig-specific presentation and host integration. It may not define a second graph command model, persistence authority, actor semantics, or research-promotion system.

* Fork Lifecycle

The fork is valid only while all of these conditions remain true.

| Rule | Requirement |
|------|-------------|
| Isolation | Auto-Dig-specific code remains under =src/auto-dig/= or in clearly marked, minimal integration patches. |
| Pinning | The Auto-Dig host records the exact fork commit and corresponding upstream =quasar-ui= commit. |
| Upstream synchronization | Synchronization uses reviewable merge commits and validation; no force-push or silent history rewrite. |
| Shared semantics | Graph/document commands reference shared Quasar contracts instead of being copied into a fork-only dialect. |
| Host specialization | Dataset context, correction/tipline actions, and Auto-Dig presentation remain host-specific. |
| Migration evidence | A narrower adapter is adopted only after it covers current host behavior and passes integration tests. |

* Typed Bridge Boundary

The existing bridge should evolve from permissive =unknown= payloads to a typed =auto-dig-quasar.v2= contract[fn:contract].

The bridge may define host-specific envelopes for:

- active dataset and research-run context;
- correction and tipline commands;
- Auto-Dig actor findings;
- host navigation and selection events;
- host capability discovery.

It must reference shared =star.graph.v1= and =quasar.control.v1= objects for graph/document mutations and canonical runtime commands.

#+begin_src text
auto-dig host
    |
    v
auto-dig-quasar.v2 host envelope
    |
    +--> star.graph.v1 graph/document commands
    +--> quasar.control.v1 runtime commands
    +--> Auto-Dig-only context/events
#+end_src

The bridge must reject unknown methods and structurally invalid payloads at its boundary.

* Upstream Rule

Generic fixes discovered while working in =auto-dig-quasar= belong upstream when they change reusable Quasar behavior, including:

- graph rendering and selection;
- command handling;
- document editing;
- undo/redo;
- persistence adapters;
- common actions;
- accessibility;
- generic performance work;
- generic mobile behavior.

A generic fix may remain fork-only temporarily only when an upstream issue or pull request records why it cannot yet be merged.

Auto-Dig-only behavior includes dataset-review affordances, correction/tipline flows, host dataset context, and presentation that has no generic Quasar equivalent.

* Migration Trigger

Replacing the full fork with a narrow adapter becomes eligible when all of these are true:

1. shared graph/document command fixtures are stable under QUASAR-003;
2. canonical runtime authority is accepted under QUASAR-004;
3. standalone browser boundaries are accepted under QUASAR-005;
4. the typed bridge has no =unknown= request, result, or event payloads at its public boundary;
5. every current Auto-Dig host capability is covered by an integration test;
6. upstream =quasar-ui= can be consumed without carrying a large permanent patch stack.

Migration eligibility is not automatic approval to perform the migration.

* Acceptance Gates

| Gate | Required proof |
|------|----------------|
| Pin proof | Host reports exact fork and upstream revisions. |
| Dataset load | Host opens an Auto-Dig dataset through the bridge and reaches the expected Quasar view. |
| Mutation | A document or relation edit uses the shared command contract and survives reload. |
| Invalid payload | Unknown method or malformed payload is rejected with a structured error. |
| Upstream sync | A generic upstream change is merged into the fork without history rewrite and passes validation. |
| Host isolation | Auto-Dig-only code is identifiable without searching the entire generic application for hidden conditionals. |

* Non-Goals

- Do not make the fork canonical Quasar.
- Do not duplicate =star.graph.v1= in an Auto-Dig namespace.
- Do not redefine ADARD[fn:adard] research evaluation or promotion inside Quasar.
- Do not require immediate removal of the fork merely because a future adapter architecture is cleaner.
- Do not put renderer-scale decisions in this document; QUASAR-007 owns them.

* Footnotes and Glossary

[fn:auto-dig] Auto-Dig: The StarIntel generated research, dataset, document, source, and graph exploration system.

[fn:fork] Fork: A repository derived from another repository so it can carry local changes while periodically incorporating upstream changes.

[fn:adapter] Adapter: A narrow integration layer that converts between two interfaces without copying the full implementation on either side.

[fn:contract] Contract: A versioned structure and behavior that communicating components agree to validate and use.

[fn:adard] ADARD: Adaptive Research DAG, the StarIntel research control plane that owns candidate, evidence, review, evaluation, and promotion semantics.
