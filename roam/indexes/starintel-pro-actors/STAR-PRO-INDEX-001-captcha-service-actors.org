* Purpose

This index connects the StarIntel[fn:starintel] CAPTCHA[fn:captcha] detection and broker designs to local, browser, manual, and paid solver actors. Core detection, authorization, routing, budgets, deduplication, and result references belong to =starintel-server=.[fn:star-server] Vendor-specific and specialized solver implementations belong to =starintel-pro-actors=.[fn:pro-actors]

The subsystem is restricted to operator-owned systems, accessibility workflows, quality assurance, and explicitly authorized automation. It is not a public solve relay.

* Architecture Decisions

- Challenge issuer and solver provider are separate axes.
- The broker matches exact issuer, family, variant, version, context, and result-kind capabilities.
- The catalog is open-world and retains =custom= and =unknown= challenge types.
- =CaptchaDetectActor= takes a source actor reference, requests bounded evidence, classifies the active challenge, invokes the broker, returns apply instructions, and verifies resumption.
- The source actor retains ownership of its browser or request session.
- Tokens, cookies, answers, coordinates, proofs, and interaction plans remain ephemeral secrets.
- A provider is not globally rejected because it lacks hCaptcha. It advertises only the capabilities supported by a current contract.
- Paid or human-assisted disclosure requires explicit target policy.

* Required Document Shape

Every CAPTCHA research or design node must contain:

1. an explicit scope and non-scope;
2. an approval table with real =PENDING=, =APPROVED=, =REJECTED=, or =NOT STARTED= state;
3. at least one relevant PlantUML graph;
4. exact capability or challenge taxonomy;
5. current source retrieval dates for external contracts;
6. secret, session, and disclosure handling;
7. related-node links;
8. glossary definitions;
9. test or evidence requirements;
10. no fabricated approval or implementation claim.

* Implementation Order

1. Approve the normalized challenge descriptor, result kinds, and capability registration.
2. Implement =CaptchaDetectActor= and =CaptchaBrokerActor= with fake detector and solver actors.
3. Implement source-actor integration using the current =define-actor=, =register-actor=, =get-dest-actor=, and =tell= service.
4. Implement NoneCap for its narrow verified hCaptcha capability.
5. Implement NopeCHA with separate Recognition and Token capabilities.
6. Implement 2Captcha as a broad asynchronous task adapter, enabling each family only after a contract fixture passes.
7. Add browser, local recognition, and manual-review actors.
8. Add Anti-Captcha, CapSolver, or CapMonster only to close measured capability gaps.
9. Add health, circuit breaking, acceptance telemetry, budgets, and explicit fallback.
10. Run opt-in canaries only against operator-owned test systems.

* Non-Goals

- Browser fingerprint fabrication.
- A public HTTP solve endpoint accepting arbitrary targets.
- Automatic authorization based on challenge type.
- Persisting results, session cookies, proxy credentials, or provider keys.
- Treating every anti-bot block as a CAPTCHA.
- Pretending an unknown challenge is a known issuer.
- Selecting solely by advertised price.

* Footnotes and Glossary

[fn:starintel] StarIntel: A local-first actor-based platform that collects, normalizes, links, searches, and analyzes authorized data while preserving provenance.

[fn:captcha] CAPTCHA, or Completely Automated Public Turing test to tell Computers and Humans Apart: A challenge or risk-control mechanism intended to distinguish ordinary human or trusted-browser interaction from automated abuse.

[fn:pro-actors] StarIntel Pro Actors: Optional paid-service, collection, browser, recognition, and enrichment actors deployed separately from the generic server core.

[fn:star-server] StarIntel Server: The Common Lisp control, routing, persistence, authorization, search, and actor-hosting service.
