* Purpose

This pass closes the gap between the language users were shown and the lower-level compiler fixture from Loop 007. Ordinary Star-Lang source now starts with =spec-library= and declares scalars, enumerations, documents, predicates, and messages directly. It does not require users to write or understand a =spec-graph= form.

The compiler still retains exact import versions and digests. Those values are lock and provenance inputs, not the conceptual center of the language.

* Field Naming

Star-Lang document fields, message-payload fields, and wire-envelope keys use lower camelCase. Examples include =candidateId=, =messageId=, =correlationId=, and =replyTo=. The compiler preserves these names exactly through normalized IR, manifests, serialization, and generated bindings.

DSL forms and named declarations are not fields. Forms and identifiers such as =spec-library=, =ingest-page=, scalar/type names, predicates, actors, compiler options, and restart names may remain kebab-case. Kebab-case field declarations are invalid and must produce a structured compiler diagnostic.

* Concrete Surface

The core specification surface is:

#+begin_src lisp
(spec-library "org.starintel/fec@1"
  (:version "1.0.0"
   :digest "sha256:fec-core-v1-research-fixture")

  (import "org.starintel/core@1"
    :version "1.0.0"
    :digest "sha256:core-v1-research-fixture")

  (scalar candidate-id
    (:base string
     :pattern "^[HSP][A-Z0-9]{8}$"))

  (enum office
    (president senate house))

  (document candidate
    (:persistence persistent)
    (candidateId candidate-id :required)
    (name string :required)
    (office office :required))

  (predicate candidate-committee
    (:source candidate
     :destination committee))

  (message ingest-page
    (:fields
     ((endpoint string :required)
      (page integer :required)
      (results (list map) :required)))))
#+end_src

This is data-only specification syntax. It does not execute arbitrary Common Lisp.

* Closed File Boundary

The Common Lisp research prototype now treats a =.star= file as a closed Star-Lang source boundary[fn:closed-source-boundary]. =load-star-form= uses an explicit parser[fn:parser] rather than the active Common Lisp reader, accepts comments and ordinary whitespace, requires exactly one =spec-library= unit, and immediately compiles that unit into normalized intermediate representation[fn:ir].

The parser represents source identifiers as strings and maps only the language's fixed option vocabulary to existing keywords. It therefore does not intern attacker-controlled identifiers into a Common Lisp package[fn:package]. Package-qualified names, reader evaluation, dispatch reader forms, quotation syntax, dotted lists, malformed lists, and malformed strings are rejected before compilation.

Parser and compiler failures remain structured Star-Lang conditions[fn:condition]. File-originated conditions include the source pathname plus a one-based line and column. This boundary performs no network access[fn:network-access] and does not resolve remote imports; digest-locked import resolution remains a separate explicit phase.

* Normalized Core IR

The Common Lisp prototype lowers each source declaration to closed property-list data with:

- a qualified library name and exact version
- exact digest-locked imports
- qualified scalar, enumeration, document, predicate, and message identifiers
- explicit required or optional field status
- normalized persistence values
- explicit predicate source and destination types
- deterministic declaration order

Unqualified local types are resolved to their library-qualified identifiers. Unknown unqualified types are rejected instead of being guessed.

* Semantic Validation

The normalized declarations pass through a semantic gate before a portable manifest is emitted. The gate enforces:

- document parents are documents rather than scalars or enumerations
- local inheritance chains are acyclic
- derived documents cannot redefine inherited fields
- predicate source and destination declarations are documents
- actor input contracts refer to messages
- actor output contracts refer to messages or documents

External qualified identifiers remain resolvable by the import/link phase. The local compiler does not fabricate declarations for them.

* Actor Boundary

Actors remain outside specification libraries because schemas and executable deployment are separate concerns. The same actor contract can be bound in two ways.

A native actor declares a Common Lisp handler and binds to cl-gserver:

#+begin_src lisp
(actor amendment-resolver
  (:runtime native
   :accepts (resolve-amendments)
   :produces (filing)
   :handler resolve-amendments-handler
   :restart transient
   :mailbox (bounded 256)))
#+end_src

The binding records =actor-of= construction and =tell= message delivery.

An external actor declares a wire protocol and endpoint:

#+begin_src lisp
(actor fec-importer
  (:runtime external
   :protocol star-message-v1
   :endpoint "rabbitmq:star.fec.ingest"
   :accepts (ingest-page)
   :produces (candidate committee filing)
   :restart permanent
   :mailbox (bounded 1024)))
#+end_src

The external binding records protocol dispatch without pretending that the process is a local cl-gserver actor.

* Portable Manifest

The compiler emits a =star-message-v1= manifest containing:

- library identity and imports
- scalar, enumeration, and document contracts
- predicate endpoints
- message payload contracts
- actor input and output contracts
- native or external runtime placement
- external protocol and endpoint data when applicable

The manifest is runtime-neutral data. JSON, MessagePack, CBOR, Protobuf generation, and language SDK generation are serialization adapters over this model rather than alternate schema systems.

* Wire Envelope

The first envelope contract contains:

#+begin_src lisp
(:starVersion 1
 :messageType "org.starintel/fec@1/ingest-page"
 :messageId "01JTEST"
 :actor "fec-importer"
 :dataset "fec-2026"
 :replyTo nil
 :payload (("endpoint" . "/candidates/search/")
           ("page" . 1)
           ("results" . nil)))
#+end_src

The prototype validates the wire version, resolves the message contract, and rejects payloads missing required fields. Deep scalar validation and transport acknowledgements remain later work.

* FEC Fixture

=prototypes/star-lang/fixtures/fec-core.star= is the first concrete external-domain specification fixture. It defines:

- FEC candidate and committee identifiers
- money, state, office, amendment, and support/oppose types
- entity, candidate, committee, filing, receipt, disbursement, and independent-expenditure documents
- candidate/committee, receipt, disbursement, filing, and expenditure predicates
- ingestion, amendment-resolution, and indexing messages

The fixture preserves raw source maps and filing provenance fields instead of claiming that the normalized schema exhausts the FEC source.

* Tests

The Common Lisp suites check:

1. the =spec-library= surface compiles without a source-level =spec-graph=
2. local types become qualified identifiers
3. required and optional fields remain explicit
4. portable message and actor contracts are emitted
5. native actors bind to =actor-of= and =tell=
6. external actors bind to protocol dispatch
7. valid envelopes pass contract validation
8. missing required payload fields fail
9. unknown local types fail
10. duplicate declarations fail
11. inheritance cycles fail
12. inherited-field redefinition fails
13. non-document parents fail
14. non-document predicate endpoints fail
15. actors cannot accept document contracts as messages
16. =.star= files compile directly to the same normalized IR as the trusted fixture form
17. empty files, multiple forms, wrong top-level forms, malformed syntax, reader dispatch, and package-qualified names fail with structured source context
18. duplicate declarations and invalid fields or types preserve their structured compiler condition classes
19. rejected attacker-controlled identifiers do not increase the parser package's symbol count

* Boundary

This pass does not:

- select Common Lisp as the final Star-Lang implementation
- replace the Racket and Scheme comparison loops
- implement transport acknowledgements or retries
- generate Python, Rust, TypeScript, or Prolog bindings yet
- serialize the manifest to a final wire encoding
- start cl-gserver actors or external processes
- promote the work into =roam/implement/=

The next core pass should add a canonical serialization adapter and generated bindings from this manifest while keeping the core IR independent from any one transport or host language.

* Footnotes and Glossary

[fn:closed-source-boundary] Closed source boundary: A file-reading interface that accepts only the intended language grammar and rejects behavior inherited from the implementation language. For example, a Star-Lang file cannot request Common Lisp reader evaluation.

[fn:parser] Parser: Code that turns source text into a structured language value while enforcing the language's grammar.

[fn:ir] Intermediate representation, or IR: Compiler-owned normalized data produced from source declarations before runtime adapters consume it.

[fn:package] Common Lisp package: A named table of symbols. Interning adds a symbol to that table, so untrusted source identifiers must not create package entries.

[fn:condition] Condition: A structured Common Lisp error value whose class and fields let callers distinguish source, declaration, field, and type failures without parsing display text.

[fn:network-access] Network access: Communication with another computer or service. This loader reads only the selected local file and leaves remote import retrieval to a separate resolver phase.
