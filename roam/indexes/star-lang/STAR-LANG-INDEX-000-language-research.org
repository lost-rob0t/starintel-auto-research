* Final Selection

Common Lisp is the sole approved Star-Lang implementation language.

The parser, compiler, semantic engine, normalized IR producer, dispatcher, recovery system, document runtime, and execution runtime are owned by Common Lisp.

Every alternate implementation language is DENIED.

Versioned JSON remains available at system boundaries. JSON does not constitute another Star-Lang implementation.

The architecture decision is approved. Implementation completion remains tracked by the active implementation node and GitHub issue [[https://github.com/lost-rob0t/starintel-auto-research/issues/47][#47]].

=STAR-LANG-002= does not reopen the language decision. It specifies the durable actor runtime required by the approved Common Lisp implementation.

The LISA, SWI-Prolog, and N-Prolog runtimes researched in STAR-LANG-RESEARCH-022 are inference backends consumed by the Common Lisp StarLang runtime. They are not alternate StarLang implementation languages.

* Current Library Finding

The Common Lisp ecosystem already supplies useful portable threads, actors, parallel tasks, HTTP, URI, TLS, HTML, XML, JSON, CSV, compression, hashing, persistence, and testing libraries.

The missing layer is durable actor correctness: bounded mailboxes, supervision, generations, journals, replay, lease fencing, capabilities, artifact custody, durable evidence-delivery intents, revisioned authorities, and StarLang compiler support.

For inference, the correct shape is also integration rather than replacement: StarLang owns the semantic protocol and compilation boundary while LISA, SWI-Prolog, and N-Prolog remain adapter-owned inference runtimes selected only when their declared semantic capabilities match the materialized plan.

The project should wrap and contribute upstream first, and fork only after a conformance suite proves that public extension points are insufficient.

* Runtime Repository

The canonical Common Lisp implementation now lives in [[https://github.com/lost-rob0t/star-lang][lost-rob0t/star-lang]]. The prototype files formerly stored under =prototypes/star-lang/= in this research repository are historical and have been removed from =main=.

This repository retains design, research, review, and implementation-ledger nodes. It does not host the live reusable runtime implementation.

* Preserved Invariants

1. all Star-Lang implementation code is Common Lisp;
2. source parsing is closed and does not execute host forms;
3. identifier data remains strings until validated, even when wrapped in first-class syntax objects;
4. document schemas, persistence, actor, tool, agent, and dataflow contracts remain explicit;
5. relations retain source, predicate, and destination positions;
6. field access remains explicit and dot syntax is denied;
7. normalized IR contains no cl-gserver object types;
8. lifecycle and transport settlement remain separate;
9. delivery is at least once and does not claim exactly once;
10. terminal duplicates replay without handler reinvocation;
11. runtime liveness affects routing rather than program validity;
12. research nodes never become StarIntel object types, predicates, or fields;
13. Auto-dig and Quasar consume contracts rather than define Star-Lang semantics;
14. alternate implementation languages remain DENIED;
15. source macros do not expose Common Lisp =READ=, =EVAL=, or arbitrary host transformer execution;
16. macro expansion must be deterministic, hygienic, digest-locked, bounded, and source-traceable;
17. macros disappear before normalized IR and runtime execution;
18. application actor systems may be authored entirely in StarLang while low-level runtime ports remain Common Lisp libraries;
19. mature ecosystem libraries are not rewritten without a measured semantic blocker;
20. durable artifact success requires a durable evidence-delivery intent or one transactional downstream release;
21. logic backend identity is explicit data, while native engine objects and executable source remain outside normalized StarLang IR;
22. a materialized logic plan pins exactly one concrete inference backend and does not change engine type because of runtime load or failure;
23. expert-system syntax lowers into checked core/IR and does not embed native LISA or Prolog forms;
24. source backend selection uses the compiler-only Lisp form =(pragma :backend ...)=; ordinary =(:backend ...)= metadata is not an equivalent selector, and a more-specific request never bypasses semantic compatibility or state-boundary safety;
25. source compiler pragmas are typed non-executable data and cannot grant capabilities, execute host code, or weaken mandatory deployment restrictions;
26. the portable logic API owns StarLang session-fact identity, named operation invocation, normalized result streams, cancellation, usage, and proof envelopes; native clause ordering, tabling/transactions, production agenda/focus, and belief semantics remain explicit versioned profiles;
27. expert-system research must not require a second expert-only application object model for authoritative StarIntel objects; direct object-backed reasoning or identity-preserving projection must retain the source identity/provenance required by the declared profile.

* Archive Rule

This file records research history. It does not approve implementation completion and must not be used as the active implementation ledger.

Do not reopen language comparison or add another implementation language without a new explicit reversal from nsaspy.

* Footnotes and Glossary

- *Research archive* — Historical sequence of StarLang research decisions; not the implementation completion ledger.
- *Inference backend* — External or embedded reasoning engine used by the Common Lisp StarLang runtime through a checked adapter; not an alternate StarLang implementation language.
- *Backend directive* — Compiler-only StarLang source form =(pragma :backend ...)= whose lexical policy is normalized before runtime execution.
- *Pragma* — Typed compiler-interpreted StarLang source data with explicit scope and no host execution authority.
- *Materialized plan* — Fully resolved immutable execution plan with concrete backend/package/mapping identities.
- *Expert sugar* — High-level StarLang syntax that expands into checked core/IR before runtime execution.
- *Logic API contract* — Versioned portable StarLang protocol that separates stable session/query/fact semantics from backend-specific semantic profiles.
- *StarIntel object reuse* — Expert reasoning over an existing authoritative StarIntel object directly or through an identity-preserving backend projection, without requiring a duplicate expert-only application object.
