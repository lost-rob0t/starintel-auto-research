* Government Data Acquisition Track

=STAR-RESEARCH-003= defines the canonical registry, source-discovery, platform-family, acquisition-priority, provenance, synchronization, failure, and coverage model for U.S. local and federal government data.

=STAR-RESEARCH-PIPELINE-003= is the dependent actor design. It uses long-lived authority, scheduler, and supervisor actors plus short-lived keyed acquisition workers. Government units remain records and job keys rather than permanent actors.

The actor design must be reviewed independently from the research and does not alter the approved implementation slot.

3. Implement deterministic validation.
4. Implement bounded branch supervision.
5. Implement independent reviewers and aggregation.
6. Implement the promotion gate.

8. Review =STAR-RESEARCH-PIPELINE-002= using the first measurable ADARD run records.
9. If approved, implement the deep-research protocol, adapter registry, deterministic fake adapter, and supervised process runner.
10. Implement Open Deep Research and GPT Researcher adapters against the same fixtures.
11. Run serial-versus-single-adapter-versus-capability-routing ablations.

14. Complete the Star-Lang comparison loop.
15. Use measured pipeline records and the completed Star-Lang comparison to propose a separate language implementation design.

* Footnotes and Glossary

[fn:control-plane] Control plane: The part of a system that decides what work should run, applies policy, records state, and coordinates workers rather than performing the main data processing itself.

[fn:domain-gserver] Domain gserver: A supervised actor subtree responsible for one bounded area of work, with its own dispatchers, ingress, workers, health, and optional transport gateways.
