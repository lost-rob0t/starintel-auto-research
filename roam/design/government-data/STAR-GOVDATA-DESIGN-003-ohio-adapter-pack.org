* REVIEW Objective

Define the smallest adapter set that can profile Ohio state systems and county source variation without writing one scraper per jurisdiction.

Ohio-specific adapters are allowed only where a source has stable Ohio semantics or unique protocol. Generic platform and format adapters remain preferred.

* REVIEW Adapter Boundary

An adapter is a short-lived, stateless or checkpoint-bounded actor/process. It receives one immutable lease-bound attempt and returns immutable retrieval events, evidence, artifact references, checkpoints, typed failures, and proposals.

An adapter may not write canonical identities, deployments, profiles, decisions, gaps, or route assessments; choose an applicability contract; approve its own evidence; infer capabilities from retrieved content; exceed bounds or leases; create credentials; accept terms; bypass controls; or retain unauthorized protected data.

Required operations include =:probe=, =:inventory=, =:fetch-page=, =:fetch-document=, =:fetch-bulk=, =:extract-links=, =:fingerprint=, and =:checkpoint=. No adapter supports every operation.

The Adapter Registry rejects mutable versions, missing schema ranges, undeclared methods, missing bounds, unsupported result protocols, and manifests without deterministic fixtures.

* REVIEW Durable Job and Execution Attempt

A durable job describes logical work and survives retries. It does not contain a lease that has not yet been issued.

#+begin_src lisp
(defstruct adapter-job-revision
  job-id job-revision-id prior-job-revision-id
  run-id command-id parent-command-id
  unit-ref component-ref route subfamily data-family
  source-profile-revision-id candidate-proposal-id
  deployment-revision-id search-plan-revision-id
  applicability-contract-id applicability-contract-version
  policy-snapshot-id
  adapter-id adapter-version adapter-manifest-hash runtime-environment-hash
  operation locator-ids allowed-hosts allowed-redirect-hosts
  cursor-checkpoint-id
  request-limit byte-limit object-limit depth-limit redirect-limit wall-time-limit
  credential-capability-id cancellation-id deadline
  artifact-policy idempotency-key input-hash)
#+end_src

Discovery before profile creation binds a candidate proposal or search-plan revision. Profile-backed acquisition requires an exact source-profile revision. Resume creates a new job revision only when logical scope, contracts, policy, adapter, bounds, or cursor changes.

After validation, the dispatcher obtains a lease and creates an immutable execution attempt:

#+begin_src lisp
(defstruct adapter-attempt
  attempt-id attempt-number job-revision-id prior-attempt-id
  rate-lease-id rate-lease-generation rate-lease-fence rate-lease-key-hash
  started-at attempt-deadline worker-generation
  attempt-input-hash)
#+end_src

Retrying the same logical job creates a new attempt with a new lease/fence; it does not mutate the job revision. Every request checks the current fence. A stale attempt must stop even if its local deadline has not expired.

* REVIEW Adapter Result

#+begin_src lisp
(defstruct adapter-result
  job-id job-revision-id attempt-id
  adapter-id adapter-version adapter-manifest-hash runtime-environment-hash
  status input-hash output-hash
  retrieval-event-ids evidence-ids raw-artifact-ids
  profile-proposal-ids deployment-proposal-ids gap-proposal-ids
  checkpoint-ids next-checkpoint-id
  truncation request-count byte-count object-count redirect-count
  started-at finished-at warnings failure)
#+end_src

Statuses are =:success=, =:partial=, =:no-change=, =:blocked=, =:unsupported=, =:ocr-required=, =:manual-review-required=, =:failed=, and =:cancelled=.

=:success= is invalid with truncation, missing required artifacts, unreconciled counts, or an expired lease. =:partial= requires explicit truncation and a resumable checkpoint or reviewed non-resumable explanation. Adapters return proposal IDs, never canonical profile IDs.

* REVIEW Determinism and Commit Ordering

For the same job revision, retained input artifacts, adapter manifest, runtime hash, and policy snapshot, normalized evidence and proposals must be deterministic. Transport timestamps are explicit observations or excluded from normalized output hashes.

Commit order:

1. validate immutable job and referenced contracts
2. acquire lease and fencing token
3. create immutable adapter attempt
4. issue bounded request after fence validation
5. reserve and stream raw artifact
6. verify bytes and content hash
7. commit retrieval event and artifact metadata
8. emit evidence and proposals
9. commit checkpoint
10. close lease
11. emit one terminal result

A checkpoint cannot advance past uncommitted artifacts/evidence. A crash after artifact commit resumes from the artifact. A retry uses the same job revision but a new attempt and lease unless logical scope changed.

* REVIEW Browser Evidence Boundary

A browser job additionally pins engine/version, runtime hash, viewport/locale when material, initial locator, navigation sequence, public form parameters, allowed origins/download types, and network-capture policy.

The result must produce the browser capture bundle required by =STAR-GOVDATA-DESIGN-002=. Screenshot-only evidence is rejected. Browser output cannot add hosts, credentials, or capabilities.

* REVIEW Ohio-Specific Adapters

** =ohio-laws=

Inventories Ohio Revised and Administrative Code; resolves current, prior, and future-effective versions; captures authenticated documents; emits relationships. Future-effective law never replaces current law before its effective date.

** =ohio-legislature=

Inventories bills, resolutions, sponsors, committees, actions, votes, documents, calendars, journals, and acts by General Assembly. It distinguishes informational bill text from authenticated enacted law.

** =ohio-buys=

Inventories public solicitations, awards, contracts, amendments, and attachments. Public read/download, supplier login, and response submission are separate capabilities. Only public read/download are authorized.

** =ohio-checkbook=

Identifies exports/endpoints, records participating-unit scope and reporting periods, distinguishes state/local submissions, and reconciles totals when possible. Participation is discovery/reconciliation evidence, never complete county finance validation.

** =ohio-sos=

Inventories results, campaign-finance search/transfers, county-board links, precinct/candidate products, and public business data when in scope. It distinguishes unofficial, official, canvassed, and historical states. Voter-record acquisition requires separate privacy review.

** =ohio-courts=

Profiles Supreme Court dockets, opinions, journals, statistics, and authoritative local-court directories. Local systems remain separate profiles using generic or reusable vendor adapters. Partial-current-year state propagates into evidence and gaps.

* REVIEW OGRIP Composition

#+begin_example
http-metadata
  -> static-directory
  -> arcgis-rest or ogc-service
  -> bounded bulk-file metadata
  -> archive-resolver
#+end_example

The composition inventories LBRS, imagery, elevation, mosaics, endpoints, update dates, and archives. Oversized files produce metadata plus =:file-too-large=; they are not partially downloaded or silently skipped.

* REVIEW Default Bounds

| Worker kind | Requests | Bytes | Objects | Wall time | Concurrency |
|-------------+----------+-------+---------+-----------+-------------|
| metadata probe | 10 | 5 MB | 100 | 120 s | 2 per host |
| HTML inventory | 50 | 25 MB | 2,000 | 300 s | 2 per host |
| API inventory | 100 | 50 MB | 10,000 | 600 s | lease-controlled |
| document capture | 25 | 100 MB | 250 | 600 s | 2 per host |
| static directory | 100 | 25 MB metadata-only | 25,000 | 600 s | 2 per host |
| browser probe | 20 navigations | 50 MB | 1,000 | 600 s | 1 per host |

Raising bounds creates a new policy snapshot and job revision.

* REVIEW Rate and Lease Keys

Lease dimensions include host, vendor, deployment/tenant, API key, source profile, adapter, government unit, and browser pool. Host aliases belonging to one deployment share limits.

A lease record exposes ID, generation, fence, key hash, issue time, expiry, and close state. Attempts carry the lease; durable jobs do not.

* REVIEW Fingerprint Pipeline

#+begin_example
official-domain evidence
  -> HTTP/redirect observations
  -> HTML metadata/assets
  -> known path probes
  -> JavaScript/configuration fingerprints
  -> API-shape probes
  -> platform candidate
  -> source/deployment proposals
  -> independent review
#+end_example

A fingerprint never proves authority, jurisdictional scope, or completeness.

* REVIEW Franklin Adapter Order

For each route/subfamily:

1. load pinned applicability rule and search-plan revision
2. verify official/delegated scope
3. run sitemap/feed and structured inventories
4. probe known platform signatures
5. prefer documented/observed APIs
6. probe delegated interfaces
7. use browser only when structured methods fail or profile requires it
8. return profile/deployment/gap proposals, never completion

One unsupported or browser-required adapter result cannot justify a negative decision.

* REVIEW Fixture Matrix

Required fixtures include exact manifest/runtime hashes, all generic adapters, effective-dated law, OhioBuys public-read/login-write separation, Checkbook non-completeness, oversized OGRIP metadata, SOS search/transfer, replayable court forms, partial-year statistics, ArcGIS viewer/REST preference, delegated portals, CAPTCHA, OCR-required PDF, browser bundle replay, redirect escape, stale lease fence, retry with new attempt, crash after artifact commit, truncated non-success, and duplicate job replay.

* REVIEW Implementation Order

After parent protocol alignment and approval:

1. manifest/job/attempt/result validators and deterministic fake adapter
2. immutable artifact/retrieval/checkpoint commit path
3. HTTP metadata, sitemap/feed, structured HTML, and static-directory adapters
4. PDF classifier/text, CSV/XLSX, ArcGIS REST, and OGC adapters
5. Ohio-specific adapters as pilot evidence requires
6. bounded browser bridge before any route requires browser probing

No live probes run until revision-aware commands, attempt/lease semantics, artifact ordering, and proposal-only writes pass fixtures.

* REVIEW Acceptance Criteria

1. Generic adapters are preferred.
2. Durable jobs pin exact logical work but never future leases.
3. Every execution attempt pins a current lease generation/fence.
4. Results bind job revision and attempt ID.
5. Results return evidence/artifacts/proposals, not canonical IDs.
6. Success cannot hide truncation, stale leases, or missing artifacts.
7. Checkpoints never advance past uncommitted evidence.
8. Browser evidence is replayable and OCR bounded.
9. Failures cannot complete routes.
10. The parent actor protocol must support revision-aware job/attempt fields before implementation.
