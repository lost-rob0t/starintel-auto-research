* Scope

This node rejects the invalid rule “a provider without hCaptcha is useless.” Provider state is capability-local. A missing hCaptcha contract changes only the hCaptcha row; it is not evidence against independently documented reCAPTCHA, Turnstile, Web Application Firewall, puzzle, image, proof-of-work, or other task families.

This is research approval only. It does not approve a provider adapter design, broker design, security policy, operations policy, or implementation.

A raw provider logo count is not a coverage matrix. One row includes issuer, family, variant, integration version, required fields, result kind, result binding, source-session/network requirements, execution/disclosure class, contract state, price confidence, and fixture freshness.

* CapSolver Gap Analysis

Current official support documentation, refreshed 2026-08-09, lists token-task support for GeeTest, reCAPTCHA v2/v3, MTCaptcha, DataDome, AWS WAF, Cloudflare Turnstile, and Cloudflare Challenge. Recognition support lists ImageToText, reCAPTCHA v2, AWS WAF, and VisionEngine.

Therefore:

- =captcha.hcaptcha.*= remains =unsupported=;
- Arkose/FunCaptcha is not registered from generic marketing language because the current exact support index does not list a corresponding task;
- DataDome requires exact proxy and user-agent fidelity; its task documentation requires the caller's proxy and matching user agent;
- Turnstile is documented as proxyless and ignores caller-supplied user agent, so it is a materially different context contract from DataDome;
- AWS WAF has proxy and proxyless forms with exact challenge-context combinations;
- one exact mapper failure affects only that capability unless shared authentication, account, or provider health fails.

** Pricing contradiction

Current official CapSolver pages disagree materially about advertised prices. The current pricing table lists Turnstile at one rate while another current official landing/documentation surface advertises a different rate. Price therefore has an independent =costConfidence= state.

Runtime or design work must not compile marketing prices into actor logic. Selection research should use configured reservation ceilings plus provider-reported/observed charges and timestamps. A pricing contradiction does not invalidate the request/result contract, but it prevents cost from being treated as high-confidence static evidence.

* Anti-Captcha Gap Analysis

Current official task documentation lists reCAPTCHA v2/v3 and Enterprise variants, Arkose/FunCaptcha, GeeTest, Cloudflare Turnstile, Prosopo, Friendly Captcha, AWS WAF, ALTCHA, image-to-text, coordinates, and AntiGate custom tasks.

Important context and disclosure findings:

- Turnstile has proxyless and proxy-on task forms; the proxy-on result includes a worker user agent that may need to accompany token submission;
- worker-backed solving means challenge material may be exposed to a human operator; target policy must authorize that disclosure before dereferencing sensitive context;
- AntiGate is not a normal provider-neutral CAPTCHA row. It can drive a programmable workflow against a target page and return browser artifacts such as cookies or fingerprint-related state;
- AntiGate therefore requires a separate target-specific design and security review and must never be registered as a wildcard “solve anything” capability;
- provider task results expose operational fields such as cost, worker/provider IP, timestamps, and solve count; these are useful redacted telemetry but not proof of downstream acceptance.

Anti-Captcha remains a strong redundancy candidate when the exact task closes a measured gap and the human-exposure class is permitted.

* CapMonster Cloud Gap Analysis

The refreshed official catalog is substantially broader than the older research snapshot. It currently includes reCAPTCHA v2/v3/Enterprise, GeeTest v3/v4, Cloudflare Turnstile, Cloudflare Challenge, Cloudflare Waiting Room, DataDome, AWS WAF, Imperva, ImageToText and complex-image tasks, Basilisk, TenDI, Prosopo, Binance, Yidun/NECaptcha, MTCaptcha, ALTCHA, FunCaptcha, TSPD, Hunt CAPTCHA, Alibaba Cloud CAPTCHA, and Friendly Captcha.

Key exact-contract distinctions:

- =captcha.hcaptcha.*= remains =unsupported= on the current catalog;
- ordinary Turnstile and Cloudflare Challenge are separate capabilities;
- Cloudflare Challenge may return either a token or a =cf_clearance= cookie, so result kind and downstream application cannot be collapsed into generic =token=;
- CapMonster uses built-in proxies for many tasks, but exact tasks can require caller-owned proxies;
- DataDome explicitly requires caller-owned proxy context and returns special cookies that must be applied to the browser;
- DataDome parameters are render-specific/dynamic and must be captured close to task creation;
- ALTCHA includes proof-of-work, code, and invisible forms with dynamic input fields;
- a historical unsupported hCaptcha response says nothing about these unrelated exact task families.

This makes CapMonster Cloud a particularly interesting redundancy candidate for typed WAF/browser-result coverage, but no adapter should be designed until exact result/context fixtures establish what can safely leave the source runtime.

* Required Provider Capability Fields

Any adapter backlog row must record:

- provider and official source;
- retrieval date and contract fingerprint;
- issuer, family, variant, and integration version;
- request and result operations;
- authentication and credential location;
- required and optional request fields;
- result kind and required result fields;
- result binding: unbound, source-session, same-network, proxy-bound, user-agent-bound, mobile/app-bound, or exact custom binding;
- proxy, cookie, user-agent, browser-session, network, and mobile requirements;
- execution class and worst-case human-exposure class;
- delivery, cancellation, idempotency, and ambiguous-create behavior;
- concurrency and rate-limit evidence;
- advertised cost, observed cost, reservation ceiling, and =costConfidence=;
- retention and data-disclosure implications;
- error contract;
- fixtures, canaries, unsupported variants, contradictions, and current state.

A provider marketing page is discovery evidence only when the exact task contract is absent.

* Adapter Candidate Gate

Create a dedicated adapter design only when:

1. a current official task page defines the exact request and result schema;
2. the capability closes a measured coverage or redundancy gap;
3. authentication and secret placement are known;
4. result kind and result binding map exactly to the broker-neutral research model;
5. execution and worst-case disclosure class are known;
6. provider retention and target-data exposure are understood;
7. cancellation, idempotency, ambiguous create, concurrency, pacing, billing, and errors are understood;
8. cost has a dated source and explicit confidence/reservation ceiling;
9. fake-provider request/result fixtures pass;
10. a credential-gated, cost-bounded operator-owned canary is separately approved.

This gate is research guidance. The adapter designs themselves remain unapproved.

* Reconsidering an Absent Capability

A previously absent capability such as hCaptcha can move from =unsupported= only when all of these exist:

1. a current official provider page naming the task;
2. documented create and result operations;
3. documented required request and result fields;
4. documented authentication and error contract;
5. exact variant, result, proxy, session, network, mobile, execution, and disclosure rules;
6. a passing fixture or bounded operator-owned probe;
7. a retrieval date and fixture fingerprint;
8. security and operator review.

A stale SDK symbol, extension claim, or broad marketing statement is insufficient.

* Candidate Evaluation Axes

Do not rank providers by hCaptcha alone or by catalog breadth. Compare exact candidates by:

- uncovered capability or redundancy value;
- contract clarity and contradictions;
- fixture freshness;
- result-kind and result-binding fidelity;
- source-context fidelity;
- exact downstream acceptance rate;
- worst-case execution and disclosure class;
- session, network, proxy, cookie, and user-agent compatibility;
- cancellation and ambiguous-create behavior;
- provider health, pacing limits, and concurrency;
- deadline fit;
- cost per accepted result plus =costConfidence=;
- operator policy.

* Research Gaps

- Capture exact current request/result fixtures for the high-value CapSolver rows, especially DataDome, AWS WAF, Turnstile, and Cloudflare Challenge.
- Resolve CapSolver price contradictions using account-side/provider-reported billing evidence rather than marketing pages.
- Capture CapMonster Cloud Cloudflare Challenge token-vs-cookie and DataDome cookie/proxy fixtures.
- Separate Anti-Captcha normal worker tasks from AntiGate programmable-browser disclosure in the taxonomy.
- Verify provider retention and cancellation semantics capability by capability.
- Build the measured StarIntel coverage matrix from observed challenge rows, not provider catalogs.
- Compare redundancy benefit and cost only after exact context and disclosure eligibility.

* Footnotes and Glossary

- *Capability gap* — An exact challenge row with no eligible validated solver or insufficient independent redundancy.
- *Result binding* — Context that must remain stable for the result to work, such as session, network identity, proxy, user agent, or app runtime.
- *Cost confidence* — Confidence that a dated advertised/configured price matches actual current provider billing.
- *Human exposure possible* — A provider task class where human review/solving may occur even if automation is attempted first.
- *Global provider rejection* — Invalid practice of disabling every provider capability because one task family is absent or broken.
