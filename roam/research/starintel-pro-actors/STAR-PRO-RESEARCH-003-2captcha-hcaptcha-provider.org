* Scope

This note evaluates 2Captcha as a broad asynchronous solver provider. The previous hCaptcha-only framing hid the strongest reason to consider the provider: its current API catalog spans token systems, Web Application Firewall challenges, image recognition, coordinates, grid, rotate, draw-around, drag-and-drop, and multiple vendor-specific families.

hCaptcha remains a separate contract-drift question. The adapter may support other verified families while leaving hCaptcha disabled.

* Stable Generic Contract

| Capability | Current public contract |
|------------+-------------------------|
| Create | =POST https://api.2captcha.com/createTask= |
| Retrieve | =POST https://api.2captcha.com/getTaskResult= |
| Balance | =POST https://api.2captcha.com/getBalance= |
| Feedback | family-specific correct/incorrect reporting |
| Optional delivery | callback uniform resource locator |
| Authentication | =clientKey= in JavaScript Object Notation body |
| States | =processing= and =ready= plus structured errors |

Version one of the StarIntel adapter uses polling, not callbacks, so no inbound provider listener is required.

* Current Catalog Coverage

The official API catalog currently includes or advertises families such as:

- Google reCAPTCHA v2, v3, and Enterprise;
- Cloudflare Turnstile;
- Arkose Labs FunCaptcha;
- GeeTest;
- Amazon challenge families;
- DataDome and Imperva/Incapsula families;
- Friendly Captcha, MTCaptcha, ALTCHA, Prosopo, CaptchaFox, Tencent, Yandex SmartCaptcha, and regional/vendor challenges;
- normal image-to-text, text questions, rotate, coordinates, grid, draw-around, and drag-and-drop.

Each task page has its own required fields and result schema. The runtime must not infer that one generic =createTask= shape makes all tasks interchangeable.

* hCaptcha Contract State

Historical client and browser materials have used task names such as =HCaptchaTaskProxyless= and =HCaptchaTask=. The current main task navigation has been inconsistent. StarIntel therefore keeps hCaptcha =experimental= until one of these exists:

1. a current official task page with request and result schema;
2. a provider sandbox fixture; or
3. a bounded live fixture against an operator-owned hCaptcha page.

Other verified 2Captcha capabilities do not depend on this gate.

* Per-Family Adapter UML

@startuml
participant "CaptchaBrokerActor" as Broker
participant "TwoCaptchaAdapterActor" as Adapter
participant "2Captcha API" as API
participant "EphemeralSecretStoreActor" as Secrets

Broker -> Adapter : captchaProviderSubmit\ncapabilityId + challengeRef
Adapter -> Adapter : load exact task mapper
alt mapper verified
  Adapter -> API : POST /createTask
  API --> Adapter : taskId or error
  loop until ready or deadline
    Adapter -> API : POST /getTaskResult
    API --> Adapter : processing / ready / error
  end
  Adapter -> Adapter : validate family-specific result schema
  Adapter -> Secrets : store typed result
  Adapter --> Broker : succeeded(resultRef, resultKind)
else mapper missing or drifted
  Adapter --> Broker : unsupportedChallenge / invalidContract
end
@enduml
#+end_src

* Capability Registration

The adapter stores one contract record per task family:

- =capabilityId=;
- provider task type;
- required normalized fields;
- request mapper version;
- expected result kind and required result fields;
- proxy and session requirements;
- disclosure class;
- cost model;
- official contract retrieval date;
- request/result fixture fingerprint;
- state: =verified=, =experimental=, =degraded=, =invalidContract=, or =disabled=.

One family drifting disables only that capability, not the whole provider, unless authentication, balance, or generic API health fails.

* Result Kinds

2Captcha can return different normalized kinds:

| Provider task family | StarIntel result kind |
|----------------------+-----------------------|
| Token systems | =token= |
| WAF or clearance systems | =token= or =cookie= |
| Normal/text CAPTCHA | =textAnswer= |
| Coordinates or draw-around | =coordinates= |
| Grid | =selectionSet= |
| Rotate or drag-and-drop | =interactionPlan= or typed family result |
| Score-producing systems | =assessment= or =token= according to current contract |

The adapter validates the exact expected kind before storing the result.

* Human-Worker and Disclosure Model

2Captcha describes automated solving with human-worker escalation for difficult tasks. The adapter registration therefore declares =executionClass: humanAssistedVendor= unless a capability contract proves otherwise.

Target policy must explicitly allow this disclosure class. Authenticated cookies, private page content, personal data, and full browser snapshots are not sent by default. Only the minimum normalized challenge context and bounded artifacts required by the approved capability are disclosed.

* Idempotency, Cancellation, and Ambiguity

The generic contract does not provide a create idempotency key or universal cancellation operation. The adapter journals the attempt before creation, records =taskId= immediately, attaches duplicate messages to the existing task, and never retries an ambiguous create automatically.

Local cancellation stops polling and deletes local result material. The provider task may continue and may charge. The normalized result reports =providerCancellationSupported: false= unless a specific task contract later proves otherwise.

* Contract Drift

A missing required result field, unexpected result kind, or task-not-supported response moves only the affected capability to =invalidContract=. The actor stops routing new work for that capability and emits a contract-drift event with redacted fixture metadata.

* StarIntel Decision

Design and implement 2Captcha as a broad exact-capability adapter candidate. Do not wait for hCaptcha confirmation before using other verified families. Do not enable any family solely because it appears in an old software-development kit or marketing page.

* Test Requirements

- Generic create, processing, ready, balance, feedback, and error mocks.
- One mapper/validator fixture per enabled family.
- Text, token, cookie, coordinates, selection, and interaction-plan result tests.
- hCaptcha disabled and successful/failed contract-probe tests.
- Per-family drift disables only that capability.
- Duplicate delivery, ambiguous create, and local cancellation.
- Disclosure-policy denial before challenge context dereference.
- Provider key and result redaction.
- No callback listener in version one.
- Per-family opt-in owned-system canaries.
