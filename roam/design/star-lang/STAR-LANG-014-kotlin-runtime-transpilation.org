* Authority

This node records the explicit operator reversal on 2026-09-20: port StarLang runtime code to Kotlin and transpile executable StarLang to Kotlin, using Java, Nim, or C only where they are the better boundary technology.

It supersedes the runtime-host restriction in STAR-LANG-001. It does not reopen the closed-source parser safety model or authorize multiple competing semantic runtimes.

* Decision

1. The closed StarLang parser, macro expander, validator, normalized IR producer, and canonical manifest producer remain compiler authorities until separately migrated.
2. The canonical executable runtime target becomes Kotlin/JVM.
3. The compiler gains a deterministic Kotlin backend from normalized runtime-neutral IR.
4. Runtime behavior migrates from Common Lisp to Kotlin subsystem-by-subsystem under differential parity tests.
5. After a Kotlin subsystem reaches parity and cutover, the superseded Common Lisp runtime implementation is deleted or reduced to a non-authoritative compatibility adapter. Permanent duplicate semantic ownership is forbidden.
6. Public Kotlin runtime APIs MUST be Java-friendly; Java is an ABI/consumer surface, not a second semantic implementation.
7. Nim MAY implement isolated native/edge adapter executables when a JVM is unavailable or materially inappropriate. Such adapters communicate through versioned StarLang wire/effect-port contracts and do not own actor semantics.
8. C is last-resort FFI glue for external native libraries only. No parser, compiler, dispatcher, mailbox, supervision, lifecycle, recovery, or actor semantics may be reimplemented in C.

* Language Selection

| Layer | Owner | Rule |
|-------+-------+------|
| Parser / source spans / macro expansion | Common Lisp for this migration | Preserve the closed parser and current safety invariants. |
| Normalized IR / canonical manifests | Common Lisp for this migration | Remain runtime-neutral and deterministic. |
| Executable code generation | Common Lisp compiler -> Kotlin backend | Generated Kotlin is deterministic from normalized IR. |
| Runtime actor semantics | Kotlin | Single canonical implementation after cutover. |
| JVM consumer ABI | Kotlin with Java-compatible API | No handwritten duplicate Java runtime. |
| Android runtime | Kotlin/JVM | Same semantics and portable contracts; Android-specific effects remain adapters. |
| Native/edge effects | Nim when justified | Separate process/FFI adapter, never semantic core. |
| Native library glue | C only when unavoidable | Thin ABI shim only. |

* Migration Rule

The existing Common Lisp runtime is the differential oracle during migration, not a permanent alternate runtime.

For every port slice:

1. freeze behavior as portable fixtures and canonical traces;
2. add a Kotlin parity test that executes the real Kotlin boundary;
3. run the same fixture against the current Common Lisp owner;
4. compare normalized outputs, lifecycle trace, errors, generations, replay/idempotency state, and externally visible ordering;
5. cut ownership to Kotlin only when parity is green;
6. delete or demote the superseded Common Lisp behavior in the same or immediately following bounded cutover change;
7. never add new authoritative runtime behavior only to the old Common Lisp path.

* Required Port Order

1. portable value model and actor/reference types;
2. bounded FIFO mailbox;
3. runtime registry, generations, start/stop/restart/shutdown;
4. deterministic tell/ask/dispatch loop;
5. runtime directory and star:// resolution;
6. lifecycle wire dispatcher, cancellation, deadlines, idempotency, retry/deferred settlement;
7. supervisor/restart policies;
8. journal/replay;
9. leases and capability enforcement;
10. artifact and verification contracts;
11. adapter SDK and HTTP/process ports;
12. durable/distributed transport integration;
13. CLI run/materialization path;
14. prototype compatibility retirement and removal of superseded Common Lisp runtime ownership.

* Transpiler Contract

The Kotlin backend MUST:

- consume normalized runtime-neutral IR, never raw .star source;
- emit deterministic source for identical normalized IR;
- preserve source identifiers and manifest lowerCamelCase field spelling;
- avoid host-language eval or arbitrary Kotlin escape hatches;
- generate explicit actor definitions, contracts, effect requirements, and runtime registration;
- keep external effects behind typed ports;
- produce source maps/provenance back to StarLang source spans where available;
- support a canonical formatting mode so generated-source hashes are stable.

* JVM Runtime Contract

The Kotlin runtime MUST preserve the approved runtime semantics already exercised by StarLang:

- bounded mailboxes and explicit full/closed delivery outcomes;
- per-runtime ownership with no process-global actor registry;
- generation-fenced actor references and stale-reference rejection;
- deterministic single-message actor transition semantics;
- transition-time state isolation before commit;
- typed contract validation;
- lifecycle/idempotency/correlation/causation/attempt/deadline semantics;
- cooperative cancellation and deterministic terminal replay;
- bounded supervision and restart accounting;
- durable journal/replay and lease fencing;
- capabilities and effect-port isolation.

Concurrency is an implementation detail and MUST NOT change externally visible semantic ordering. Coroutine/virtual-thread adapters may schedule work only around the deterministic semantic core.

* Java ABI

Kotlin public types must remain straightforward for Java callers:

- avoid Kotlin-only public type tricks at the boundary;
- expose stable constructors/factories and immutable DTO-style protocol values;
- use explicit nullable contracts;
- provide Java-callable static/factory entry points where useful;
- maintain binary-compatibility checks once the API is released.

* Nim / C Boundary

Nim is preferred over handwritten C for standalone native helpers because it offers a higher-level implementation while producing small native executables.

Allowed examples:

- OS/device integration unavailable on the JVM;
- high-throughput native codec or packet adapters;
- constrained edge workers where the JVM cannot be deployed.

C is allowed only when binding an existing C ABI or where no practical Java FFM/JNI/JNA/Nim boundary exists.

All native components communicate via frozen wire/effect-port contracts. They do not import or reproduce StarLang runtime state machines.

* Acceptance Gates

- Kotlin runtime tests execute the real Kotlin runtime.
- Differential fixtures prove parity with the current Common Lisp oracle for every migrated slice.
- Generated Kotlin is byte-for-byte deterministic after canonical formatting.
- JVM tests include Kotlin and Java consumer compilation.
- Android-compatible tests cover the portable runtime subset.
- No Kotlin runtime slice depends on prototype/.
- No semantic behavior exists in both Kotlin and Common Lisp after its declared cutover.
- Native adapters cannot mutate runtime-owned state except through typed messages/effect responses.
- CI reports the exact migration ownership map and fails if a cutover subsystem regains duplicate authority.

* Toolchain Baseline

Implementation currently targets Kotlin 2.4.20 and Gradle 9.7.1. Exact versions are implementation pins rather than language semantics and may be upgraded independently with CI proof.

* Superseded Decision

STAR-LANG-001 remains authoritative for the closed parser, declarative source model, safety boundaries, normalized IR discipline, and deterministic semantics except where this node explicitly changes runtime implementation ownership.

The rule "Common Lisp is the sole runtime implementation language" is superseded by this node.
