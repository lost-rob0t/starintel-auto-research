* Scope

This index tracks the shared symbolic knowledge system across its repository boundaries. The ARADR control plane is =lost-rob0t/starintel-auto-research=. The product implementation repository is =lost-rob0t/star-kb=. Runtime execution may occur through =lost-rob0t/prolog-query-server=, direct/native Prolog actors, or StarLang logic actors using StarLang's logic protocol/IR.

PQS remains the preferred shared safe runtime, but it is not the exclusive semantic authority for reusable rules. =star-kb= owns canonical package semantics; backend-specific mappings own runtime materialization.

* Approved Portable Rule-Reuse Direction

STAR-KB-RESEARCH-004 is approved. The resulting design direction is:

#+begin_src text
                    canonical reusable logic
                           star-kb
                              |
                 package digest + semantics
                              |
              +---------------+---------------+
              |               |               |
              v               v               v
         PQS mapping      SWI mapping     StarLang selection
         safe shared      local/direct    eligible backend
              |               |               |
              +---------------+---------------+
                              |
                       same package

safe package           -> PQS or eligible local SWI
sandbox-required       -> eligible sandboxed native worker only
prohibited             -> no execution route
#+end_src

Portability and execution trust are independent. The design uses =portable-core/backend-extension/native-only= for semantic portability and =safe/sandbox-required/prohibited= for execution trust.

Author metadata cannot lower trust. Static classification determines the minimum execution class, and unknown constructs fail closed. Normal PQS remains restricted and never gains arbitrary consult/meta-call/filesystem/network/process/foreign-code capabilities.

* STAR-KB-002 Design Highlights

[[id:star-kb-design-002-portable-logic-packages-sandboxed-actors][STAR-KB-002]] makes package identity backend-neutral and materialization identity backend-specific:

#+begin_src text
package digest  = what rules/semantics this is
mapping digest  = how one backend materializes it
evidence digest = what ephemeral actor/session facts were supplied
backend build   = which exact runtime executed it
isolation class = where/how it was permitted to execute
#+end_src

The initial parity targets are PQS and native SWI-Prolog. LISA/N-Prolog remain later targets behind the same semantic-profile/capability model.

The sandbox-required route is deny-by-default and must provide no ambient credentials, no network by default, narrow/read-only filesystem access, bounded private scratch, CPU/time/memory/PID/output/open-file limits, privilege-escalation prevention, deterministic cancellation/reaping, and explicit capability grants. Failure to establish required isolation rejects execution.

Actor/session fact deltas are ground data only, constrained to predicates declared by the package, separately digested/provenanced, and destroyed with the query/session. They cannot inject new rules or mutate canonical package semantics.

* Operational Follow-up Research Gate

[[id:star-kb-design-001-canonical-knowledge-authoring-query-plane][STAR-KB-RESEARCH-002]] resolves seven previous operational questions with preferred dispositions, but those additions remain =PENDING= operator review:

- normal activation should keep roughly 25% headroom under active PQS hard ceilings;
- same-KB throughput should be managed as serialized utilization, with roughly 70% sustained mutex utilization as a practical pressure point pending actual benchmarks;
- large relational/reused actor evidence may move to bounded query/session-local ground fact overlays;
- general probabilistic programming stays outside normal safe PQS; a separate calibrated fusion/model component is the first escalation;
- multi-KB imports wait until duplicated bytes/reload/release churn are measured problems and must later be immutable digest-pinned dependencies;
- first-party dialect collection uses purpose-separated consent, finite raw retention, deletion while controlled, and aggregate publication by default;
- deterministic hashes remain content identity while detached signed attestations later provide build/approval trust evidence.

* Footnotes and Glossary

- *ARADR control plane* :: Research/design/implementation-state documents; for STAR-KB these live in =starintel-auto-research=.
- *PQS* :: =prolog-query-server=.
- *Logic package* :: Backend-neutral, versioned/digest-identified reusable unit of logical semantics.
- *Package digest* :: Identity of normalized canonical package semantics independent from a specific runtime representation.
- *Mapping digest* :: Identity of one backend-specific materialization/translation.
- *Semantic profile* :: Named behavioral contract that an eligible logic backend claims and proves it can execute.
- *Portability class* :: Portable core, backend extension, or native-only semantic dependence.
- *Execution class* :: Safe, sandbox-required, or prohibited execution trust requirement.
- *Sandbox* :: Isolation boundary reducing blast radius for approved native-power logic; it does not make arbitrary code trusted.
- *Ephemeral fact overlay* :: Bounded query/session-local ground data supplied without mutating the canonical package.
- *Evidence digest* :: Identity of normalized actor/session evidence supplied to a logic operation.
- *Semantic parity* :: Evidence that the same package produces equivalent defined behavior across claimed compatible backends.
- *Attestation* :: Detached signed evidence describing who/what built or approved an exact content digest under specific build/test/provenance conditions.
- *Implementation slot* :: The one active approved design copy under =roam/implement/<project>/= used to track actual implementation work.
