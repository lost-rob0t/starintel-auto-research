* Research Question

How should StarIntel build a large, reusable corpus of Prolog facts and rules that can be consumed by many actors without duplicating knowledge or embedding a separate Prolog runtime in every actor, while preserving source provenance, reproducible releases, bounded inference, and a path to StarLang and learned-model evidence?

The immediate reference use case is a dialect-enrichment actor that can reason over linguistic observations and return explainable regional-language candidates. The architecture must generalize to geography, organizations, identity, infrastructure, social platforms, political structures, and later expert systems.

This document is research evidence only. It does not authorize runtime changes, actor implementation, or dataset publication.

* Verified Facts

- =lost-rob0t/prolog-query-server= already provides a CouchDB-backed SWI-Prolog expert-system runtime with named KBs, safe JSON AST facts/rules, bounded inference, explanations, release semantics, authentication, synchronization, and tests.
- =lost-rob0t/starintel-server= already provides the actor/messaging/runtime boundary that will consume knowledge-service results.
- =lost-rob0t/star-lang= currently points toward generic process/RPC adapters rather than Prolog syntax embedded into the language core.
- MyDialect/Harvard-derived dialect data is useful research material but carries licensing constraints unsuitable for silent adoption as unrestricted canonical production knowledge.
- Weak geographically labeled public corpora describe posting/current geography more directly than dialect-acquisition origin and therefore require careful label semantics.

* Inference

The approved research direction is to use =prolog-query-server= as the shared inference runtime rather than creating or embedding a separate SWI-Prolog runtime in every actor. A separate =star-kb= product repository should become the reviewed authoring/compiler plane for reusable symbolic knowledge after design approval.

Canonical knowledge, runtime knowledge releases, and run-specific StarIntel observations should remain distinct authorities. Readable restricted Prolog is a strong source format if it is parsed as data and compiled into PQS's safe structured representation rather than directly consulted/executed.

Dialect enrichment remains a good first downstream consumer after the generic knowledge pipeline is proven. Its output should preserve alternatives, confidence semantics, evidence provenance, and separation between linguistic evidence and other geographic clues.

* Contradictions

- Human-friendly Prolog source conflicts with PQS's deliberate rejection of arbitrary executable source unless a restricted parse-only compiler boundary is introduced.
- A large reusable corpus favors shared modules, while PQS currently queries one named KB/release at a time; V0.1 can resolve dependencies during build/publication and revisit runtime imports only after measurement.
- A continuously growing evidence corpus should not be confused with the slower reviewed canonical corpus; automatic observation-to-knowledge promotion would risk self-reinforcing contamination.

* Unresolved Questions

- Exact V0.1 restricted source grammar and deterministic normalization rules.
- Practical PQS bundle-size and same-KB concurrency limits.
- Whether later probabilistic inference belongs in dedicated safe builtins, cplint, or an external model/fusion layer.
- First-party dialect survey consent, retention, deletion, and publication policy.
- Whether future large evidence payloads need query-scoped ephemeral facts rather than bounded query arguments.

* Footnotes and Glossary

- *PQS*: =prolog-query-server=, the existing SWI-Prolog/CouchDB expert-system runtime.
- *KB*: a knowledge base, meaning a named set of facts and rules.
- *AST*: a structured representation of parsed source/code rather than raw executable source text.
- *Bundle*: a consumer-facing package formed from a dependency closure of reusable knowledge modules.
- *Release*: an immutable runtime version of one KB.
- *Provenance*: metadata recording where knowledge/results came from and which exact versions participated.
- *Observation*: case/run-specific evidence; not automatically reusable canonical knowledge.
- *Canonical knowledge*: reviewed reusable knowledge maintained for multiple consumers.
