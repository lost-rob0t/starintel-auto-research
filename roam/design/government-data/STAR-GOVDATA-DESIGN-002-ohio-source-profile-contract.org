* REVIEW Objective

Define one durable national-compatible contract for Ohio state systems, county systems, components, delegated vendor portals, shared deployments, static files, APIs, dashboards, form-driven searches, document archives, applicability decisions, and explicit coverage gaps without creating a schema fork per county.

* REVIEW Invariants

1. Search results and adapter observations create proposals, never verified canonical state.
2. Every verified profile revision links to official ownership or delegation evidence.
3. Every canonical profile, deployment, search plan, subfamily decision, gap, and route assessment is revisioned and immutable.
4. Every source-state or review-state transition creates a new revision; no canonical revision is updated in place.
5. Every revision declares its logical ID, revision ID, immediate predecessor, and the revisions it supersedes.
6. Route assessments bind exact profile, deployment, search-plan, subfamily-decision, gap, review, evidence, policy, and applicability-contract revisions.
7. Shared vendor deployments are separate from jurisdiction-specific authority and coverage.
8. A source profile does not imply complete route coverage.
9. Negative findings are evidence-bearing, expiring decisions.
10. =:not-applicable= requires positive authority or service-topology evidence.
11. Source state and human review state are independent enums and authorities.
12. Current, historical, and future-effective content are measured separately.
13. A later revision never changes the evidence basis of an older decision.
14. Browser and OCR output cannot become evidence without replayable artifact boundaries.
15. Personal-data fields and access restrictions are recorded before acquisition is authorized.

A browser bundle contains final URL, redirect chain, normalized DOM/rendered-text hash, public network-request metadata, public form parameters, browser/runtime version, navigation sequence, screenshot metadata, and raw-artifact references. Screenshot metadata alone is insufficient.

Until a reviewed OCR adapter exists, image-only documents return =:ocr-required= and enter manual review.

* REVIEW Official Status

=:official-status= is one of =:verified-official=, =:verified-delegated=, =:candidate-official=, =:candidate-delegated=, =:unverified=, =:rejected=, or =:retired=.

Verified official status requires government-controlled-domain, authoritative-registry, or authenticated-publication evidence. Verified delegated status requires an official government link or authority record. Logos, names, TLS certificates, and search results are insufficient by themselves.

** Initial Ohio county route contract

| Route | Kind | Required and conditional subfamilies |
|-------+------+------------------------------------------|
| identity | source | county identity/domains; component identities; delegated hosting; service-provider topology |
| open data | inventory | catalog/landing inventory; data.json/DCAT/platform probes; bulk/export inventory; reviewed absence |
| GIS | source | countywide or resolved-provider GIS; auditor/parcel; engineer/planning when operated; OGC/ArcGIS/bulk inventory |
| law | source | charter or reviewed non-charter result; resolutions/ordinances; code/policy repository; authoritative versions |
| meetings | source | commissioners; applicable boards; agendas/packets/minutes; votes/recordings when maintained; calendar/feed inventory |
| finance | source | budgets; annual reports/audits; payroll/checkbook/vendor payments when maintained; debt/grants/revenue when published |
| procurement | source | bids/solicitations; awards/contracts; purchase orders/vendor payments when maintained; delegated portal/attachments |
| property | source | auditor/assessment; recorder/deeds; treasurer/tax; parcel/GIS; resolved providers |
| courts | source | court/clerk topology; authoritative local-court links; public docket/index/document capability; restrictions |
| elections | source | board identity; candidates/precincts; result states; local campaign finance when maintained |
| public safety | source | sheriff; jail when county-operated; incident/dispatch/enforcement when published; applicable inspections |
| permits | source | building, zoning, planning, health, environmental, licensing, and code providers/capabilities |
| public records | source | policy; portal/method; contacts; fees; retention; official escalation instructions |
| feeds | inventory | sitemaps; RSS/Atom/iCalendar; alerts/newsletters; APIs/exports/change feeds; reviewed absence |
| archives | inventory | retired domains; predecessor/successor; archive candidates; historical repositories/exports; migration evidence |
| operational metadata | cross-cutting | platform/deployment; locators; auth/access; rate/lease; pagination/cursor; refresh; scope; artifacts/provenance; truncation; gaps/reassessment |

The operational-metadata route is derived from all bound revisions. No independent source profile satisfies it alone.

* REVIEW Independent State Models

Source states are =:candidate=, =:observed=, =:active=, =:changed=, =:blocked=, =:retired=, and =:rejected=.

Review states are =:unreviewed=, =:evidence-collected=, =:verification-pending=, =:reviewed=, =:changes-requested=, and =:invalidated=.

Workers propose source observations. The Source Profile Authority writes source-state revisions. The independent review authority writes review-state revisions. Every transition creates a new canonical revision with predecessor/supersession links. A changed source creates a new unreviewed revision; prior reviewed revisions remain immutable.

* REVIEW Validation Rules

A profile revision is invalid when authority, locator, deployment, scope, adapter capability, temporal evidence, artifact/provenance, access, browser/OCR, or independent-review requirements are missing.

A route assessment is invalid when:

- contract, policy, or exact revision bindings are missing
- a required subfamily lacks a reviewed decision revision
- not-applicable lacks positive authority evidence
- referenced profile, decision, search plan, deployment, gap, or review revisions are unresolved
- a negative state lacks completed reviewed search-plan and gap revisions plus reassessment deadline
- a stale negative result is used
- verified-partial lacks explicit scope/gaps
- a nonterminal state passes a gate
- an old revision is mutated
- operational metadata is marked verified while any bound revision lacks required fields

* REVIEW Ohio-Specific Extensions

Ohio-only fields may exist under =(:extensions (:ohio ...))=. An Ohio extension cannot replace generic source, deployment, applicability, decision, gap, assessment, or review fields.

* REVIEW Parent Actor Contract Requirement

Before implementation, =STAR-RESEARCH-PIPELINE-003= must expose revision-aware messages and durable ownership for route assessments and independent reviews. Until then, Ohio may be reviewed but cannot enter implementation.

* REVIEW Versioning and Migration

- logical IDs remain stable; revision IDs are immutable
- every state transition creates a new revision
- every superseding revision names what it replaces
- locator IDs remain stable while endpoints remain logical equivalents
- migrations create new locators and deployment/profile revisions
- retired revisions remain queryable
- contract or policy migration forces new decisions
- unknown newer fields are preserved
- latest-state materialization never erases history

* REVIEW Acceptance Criteria

1. One revisioned schema covers state, county, component, and shared deployment sources.
2. All sixteen routes have explicit machine-readable subfamily requirements.
3. Operational metadata is cross-cutting and derived.
4. Route assessments pin exact profile, deployment, decision, search-plan, gap, review, policy, and evidence revisions.
5. Every source/review transition is append-only.
6. Not-applicable requires positive evidence.
7. Negative findings expire.
8. Browser and OCR boundaries are reproducible.
9. Proposals and canonical writes are separated.
10. Parent protocol alignment is required before implementation.

* REVIEW Required Fixtures

- verified official/delegated and rejected lookalike sources
- shared deployment across jurisdictions
- all sixteen route definitions/rules
- legitimate and rejected not-applicable decisions
- image-only PDF and browser capture bundle
- incomplete current-year/participating-unit source
- source migration
- expiring/stale negative result
- review-state transition creating a new revision
- gap/decision/profile/assessment supersession replay
- later profile revision that does not alter an older route assessment
- contract/policy migration
- duplicate proposal idempotency
