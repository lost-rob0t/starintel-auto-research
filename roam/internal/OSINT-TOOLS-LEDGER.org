* Purpose

Track every OSINT tool encountered during StarIntel feature research before research conclusions are promoted into ARARD/ARADR documents.

This ledger is intentionally tool-centric. Architecture decisions remain domain-server-centric.

For every tool record:

- deeply enumerate the actual feature surface
- identify the smallest reusable capability set rather than cloning the product
- map those capabilities into an existing or proposed OSINT domain-server cluster
- prefer implementation in StarLang
- if StarLang cannot express a required primitive, record the missing language/runtime capability so StarLang can be extended
- use Common Lisp when the capability genuinely belongs below the StarLang surface or needs a Lisp library/adapter
- use Python only when StarLang plus Common Lisp cannot reasonably implement or wrap the required dependency
- preserve provenance, confidence, failure states, rate limits, and partial results
- do not create one actor per upstream feature or provider

* Implementation Preference

1. StarLang
2. Extend StarLang where the required semantic/runtime primitive is missing
3. Common Lisp library or adapter
4. Python only as a last-resort external process boundary

* Domain-Server Rule

Tools do not define architecture boundaries. Related capabilities are grouped into coherent domain servers. Providers and algorithms live behind capability contracts inside those servers.
