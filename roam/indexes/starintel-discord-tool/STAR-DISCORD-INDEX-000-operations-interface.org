* Scope

This index covers the operator-facing Discord application currently represented by =lost-rob0t/starintel-discord-tool=. The tool is treated as a controlled Python edge interface into StarIntel rather than as a second database, authorization system, research engine, or message broker.

The implementation-language decision is now explicit: =starintel-discord-tool= is to become a Python bot. Existing Nim package metadata is historical repository state, not the selected implementation direction.

* Implementation Order

1. Keep the research node in =REVIEW= until it receives separate explicit approval; do not infer research approval from the design decision.
2. Treat =STAR-DISCORD-001= as the approved architecture, including the requested Python bot change.
3. Replace the historical Nim edge direction in =starintel-discord-tool= with a pinned Python environment and =discord.py= application-command/Gateway implementation.
4. Add the authoritative =discord-ops-bridge= runtime boundary to =starintel-server=.
5. Add a narrow typed client protocol to the Python =starintel-discord-tool= edge.
6. Implement read-only search and identity/capability introspection first.
7. Add document submission with quarantine, validation, provenance, and idempotency.
8. Add subscription notifications.
9. Add trusted target creation and Auto-Dig job submission.
10. Add operator-approved RabbitMQ channel projections last.

The order intentionally keeps mutations and arbitrary event projection behind the read-only path until authorization, audit, replay, and failure behavior are observable.

* Footnotes and Glossary

[fn:gserver] A supervised actor-style service boundary that owns state and typed message handling inside the StarIntel runtime.

[fn:auto-dig] =lost-rob0t/starintel-gpt-auto-dig=, the Git-backed StarIntel research repository and recursive target-selection workflow.

[fn:projection] A bounded transformation of internal events into Discord notifications; it is not a second authoritative event store.

[fn:discord-py] =discord.py=, the asynchronous Python API wrapper selected for the Discord edge implementation; Discord-side permissions remain presentation constraints rather than StarIntel authorization.
