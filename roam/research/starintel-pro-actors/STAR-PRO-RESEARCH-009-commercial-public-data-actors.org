* Research Question

Which bounded actors in =starintel-pro-actors= could plausibly support a paid intelligence product, using available official data and the existing StarIntel document contract?

* Verified Source and Repository Facts

- The General Services Administration (GSA) Get Opportunities Public API returns published SAM.gov opportunity details, requires an API key and posted-date window, paginates with =limit=/=offset=, and exposes notice IDs, procurement type, North American Industry Classification System (NAICS) code, response deadline, and links. Its public endpoint exposes only the latest active version; the source says active notices update daily and archived notices weekly.[fn:gsa]
- USAspending's official endpoint reference says its endpoints currently require no authorization. It exposes federal award data through documented query endpoints.[fn:usaspending]
- The Securities and Exchange Commission (SEC) exposes company submission history and extracted financial data through JSON APIs. Its fair-access guidance currently caps scripted access at 10 requests per second per user, across machines.[fn:sec]
- The active =starintel-pro-actors= lock pins release/profile =0.9.1= and base/wire schema =0.9.0= at canonical commit =6479c0a9dc88ce9fed183515fc4df5d245de0b3a=. The canonical schema includes =procurement=, =contract=, =financial-observation=, =source=, and =actor-manifest= dtypes. The runtime currently has source-specific collection actors, a document publisher, and RabbitMQ integration; it has no dedicated GSA or SEC actor in the inspected Python tree.[fn:repo]
- Existing StarIntel government-data designs already cover procurement as a source family and define a separate broad jurisdiction acquisition program. Any federal product actor should reuse its source/provenance model, not create a second government-data control plane.[fn:govdata]

* Inferences and Unverified Commercial Assumptions

- Small contractors may pay for timely, narrowly filtered notices and deadline changes. The APIs prove data availability, not willingness to pay or alert quality.
- Vendors may pay for incumbent and spending context around notices. A join between opportunities and awards requires identity validation; a shared agency name or NAICS code alone cannot prove a contract lineage.
- Analysts may pay for filing-change monitoring, but this market may be crowded. Public access and permission to reuse SEC content do not imply differentiation.
- No revenue, market-size, conversion, or pricing claim is established by this research. Customer interviews, a measured pilot, and source-rights review are required before product commitment.

The first experiment should be a bounded GSA collector plus a manual customer-facing digest, followed by award context only when deterministic joins are measured. A generic all-sector alert feed would obscure whether a narrow buyer has value.

* Proposed ADADR Direction — Research Only

** Analyze

The hardest problem is producing a trusted, timely, non-duplicative signal from a public feed, not fetching a JSON page. Current source behavior provides a daily cadence and only the latest active opportunity version. That makes a durable observation history and deadline-change detection necessary for the proposed product.

** Design candidate

Give each source adapter an explicit request budget and persisted checkpoint. Store source snapshots by source notice ID plus observed content digest. Convert only validated fields into the pinned StarIntel dtype, preserve the raw source locator and collection time, and emit change events only when an observed field changes. Keep customer watchlists and billing outside the collector; a separate projection can filter canonical records for each customer. Use the existing publisher and contracted server operations.

** Adversarial review

- A notice can disappear or be cancelled after the latest-active API response; absence from one page is not deletion evidence. Reconcile by notice ID and record an unknown state until a documented source response confirms status.
- Offset pagination can change while scanning. Use overlapping posted-date windows and stable notice IDs; repeated pages must be idempotent. Measure missed notices against a bounded independent sample.
- A deadline may carry a timezone or be missing. Preserve the source value and avoid fabricating an exact deadline in customer alerts.
- An awardee name may collide across entities. Relations require exact source identifiers or reviewed evidence; do not infer an incumbent from text similarity alone.
- Rate limits, API-key rotation, outage, and malformed records must produce bounded retries and visible terminal gaps, not silent success.
- Customer workspaces must receive only their authorized projection; a shared source cache must not leak private watchlists or contact data.

** Decision gate

Research approval is pending. This document recommends the GSA actor as the first design candidate, subject to an operator-selected product segment and at least five buyer interviews. It does not approve implementation or claim that a paid market exists.

* First Design Acceptance Criteria

1. A fixture scan with overlapping pages emits one canonical notice per stable source ID and preserves every changed observation.
2. Source snapshots, response errors, and every projected deadline alert have reproducible provenance.
3. Malformed inputs, cancellation, outage, and restart never advance a checkpoint past unprocessed pages.
4. A pinned-schema conformance test validates all emitted document variants.
5. A measured pilot reports alert precision, lateness, misses, duplicate rate, operator time, and customer willingness to pay without inventing revenue.
