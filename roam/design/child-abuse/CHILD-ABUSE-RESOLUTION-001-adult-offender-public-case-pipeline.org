* REVIEW Objective

Define the actors, capability gates, crawler adapters, quarantine boundary, and message contracts for severe child-abuse public-case research.

The architecture contains a real live public-source crawler. It also contains a deterministic synthetic retrieval adapter used for tests. The test adapter is not the crawler and must never be presented as the production retrieval implementation.

The pipeline may create evidence-backed records about publicly documented adult defendants. It must never identify child victims, child survivors, minor witnesses, or minor alleged offenders.

* REVIEW User Directive

The user explicitly directed:

- actors only;
- no AutoDig for this domain;
- do not expose child names;
- child-name exposure would abuse the child further;
- document the request as a durable project rule.

This directive is implemented by [[file:CHILD-ABUSE-POLICY-001-child-identity-firewall.org][CHILD-ABUSE-POLICY-001 Child Identity Firewall]]. The firewall supersedes weaker generic evidence-preservation behavior.

* REVIEW Architecture Versus Execution

This document defines the complete target architecture, including live crawling. Design approval does not itself start a crawl or grant network capability.

Two execution profiles exist:

1. =synthetic-design-test=
   - uses fixed synthetic fixtures;
   - has no network access;
   - proves actor contracts, quarantine, redaction, and export scanning.
2. =approved-live-retrieval=
   - uses the Live Public-Source Crawler;
   - requires an explicit capability grant and approved source policy;
   - sends every response directly into raw-content quarantine;
   - remains separate from AutoDig.

The default profile is =synthetic-design-test=. The live crawler is a first-class architectural component, not deferred hand-waving and not replaced by the synthetic adapter.

* REVIEW Hard Invariants

1. No AutoDig run, dataset, target queue, or monitoring job is used for this domain.
2. No child name may be used as a query term.
3. No real child identity may enter an actor request, response, log, prompt, fixture, filename, graph label, or published document.
4. Child identities remain prohibited even when a source has already made them public.
5. Only adults with a supported public legal role may become named targets.
6. A person whose adult status is unresolved is treated as a minor and cannot be named.
7. Adult-defendant and child-victim roles are separate; text proximity cannot establish either role.
8. Child records use case-local pseudonyms and cannot be linked across cases.
9. Raw fetched content is unavailable to normal actors until direct and indirect identifiers are removed.
10. Raw crawler responses are never indexed, embedded, graphed, logged, or exported.
11. Detailed sexual or medical narratives are removed unless indispensable to a legal element and approved for restricted use.
12. Every stage may abstain, reject, or stop.
13. Privacy failure overrides evidence confidence and blocks publication.
14. Legal status is represented exactly and temporally.
15. No actor may expand to relatives, schools, households, social accounts, obituaries, fundraisers, or associates.
16. The retrieval path must fail closed when capability, source class, adult role, or child-safety policy is unresolved.

* REVIEW Actor Contracts

** Operator Authorization Gate

Purpose: reject execution modes and capabilities not explicitly authorized.

Consumes:

- requested profile;
- requested operation;
- capability grant;
- project policy version.

Produces:

- authorized request envelope;
- denied-operation event.

Rules:

- =autodig= is always denied;
- =synthetic-design-test= cannot request network capability;
- =approved-live-retrieval= requires a valid scoped grant;
- denied requests never echo prohibited identifiers.

** Case Scope Gate

Purpose: restrict the pipeline to severe child-abuse public-case patterns involving a supported public adult legal action.

Produces:

- eligible branch;
- ineligible terminal result;
- unresolved classification.

Eligible classes include fatality, near fatality, serious bodily injury, permanent impairment, severe starvation, poisoning, burning, torture, medical neglect, and publicly charged sexual abuse represented without graphic victim detail.

Excluded classes include custody disputes, unsubstantiated referrals, minor injuries, school discipline, social-media accusations, family-court-only allegations, ordinary parenting disputes, and cases lacking public adult legal action.

** Child Identity Input Firewall

Purpose: prevent prohibited child identity from entering the run.

Rules:

- remove child names, initials, exact birth dates, addresses, schools, photographs, handles, and contacts;
- reject rather than guess when safe rewriting is impossible;
- never place rejected values in logs or error messages;
- allow an adult name only when the request supplies or establishes a supported adult public legal role;
- apply the same checks to attachment names, URL slugs, metadata, and operator notes.

** Source Request Policy Actor

Purpose: decide whether a proposed retrieval request is permitted and which adapter may execute it.

Consumes:

- execution profile;
- source class;
- proposed query or URL;
- known adult-role evidence;
- capability grant;
- source-policy version.

Produces:

- permit, rewrite, or deny decision;
- adapter selection;
- required redaction profile;
- crawl limits.

Rules:

- deny child-name and child-initial searches;
- deny reverse-family and associate expansion;
- deny school, social-account, obituary, and fundraiser searching;
- deny adult-name searches when no supported adult legal role exists;
- route =synthetic-design-test= only to the Synthetic Retrieval Adapter;
- route =approved-live-retrieval= only to the Live Public-Source Crawler;
- never silently downgrade a requested live run into synthetic output.

** Child-Safe Query Rewriter

Purpose: build useful public-record queries without child identifiers.

Allowed query features:

- month or date;
- county or state;
- public agency;
- severe outcome class;
- public charge, indictment, plea, verdict, sentence, dismissal, or appeal terms;
- adult candidate name after event-based discovery or supplied legal-role evidence.

Prohibited query features:

- child name or initials;
- exact child age or birth date;
- school, daycare, classroom, team, or club;
- home address;
- sibling, parent, or caregiver discovery derived from child identity;
- obituary or fundraiser terms;
- child social account or photograph.

** Retrieval Router

Purpose: select exactly one retrieval backend from the authorized profile.

Rules:

- synthetic and live results use the same retrieval-result schema;
- adapter selection is explicit and auditable;
- a missing or ambiguous profile is denied;
- the router cannot grant capabilities;
- the router cannot return raw content directly to downstream actors.

** Synthetic Retrieval Adapter

Purpose: provide deterministic source-shaped fixtures without network access or real people.

Consumes:

- permitted synthetic query;
- fixture identifier and version.

Produces:

- synthetic response body;
- synthetic source metadata;
- retrieval event;
- quarantine write request.

Rules:

- all adult names are obviously fictional;
- child names remain prohibited; use =[CHILD]= or adversarial placeholder tokens;
- no fixture copies a real case narrative;
- fixtures simulate redirects, PDFs, URL slugs, image captions, metadata, copied stories, and malformed content;
- one immutable output exists per fixture version.

** Live Public-Source Crawler

Purpose: retrieve approved public sources for an authorized live run.

Consumes:

- permitted child-safe query or URL;
- capability grant;
- allowed source classes;
- crawl budget;
- policy version.

Produces:

- retrieval metadata;
- response hash;
- restricted quarantine reference;
- crawl event without response-body content.

Supported adapters:

- court docket and opinion sources;
- prosecutor and attorney-general releases;
- police and sheriff releases;
- government reports and public registries;
- approved public web archives;
- approved news sources used for discovery or corroboration.

Rules:

- never search by child identity;
- fetch only public, policy-approved sources;
- enforce domain, redirect, depth, page, byte, and time budgets;
- send response bytes directly to quarantine before parsing;
- never publish response bodies to the message bus;
- record source URL, retrieval time, status, media type, hash, redirect chain, adapter, and grant identifier;
- preserve source provenance while stripping prohibited identifiers from all normal events;
- stop when a response or redirect leaves the approved source boundary;
- fail closed on login walls, unexpected authentication, source-policy conflict, or unverifiable content type.

** Crawler Network Sandbox

Purpose: contain untrusted network retrieval.

Rules:

- deny loopback, link-local, private, metadata-service, multicast, and reserved network ranges;
- resolve DNS inside the sandbox and re-check every redirect target;
- block unsupported schemes and local-file access;
- isolate browser state per request;
- do not persist cookies, credentials, or browser profiles unless a separately approved adapter requires them;
- apply decompression, archive, document, image, and response-size limits;
- perform MIME sniffing and reject type confusion;
- rate-limit by host and adapter;
- prevent unrestricted JavaScript callbacks, downloads, and child-process execution;
- emit only bounded metadata and the quarantine reference.

** Raw Content Quarantine

Purpose: isolate unredacted synthetic or live content from normal actors.

Consumes:

- synthetic retrieval result; or
- live crawler response stream.

Produces:

- restricted artifact reference;
- redaction task.

Rules:

- only the redaction boundary may read raw content;
- raw content is never indexed, embedded, logged, graphed, exported, or placed in a public repository;
- quarantine references are opaque, short-lived, and access-controlled;
- teardown deletes transient fixture content;
- live-retention policy is explicit, minimal, and auditable;
- a failed redaction or privacy scan deletes or seals the artifact according to incident policy.

** Child Identifier Redactor

Purpose: remove direct child identity from content and metadata.

Redaction categories:

- child name and initials;
- exact birth date and exact age;
- address and precise location;
- school, daycare, classroom, team, or club;
- child photograph, caption, alt text, and filename;
- social handle and contact details;
- sibling and minor-witness identity;
- quoted child statement;
- detailed medical or sexual narrative.

Outputs contain redacted text, redacted metadata, category counts, privacy warnings, and source-relative evidence locators that cannot reconstruct a prohibited value.

** Indirect Identification Detector

Purpose: detect combinations that could identify a child without naming them.

Rules:

- generalize exact ages into approved bands;
- generalize location to county or state;
- remove distinctive school, family, medical, and event details;
- reject when remaining facts make the child readily identifiable;
- never reconstruct a removed identity.

** Severe Harm Classifier

Purpose: classify the supported case outcome without determining guilt.

Rules:

- severity does not identify an offender;
- ambiguous severity yields unresolved;
- graphic detail is not retained merely to justify severity.

** Adult Status Verifier

Purpose: establish that a potential named target was at least eighteen at the event.

Rules:

- minor and unresolved decisions block naming;
- never infer adult status from appearance, occupation, parenthood, or marital status;
- use explicit age, an authoritative adult-record calculation, or a court statement that the person was tried as an adult;
- do not retain unnecessary exact birth dates.

** Adult Role Extractor

Purpose: identify the adult's exact public role.

Produces defendant, charged adult, convicted offender, nonoffending caregiver, witness, reporter, official, or ambiguous role with supporting evidence.

Rules:

- only a supported defendant or offender role proceeds;
- nonoffending caregivers and ambiguous roles remain unnamed;
- article proximity is not role evidence;
- multiple adults remain separate candidates.

** Legal Status Extractor

Purpose: preserve procedural status and lifecycle.

Produces arrest, charge, indictment, plea, verdict, sentence, acquittal, dismissal, appeal, correction, and contradiction events.

Rules:

- allegations remain allegations;
- arrest without a public charge does not authorize publication;
- dismissals, acquittals, appeals, and corrections supersede stale status;
- child identity never appears in event text.

** Case Evidence Normalizer

Purpose: convert redacted evidence into source, evidence, claim, legal-case, event, and adult-person candidates.

Rules:

- child person uses only a case-local pseudonym and age band;
- source excerpts use =[CHILD]=;
- no raw artifact path enters candidate documents;
- synthetic mode cannot write canonical documents;
- live mode remains noncanonical until both reviewers and the publication gate approve it.

** Adult Candidate Linker

Purpose: decide whether public adult references describe the same adult in the same case.

Rules:

- no child feature is a linkage key;
- no household graph is created;
- cross-case adult linkage is deferred;
- name alone is insufficient when several adults share a name.

** Independent Evidence Reviewer

Purpose: review adult role, case match, source independence, and legal status without inheriting linker conclusions.

Rules:

- reject copied-source pseudo-corroboration;
- check nonoffending-adult confusion;
- identify unsupported claims and contradictions;
- never waive child-privacy rules.

** Independent Privacy Reviewer

Purpose: independently inspect direct and indirect child identification across the entire proposed packet.

Rules:

- default to reject when uncertain;
- inspect text, metadata, identifiers, URLs, attachment names, graph labels, excerpts, and generated prose;
- require removal of analytically useful facts when privacy requires it;
- cannot be overridden by the evidence reviewer.

** Publication Policy Gate

Purpose: make the only decision about whether an adult record may be published.

Mandatory prerequisites:

- verified adult status;
- supported formal public legal role;
- evidence-review approval;
- privacy-review approval;
- zero known leakage;
- current legal lifecycle;
- successful export scan.

One failed or unresolved prerequisite blocks publication.

** Child-Safe StarIntel Writer

Purpose: create validated StarIntel documents only from approved sanitized candidates.

Future document pattern:

#+begin_src text
adult public defendant
  --defendant_in-->
public legal case
  --concerns-->
child-victim-01
#+end_src

Rules:

- child labels are case-local;
- no =resolved_as= relation targets a child;
- no child identity or stable cross-case identifier exists;
- synthetic mode writes only temporary test documents;
- canonical writes require a separate capability grant after publication approval.

** Export Leakage Scanner

Purpose: scan every serialized output surface.

The scanner covers JSON, JSONL, Org, HTML, EPUB, graph data, search indexes, logs, diagnostics, URLs, attachment titles, and generated summaries.

A missing scan is a failure. Any known child-identity leak fails the release.

** Audit and Retraction Actor

Purpose: apply corrections, legal-status changes, privacy incidents, retractions, and cleanup verification.

Rules:

- child identity never appears in incident reports;
- caches, indexes, generated pages, and graph projections are included in cleanup;
- dismissals and acquittals remain prominent;
- retraction does not silently erase provenance history.

* REVIEW Evaluation Gates

Synthetic validation must demonstrate:

- zero network calls;
- zero child-name queries;
- zero prohibited child identifiers in outputs;
- zero stable cross-case child identifiers;
- zero AutoDig paths;
- zero canonical writes;
- deterministic replay;
- complete export scanning.

Live crawler validation must additionally demonstrate:

- explicit capability enforcement;
- domain and redirect containment;
- SSRF protection;
- bounded crawling and downloads;
- quarantine-before-parse behavior;
- no raw-content event-bus payloads;
- source provenance and hashing;
- immediate stop on policy conflict;
- identical privacy gates for every adapter.

There is no acceptable child-identity leakage threshold above zero.

* REVIEW Acceptance Criteria

This design is ready for approval when:

- the architecture includes both the real crawler and the synthetic test adapter without conflating them;
- the Child Identity Firewall remains mandatory;
- live retrieval is capability-gated and disabled by default rather than absent from the design;
- AutoDig has no execution path;
- every retrieval backend writes first to quarantine;
- every child-data path passes through direct and indirect privacy review;
- adult naming requires verified adult status and formal public legal status;
- crawler security and privacy tests pass;
- CI validates Org-roam links and publication artifacts.

* Footnotes and Glossary

[fn:actor] Actor: A small independent software worker that owns a limited responsibility and communicates through structured messages.

[fn:privacy-firewall] Privacy firewall: Mandatory checks at several system boundaries that reject, remove, or generalize prohibited identifying information.

[fn:quarantine] Quarantine: A restricted temporary area where untrusted raw content is isolated until it has been sanitized.

[fn:indirect-identification] Indirect identification: Recognizing a person from a combination of details such as age, school, location, family structure, and medical facts even when their name is absent.

[fn:capability-grant] Capability grant: A short-lived authorization that permits one bounded operation under a named policy version and source scope.
