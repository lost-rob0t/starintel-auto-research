* Purpose

This project designs privacy-preserving actors for severe child-abuse public cases.

It is not an AutoDig dataset and does not authorize live case research. Child victims, survivors, minor witnesses, and minor alleged offenders are never named.

* User Directive

The controlling request is:

- actors only;
- no AutoDig for this domain;
- do not expose child names because doing so would harm the child further;
- document the request durably.

This directive is represented by the approved Child Identity Firewall.

* Approved Policy

- [[file:../../design/child-abuse/CHILD-ABUSE-POLICY-001-child-identity-firewall.org][CHILD-ABUSE-POLICY-001 Child Identity Firewall]]

Status: approved. It prohibits child names, child-name searches, stable child identifiers, cross-case child linkage, identifying metadata, raw public source artifacts, and named minor alleged offenders.

Status: review. It defines twenty-two bounded actors and gates for authorization, scope, child-identity removal, fake retrieval, quarantine, redaction, indirect-identification review, severe-harm classification, adult verification, role and legal-status extraction, evidence and privacy review, test writing, export scanning, and audit.

* Current Decisions

- No AutoDig run is permitted.
- No live source retrieval is permitted during this phase.
- No real case is selected or ingested.
- No child name is searched, stored, logged, graphed, embedded, or exported.
- Public availability of a child name does not make it permissible for StarIntel.
- Children receive random case-local pseudonyms only.
- Child records cannot be linked across cases.
- The only possible future named target is a verified adult with a supported public legal role.
- Unknown adult age fails closed.
- Arrest without confirmed public charge does not authorize publication.
- Privacy approval and evidence approval are independent requirements.
- Child-identity leakage tolerance is zero.

* Prohibited Work

- AutoDig;
- national or local case crawling;
- live web search;
- child-name queries;
- court scraping;
- archive recovery;
- government-feed monitoring;
- NCANDS, NIBRS, or NVSS ingestion;
- public-record request submission;
- real-case identity resolution;
- child identity resolution;
- family or associate graph expansion;
- publication of real adult or child names under this design phase.

2. Review the actor-only design.
3. Define protocol and privacy schemas.
4. Build synthetic fixtures with no real names.
5. Implement authorization and input firewalls.
6. Implement quarantine, redaction, and indirect-identification checks.
7. Implement fake retrieval.
8. Implement adult-age, role, and legal-status validators.
9. Implement independent evidence and privacy review.
10. Implement temporary child-safe document generation.
11. Scan every export surface.
12. Demonstrate zero child-identity leakage and zero live execution.
13. Return results to the user for review.
14. Do not implement live retrieval or AutoDig without a new explicit request.

* Footnotes and Glossary

[fn:case-local-pseudonym] Case-local pseudonym: A nonidentifying label valid only inside one case, designed to prevent records about a child from being connected across incidents or datasets.

[fn:legal-status] Legal status: The exact public procedural stage of a case, such as charged, indicted, pleaded, convicted, acquitted, dismissed, or sentenced.
