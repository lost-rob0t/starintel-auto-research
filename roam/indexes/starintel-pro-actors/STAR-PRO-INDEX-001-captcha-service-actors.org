* Purpose

This index connects the StarIntel[fn:starintel] CAPTCHA[fn:captcha] broker design to the separately deployed provider adapters in =starintel-pro-actors=.[fn:pro-actors] The broker remains generic infrastructure in =starintel-server=.[fn:star-server] Paid provider integrations remain optional professional actors and are never compiled into the server core.

The subsystem is restricted to operator-owned systems, accessibility workflows, quality assurance, and explicitly authorized automation. It is not a public solve relay and must reject requests without an approved target policy.

* Architecture Decision

- Broker, authorization, routing, budgets, deduplication, secret references, cancellation, and normalized events belong to =starintel-server=.
- Provider credentials, vendor-specific request formats, polling, error translation, and billing telemetry belong to =starintel-pro-actors=.
- Tokens remain ephemeral secrets. They are not StarIntel documents and are not persisted in RabbitMQ, CouchDB, logs, actor events, or research datasets.
- Provider adapters advertise capabilities dynamically. The broker must not assume that a vendor still supports hCaptcha merely because an old software-development kit contains an obsolete task type.

No CapSolver, Anti-Captcha, or CapMonster Cloud hCaptcha adapter is designed in this pass because their current public documentation does not advertise an hCaptcha token task. A future adapter requires fresh official documentation and a live contract test before its capability may be registered.

* Implementation Order

1. Approve the normalized broker protocol and policy model.
2. Implement the =starintel-server= broker with a fake provider actor.
3. Implement the NoneCap adapter as the reference adapter because its current interface is hCaptcha-specific and exposes cancellation and long polling.
4. Implement the NopeCHA adapter behind subscription-aware budget accounting.
5. Keep the 2Captcha adapter disabled by default until a live sandbox or support confirmation proves the current hCaptcha task contract.
6. Add provider health, circuit breaking, cost accounting, and explicit operator selection before enabling automatic fallback.

* Non-Goals

- CAPTCHA detection inside arbitrary web pages.
- Browser fingerprint fabrication.
- Automatic extraction of target-specific challenge internals.
- A public HTTP endpoint that accepts arbitrary URLs.
- Persisting challenge tokens or proxy credentials.
- Selecting a provider solely by lowest advertised price.

* Footnotes and Glossary

[fn:starintel] StarIntel: A local-first, actor-based platform that collects, normalizes, links, searches, and analyzes public or authorized data while preserving provenance.

[fn:captcha] CAPTCHA, or Completely Automated Public Turing test to tell Computers and Humans Apart: A challenge used by a service to distinguish ordinary human interaction from automated requests.

[fn:pro-actors] StarIntel Pro Actors: Optional paid-service, collection, and enrichment actors deployed separately from the generic StarIntel server.

[fn:star-server] StarIntel Server: The Common Lisp control, routing, persistence, search, and actor-hosting service at the center of StarIntel.
