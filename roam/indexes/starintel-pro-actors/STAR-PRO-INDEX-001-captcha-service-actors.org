* Scope

This index connects the provider-neutral StarIntel[fn:starintel] CAPTCHA[fn:captcha] subsystem across research, design, implementation, provider adapters, publication, and future operational work.

Core detection, authorization, exact matching, budgets, idempotency, secret references, cancellation, and downstream verification belong to =starintel-server=.[fn:star-server] External providers, local recognition engines, local browser workers, and manual-review actors belong to separately deployable =starintel-pro-actors= capabilities.[fn:pro-actors]

The subsystem is restricted to operator-owned systems, accessibility workflows, quality assurance, and explicitly authorized automation. It exposes no public raw solve endpoint.

* Architecture Decisions

- Challenge issuer, challenge family, challenge variant, integration version, solver actor, and external provider are independent axes.
- The catalog is open-world and preserves =custom= and =unknown= states until evidence supports a narrower classification.
- Detection belongs in =CaptchaDetectActor= and its versioned detector registry, not inside provider adapters.
- The broker performs authorization, purpose, disclosure, target-policy, allowlist, source-context, network, budget, idempotency, and exact-capability checks before selection.
- The source actor owns its browser, HTTP, mobile, or first-party runtime and applies results inside that context.
- Provider completion is not target acceptance; downstream verification records =accepted=, =rejected=, =expired=, =replaced=, or =inconclusive=.
- Tokens, cookies, answers, coordinates, selections, proofs, and interaction plans remain ephemeral secrets represented by opaque references.
- A capability contract can drift or fail independently without disabling unrelated provider capabilities.
- Paid, human-worker, cookie-bearing, proxy-bearing, authenticated-session, or same-network work requires explicit policy.

* Implementation Order

1. Approve the normalized descriptor, typed result union, capability state vocabulary, disclosure classes, and opaque result-reference contract.
2. Implement fake detector, broker, source actor, secret store, and solver actors against current =define-actor=, =register-actor=, =get-dest-actor=, =tell=, and =log-actor-event= interfaces.
3. Add exact eligibility tests, policy denials, budgets, duplicate delivery, ambiguous create, cancellation, expiration, one-read result, verification outcomes, drift, redaction, and shutdown tests.
4. Implement source-runtime application and verification with no broker-owned browser session.
5. Implement NoneCap only for fixture-backed hCaptcha capabilities.
6. Implement NopeCHA Token and Recognition adapters as separate capability surfaces.
7. Implement 2Captcha family-by-family; isolate any invalid hCaptcha contract from unrelated tasks.
8. Add local browser, local recognition, local audio, and manual-review actors.
9. Add Anti-Captcha, CapSolver, or CapMonster Cloud only to close measured exact-capability gaps.
10. Add operational monitoring, circuit breakers, accepted-result cost telemetry, and opt-in owned-system canaries.

* Required Test Coverage

The implementation must cover normalized families, unknown and custom challenges, exact capability matching, forbidden version and result-kind widening, source-session and network requirements, policy and disclosure denial, provider allowlists, exhausted budgets, health and concurrency, duplicate deliveries, ambiguous creation, cancellation, expiration, one-read results, detector evidence requests, multiple and conflicting candidates, all verification outcomes, bounded redetection, source actor failure, capability-local provider drift, redaction, and shutdown with active runs.

Continuous integration must use fakes and fixtures and must never invoke a paid provider. Live probes remain opt-in, credential-gated, cost-bounded, capability-specific, and restricted to operator-owned or explicitly authorized systems.

* Supersession and Duplicate Policy

- This file is the one canonical CAPTCHA index.
- STAR-PRO-RESEARCH-006 is the canonical cross-provider taxonomy and capability-state document.
- Provider-specific research and adapter designs retain their own stable IDs and must link back here.
- New research extends an existing canonical node or explicitly identifies a superseded replacement; agents must not create a second canonical CAPTCHA index or duplicate provider node.
- Legacy hCaptcha terminology in filenames is historical. Titles and current contents must state the broader role where the document has been generalized.

* Research Gaps

- Exact current Arkose, DataDome, Tencent, CapSolver, and CapMonster task fixtures remain incomplete.
- The repository-wide approval and changelog repair has not yet produced an observed full validation run.
- The complete generated site and every PlantUML block still require an observed current-head build.
- Current StarIntel actor runtime code examples require compilation or load validation against the checked-out =starintel-server= source.
- Target-branch publication must be verified after merge; a local or pull-request site build is not publication.

* Non-Goals

- Browser fingerprint fabrication.
- A public arbitrary-target solve endpoint.
- Automatic authorization based on challenge type.
- Persisting provider credentials, raw results, session cookies, proxy credentials, or authenticated browser material.
- Treating every anti-bot block as a CAPTCHA.
- Guessing an issuer when evidence is insufficient.
- Ranking by price before hard authorization, context, disclosure, exact-capability, and contract checks.

* Footnotes and Glossary

[fn:starintel] StarIntel: A local-first actor-based platform that collects, normalizes, links, searches, and analyzes authorized data while preserving provenance.

[fn:captcha] CAPTCHA: Completely Automated Public Turing test to tell Computers and Humans Apart; this index also covers adjacent browser, device, behavioral, proof-of-work, and Web Application Firewall challenges.

[fn:pro-actors] StarIntel Pro Actors: Separately deployable paid-service, browser, recognition, manual-review, and enrichment actors outside the generic server core.

[fn:star-server] StarIntel Server: The Common Lisp control, routing, persistence, authorization, search, and actor-hosting service.

- *Canonical document* — The single maintained source node for a subject; other nodes link to it or explicitly identify supersession.
- *Exact capability* — A solver contract matched on issuer, family, variant, version, required fields, result kind, source and network binding, execution class, disclosure class, and current contract state.
- *Opaque result reference* — A short-lived identifier that permits a bounded secret read without putting sensitive result material in an actor message or document.
