* Research Question

What evidence is available for adding dialect and regional-language analysis as a StarIntel enrichment capability when reusable dialect knowledge will live in =lost-rob0t/star-kb= and logical inference can use the existing =lost-rob0t/prolog-query-server= (PQS)?

This pass compares evidence relevant to three candidate families named by the operator: symbolic Prolog reasoning, StarLang integration, and learned/deep models. It also examines how StarIntel can self-source a higher-quality corpus instead of depending on one third-party dialect quiz dataset.

This document is deliberately research only. It does not select a concrete actor contract, source grammar, repository layout, API shape, model architecture, or implementation sequence. The operator subsequently selected *weights/salience* as the initial scoring research direction, so this revision records the evidence-backed consequences of that choice without turning them into an implementation specification.

* Operator Constraints Recorded for This Pass

- Reusable dialect knowledge is intended to live in =lost-rob0t/star-kb=.
- The existing Prolog query server is preferred over embedding a separate SWI-Prolog process inside each Common Lisp actor.
- StarLang and deep learning remain candidates worth researching rather than assumptions about the final implementation.
- The desired long-term corpus is larger than dialect alone: reusable facts and rules should be capable of serving many StarIntel actors.
- For the first dialect inference baseline, use *weights/salience* rather than treating every observation as equally informative.

* Verified Current Runtime Facts

** prolog-query-server

The current PQS repository describes CouchDB as the durable knowledge store and SWI-Prolog as the inference engine. Facts and rules are persisted as CouchDB documents, converted from a restricted JSON abstract syntax tree (AST), loaded into an isolated in-memory clause set for a named KB, and evaluated by a bounded meta-interpreter. The public expert-system surface includes query, explanation, reload, and knowledge inspection operations.

The runtime deliberately rejects raw executable Prolog and arbitrary predicate calls over HTTP. Persisted facts must be ground, rules use structured head/body terms, and inference is limited to stored clauses plus an allowlisted builtin surface. This is relevant to =star-kb= because readable source material cannot simply be treated as arbitrary code if it is eventually published into PQS.

PQS already supports immutable logical releases. Facts/rules may be associated with a named release, a single manifest selects the active release for a KB, staged releases can be queried explicitly before activation, and changing the manifest selects the new release atomically from the query runtime's perspective. Active non-legacy releases are immutable; rollback is performed by reactivating an earlier release.

PQS also already enforces hard resource ceilings around loading, inference, proof generation, and HTTP request size. Current documented defaults include a 5-second query ceiling, maximum depth 32, maximum 100 solutions, one million inference steps, 10,000 loaded knowledge documents, and 16 MiB serialized KB size per loaded KB/release. These are current runtime facts, not claims that those limits are sufficient for a future dialect corpus; corpus scale must be measured against them.

The current resource documentation also exposes asynchronous queries, cooperative cancellation, stable resource-exhaustion errors, query IDs, and bounded proof output. These capabilities make PQS suitable for empirical evaluation as a shared inference runtime.

Current source inspection answers one important concurrency question: =query_kb/4= obtains a mutex keyed by KB and holds it across release resolution, snapshot refresh/synchronization, and =expert_system:run_query/4=. Same-KB query execution is therefore serialized in the current implementation. This is an observed implementation fact, not a benchmark result.

PQS's current safe builtin surface includes =calc/2=, arithmetic addition/subtraction/multiplication/division/min/max/absolute value, numeric comparisons, and type/shape predicates. That is enough evidence that numeric weights can participate in bounded stored-rule inference. It does not establish that the present rule language has the ideal aggregate primitive for arbitrary evidence-vector summation; that remains an implementation-design question.

** star-kb

The =lost-rob0t/star-kb= repository exists and currently carries the RAGE research/design/implementation control-plane skeleton. The current repository README describes the Org tree as its source of truth and separates research, design, implementation, indexes, scripts, and tests. A default-branch code search for =dialect= returned no current implementation result during this pass. Therefore this pass treats the dialect corpus as not yet implemented rather than inferring a hidden product contract.

** StarLang

The current =lost-rob0t/star-lang= repository is a Common-Lisp-only compiler and durable actor runtime. Its declared systems include generic HTTP and external-process adapter ports as well as actor protocol, mailbox, supervision, journal, capability, artifact, canonical JSON, and runtime components. The repository explicitly states that current implementation is not yet fully conformant with its approved research sequence. This supports researching StarLang as a future consumer/orchestration path, but does not prove a dialect-specific StarLang integration today.

* Dialect Quiz and Survey Methodology Findings

** MyDialect / Harvard-derived baseline

The current MyDialect site offers 24-, 60-, 122-, and 148-question modes. Its full mode states that 122 questions come from the original Harvard Dialect Survey. The site describes its core state score as the average, across the user's answers, of the probability that a resident of a state gave that same answer. It then applies Gaussian kernel smoothing to state scores to produce the continuous map. This establishes that the visible product is fundamentally a survey-response similarity model plus map smoothing rather than evidence of a deep neural dialect classifier.

MyDialect currently offers a downloadable state/question/answer percentage table covering 51 jurisdictions and 148 questions. The site attributes the Harvard-derived portion to Bert Vaux and Scott Golder under =CC BY-NC-SA 3.0=. The noncommercial/share-alike terms mean that this material should not be silently treated as an unrestricted StarIntel production corpus. Whether a particular deployment or derived artifact complies is a licensing question that requires explicit review or separate permission.

The Harvard-style state aggregation is useful as a baseline but has an obvious resolution limit: a state is not a dialect. Regional speech may cross state boundaries, differ within states, and change through mobility and social contact. The map's smoothing improves display continuity but does not create more underlying geographic observations.

MyDialect's =what gave you away= behavior is also relevant to salience: it highlights choices that are far more common than nationwide. That is a simple example of presenting feature discriminativeness rather than treating all responses as equally explanatory.

** Geographic resolution evidence

DialectGram research explicitly addresses dialectal variation at multiple geographic resolutions and argues against requiring a single predefined regional resolution. Its method learns dialect-sensitive word representations from geographically associated text and permits analysis at a chosen resolution after training. This is useful evidence that a future StarIntel corpus should preserve the finest defensible geographic labels available instead of collapsing everything permanently to states.

Older social-media geolocation work by Han, Cook, and Baldwin shows that location-indicative lexical features can predict geographic location from text. Their information-gain-ratio feature selection outperformed the compared feature-selection/geolocation baselines and their confidence experiments showed an accuracy-versus-coverage tradeoff when the model abstains on low-confidence cases. This is direct evidence for a salience-weighted baseline and explicit abstention rather than equal-weight scoring.

That work is still geolocation research, not proof that every location-indicative feature is dialectal. Named places and local entities can be highly geographically informative while saying little about dialect acquisition.

* Label Semantics and Mobility Findings

The strongest recurring problem in the available data is label meaning.

The Ohio State Geographic Mobility and Lexical Processing project records all places participants lived, how long they lived there, their age when they lived there, parents' and close contacts' origins, visits, self-identified dialect, and regional identification. Its published specific-dialect score gives two points for residence in a region before age 18 and one point each for parental origin, close-contact origin, residence after 18, current residence, any visit, recurring visits, self-identified dialect, and regional identification. The exact Ohio State score is not adopted here, but it is direct evidence that acquisition/exposure variables need differentiated weights.

Therefore at least four labels that may look superficially equivalent must be kept conceptually distinct during later design work:

- where text/audio was produced or posted;
- current residence;
- childhood/adolescent residence and other acquisition-period exposure;
- self-identified dialect or regional affiliation.

A geotagged post is strong evidence for where that post was associated geographically under the source's collection method. It is only weak/indirect evidence for where the speaker learned their dialect unless additional history is available.

Another distinction is between linguistic evidence and geographic context. A regional lexical form can be dialect evidence; a named local business, sports team, road, or place mention can instead be contextual geographic evidence. Both can be useful enrichment signals, but conflating them would make a claimed dialect explanation misleading.

* Self-Sourcing Findings

The available research strongly supports collecting more than a single state field if StarIntel builds a first-party corpus. Useful research dimensions include residential history with ages/durations, current residence, self-described regional/dialect background, and provenance for each response or recording. These dimensions would allow later research to test which history fields are predictive rather than baking one assumption into the labels.

A first-party survey can separately collect structured dialect choices and optional free-form language/audio. Structured questions provide highly interpretable feature frequencies; free-form language provides training/evaluation material for models that operate on ordinary posts or transcripts.

For data minimization, the evidence favors age-banded residence history over exact addresses or a single current-location field. A reasonable research priority is: acquisition-period residence history has highest exposure salience; current/post-18 residence and self-identification are useful but conceptually separate; caregiver/parent origin is useful optional context; casual visits should carry substantially less weight than residence. Exact field names and numeric weights remain design/calibration work.

Speaker-level separation matters for learned-model evaluation. If multiple samples from one participant are split across training and test data, a model can partially recognize speaker-specific patterns rather than demonstrating generalization to unseen speakers. A 2026 VarDial study found dialect-identification models highly affected by speaker bias when comparing speaker-dependent with speaker-independent partitions. Speaker-disjoint evaluation is therefore not merely a stylistic preference.

* Symbolic Prolog and Weighted-Salience Findings

The dialect problem contains many pieces that map naturally to symbolic facts and rules: lexical variants, regional associations, source reliability, provenance, temporal validity, language variety, contradictions, and explanation of which observations supported a candidate region. PQS already returns proof/source information for deterministic inference, so an explainable symbolic baseline is technically plausible without adding another Prolog server.

The operator selected *weights/salience* for the first scoring direction. The research supports that choice more strongly than an equal-response average. Han, Cook, and Baldwin found information-gain-ratio selection of location-indicative words improved geolocation performance, while MyDialect itself exposes a simple nationwide-versus-regional discriminativeness concept in its giveaway display. Ohio State independently demonstrates differentiated exposure weighting.

For research purposes, the useful decomposition is:

#+begin_src text
regional association   direction and strength of feature -> region evidence
feature salience       how discriminative the feature is across regions
source reliability     how trustworthy the observation/source is
exposure relevance     how strongly the observation represents acquisition/exposure
redundancy control     prevent correlated copies of one signal from dominating
#+end_src

A conceptual weighted-evidence score is therefore better supported than equal counting:

#+begin_src text
score(region) = sum(signed-association
                    * feature-salience
                    * source-reliability
                    * exposure-relevance)
                - redundancy/conflict penalties
#+end_src

This is a research model, not a frozen API or numeric formula. Salience should preferably be estimated empirically from corpus distributions using measures such as information gain ratio or smoothed regional-versus-background log odds rather than hand-assigned because a word merely feels regional. Human-curated weights remain useful for provenance/reliability and as priors where data are sparse.

A weighted score is not automatically a probability. If a consumer reports probability-like confidence, the mapping from score/evidence mass to confidence must be calibrated on held-out data.

The current PQS builtins can represent and manipulate numeric weights, but this pass does not decide whether arbitrary accumulation belongs entirely inside PQS rules, in a bounded safe aggregate builtin, or in a caller-side calibrated scorer. That is design work.

* Probabilistic and Neural-Symbolic Findings

There are mature Prolog-related probabilistic systems worth comparing if the weighted-salience baseline later demonstrates a concrete limitation:

- =cplint= is an SWI-Prolog pack providing inference and learning for probabilistic logic programs.
- ProbLog is a probabilistic logic programming language/toolbox supporting probabilistic facts, inference, learning, and related tasks.
- DeepProbLog extends ProbLog with neural predicates whose probabilities are parameterized by neural networks.

None of those systems is required to express the first weighted-salience baseline, and none is a drop-in PQS extension. PQS deliberately has its own safe stored-clause interpreter and restricted builtin surface. Research should therefore treat probabilistic logic as an escalation path: compare it only if held-out evidence shows that calibrated weighted salience is materially inadequate, especially for correlated/dependent evidence or joint neural-symbolic reasoning.

If that escalation occurs, the least disruptive experiment is an external isolated scorer/runtime against the same benchmark rather than modifying PQS first. ProbLog/cplint are the relevant probabilistic-symbolic comparisons; DeepProbLog becomes specifically relevant when a learned neural predicate is actually part of the hypothesis being tested.

* Learned-Model Findings

Natural-language dialect enrichment is a different problem from answering a structured quiz. A learned text model can potentially exploit combinations of lexical, syntactic, semantic, and contextual features that were never manually encoded as survey questions. DialectGram demonstrates one research path for learning geographic lexical/sense variation from geotagged text; location-indicative-word work demonstrates another more explicit feature-selection path.

Speech adds phonetic/phonological evidence unavailable from text. Common Voice, CORAAL, and the Speech Accent Archive demonstrate three very different speech regimes: large scripted crowdsourced speech, spontaneous sociolinguistic conversation, and a fixed elicitation passage. Their differences are evidence that a future speech benchmark must account for domain mismatch rather than treating all audio as equivalent.

There is no defensible universal minimum input length. Early-guessing dialect-identification research reports no absolute token-length point at which shortened text becomes reliably sufficient. ADI17 deliberately evaluates short speech under 5 seconds, medium speech from 5 to 20 seconds, and long speech over 20 seconds; separate Ao dialect work reports useful but far from perfect automatic performance on 3-second utterances. The research implication is to gate inference on accumulated *salient evidence* and calibrated confidence rather than a hard universal word-count or seconds threshold.

A single highly distinctive feature can be useful evidence. It should not automatically become a precise origin claim. Conversely, a long input containing no discriminative features should still be allowed to abstain.

* StarLang Findings

StarLang already has generic HTTP and external-process adapter systems, while its normalized IR is intended to remain runtime-neutral. That means a later StarLang actor could in principle consume an external knowledge/inference service without embedding Prolog syntax into the StarLang language core. This is a compatibility observation only. No dialect-specific StarLang syntax or adapter contract was designed in this pass.

Because StarLang currently reports that it is not yet fully conformant with its approved research sequence, a dialect project should not use current implementation details as justification for freezing a permanent dialect-specific language feature before the runtime boundary is stable.

* Contradictions and Risks

- *Dialect versus geolocation*: many public corpora label where content was posted, while the requested capability concerns language variety. Treating the two labels as identical would overstate evidence.
- *State-level data versus real dialect regions*: convenient administrative boundaries do not necessarily match linguistic boundaries or within-state variation.
- *Reproducibility versus social-media hydration*: tweet-ID corpora can become less reproducible as posts are deleted, accounts disappear, or platform access rules change.
- *Readable Prolog versus PQS safety*: human-friendly Prolog source is attractive for =star-kb=, while PQS correctly rejects arbitrary executable Prolog over its runtime API. Any future bridge needs explicit validation rather than direct consultation.
- *Huge reusable corpus versus current PQS ceilings*: current default loaded-KB limits are 10,000 documents / 16 MiB; suitability for a large StarIntel corpus still requires measurement.
- *Shared KB versus run observations*: continuously generated actor observations can dwarf reviewed reusable knowledge and can contain errors. Automatically promoting observations into canonical knowledge risks feedback loops and corpus contamination.
- *Interpretability versus model capability*: symbolic rules provide clear proof paths; learned models may capture subtler patterns but require additional explanation/calibration evidence.
- *License versus data usefulness*: several high-value dialect corpora use noncommercial/share-alike licenses or contractual restrictions. Research usefulness does not equal unrestricted redistribution or production use.
- *Sampling bias*: web surveys, social media, scripted crowdsourcing, and sociolinguistic interview corpora all sample different populations and communication styles. Accuracy measured on one source may not transfer to StarIntel inputs.
- *Correlated salience*: several words/features can arise from one underlying construction or copied text; naïvely summing every hit can create false confidence. Redundancy/dependence needs explicit evaluation.

* Answers to the Previously Open Questions

** 1. Geographic ontology

*Answer:* preserve *multiple simultaneous resolutions*. Store the finest defensible geographic observation, preferably coordinates or a locality/metro when the source actually supports that precision, and map it to both administrative hierarchy and independently defined linguistic regions. Do not permanently collapse dialect evidence to states. DialectGram's central result is that dialect variation appears at multiple resolutions, while the Ohio State exposure work uses dialect regions whose boundaries can require latitude/longitude inside states. The research therefore rejects a single-resolution ontology as the default.

** 2. First-party survey/history fields

*Answer:* collect age-banded residence/exposure history rather than exact addresses. Highest-salience history is where the participant lived during acquisition/childhood/adolescence and for how long. Also retain current/post-18 residence and self-identified dialect/region as separate fields. Caregiver/parent origins can be optional supporting exposure. Casual and recurring travel can be optional lower-salience evidence. This captures the dimensions supported by the Ohio State questionnaire while avoiding unnecessary street-level location collection.

** 3. Harvard/Vaux/Golder respondent-level data

*Answer:* do not make it a dependency. No current public respondent-level download with clear production-compatible terms was located in this pass. There is public evidence that Bert Vaux directly shared a 47,472-respondent dataset with an academic instructor, showing that respondent-level data existed and may be obtainable by request, but that is not a public redistribution grant. If StarIntel wants it, obtain the data and intended-use terms directly from the rights/data holder. Until then, use public state aggregates only as license-constrained research/validation material.

** 4. Which source licenses permit raw material, aggregates, embeddings, or research-only use?

*Answer:* treat this as source-specific rather than assuming derivation removes obligations.

- MyDialect/Harvard-derived data: =CC BY-NC-SA 3.0= according to MyDialect; keep it in a restricted research path unless separate permission resolves intended production use.
- CORAAL: public corpus is =CC BY-NC-SA 4.0=; the CORAAL guide states that some components have additional licensing paths, including commercial licensing. Do not treat the public corpus as unrestricted production material.
- Common Voice: dataset copyright license is =CC0-1.0=, but current Common Voice/MDC terms prohibit speaker identification and prohibit rehosting/resharing the dataset; some curated subsets add further use restrictions. Use must satisfy both the public-domain dedication and current access/usage terms.
- Geo-Twitter2019: the reviewed repository exposes tweet IDs and says they may be crawled to reproduce the research, but no root =LICENSE= file was present. That does not establish unrestricted rights to redistribute repository code, hydrated tweet text, or derived artifacts. Preserve tweet-ID/source provenance and review platform/content rights independently.
- Speech Accent Archive: public mirrors report noncommercial/share-alike licensing, but this pass did not establish one unambiguous current official redistribution statement. Treat as restricted until confirmed.
- First-party StarIntel data: StarIntel can choose the grant/terms, but participant consent and privacy constraints must be established before collection and publication.

Derived salience tables or embeddings are not presumed license-free merely because they are transformed. Exact derivative-work consequences need source-specific legal/terms review.

** 5. PQS throughput and memory at 10^3, 10^4, and larger clause counts

*Answer:* the current source establishes the capacity envelope but not measured latency/RSS. At default limits, 1,000 documents are below the 10,000-document ceiling and can occupy at most about 16 KiB serialized per document on average before the 16 MiB KB byte ceiling is hit. At 10,000 documents, the average must be roughly 1.6 KiB or less to remain under 16 MiB. More than 10,000 loaded knowledge documents is rejected at defaults. Actual load time, resident memory, inference latency, and throughput are not inferable from the source and must be benchmarked. That measurement is a design-validation requirement, not an unanswered architecture choice.

** 6. Same-KB locking under concurrent enrichment

*Answer:* yes, the current implementation is structurally a same-KB serialization point. =query_kb/4= holds the per-KB mutex while resolving the release, ensuring the snapshot, and running inference. A rough throughput ceiling for one hot KB is therefore approximately the reciprocal of average mutex-held query time: e.g. 50 ms average work implies roughly 20 serialized queries/s before queueing effects, while 200 ms implies roughly 5/s. Those numbers are illustrative, not benchmarks. Different KB mutexes can permit independent lanes; a shared dialect bundle needs a concurrency benchmark before scale claims.

** 7. Weighted symbolic/statistical baseline versus probabilistic logic

*Answer:* use the weighted-salience baseline first. Equal-answer averaging throws away discriminative strength. Empirically derived feature salience, signed regional association, source reliability, exposure relevance, and redundancy/conflict penalties give a strong interpretable baseline while remaining compatible with the current PQS model. Information-gain-ratio results in location-indicative-word research support this direction. Probabilistic logic is not justified as a prerequisite.

** 8. If probabilistic logic becomes useful, what should be compared?

*Answer:* compare it only against the frozen weighted-salience benchmark. Start with an *external isolated* ProbLog or cplint experiment so PQS safety/runtime semantics are not changed to answer a research question. DeepProbLog belongs in the comparison only when the hypothesis includes neural predicates or jointly learned perceptual features. If an ordinary calibrated external scorer matches or beats probabilistic logic, keep the simpler system.

** 9. Uncertainty and abstention

*Answer:* evaluate *accuracy as a function of coverage*, not only forced top-1 accuracy. A candidate should be allowed to abstain when total independent salience/evidence mass is low, the leading candidates are too close, evidence classes conflict, or calibration predicts high error. Han et al. directly report better geolocation performance on more confident subsets, supporting this selective-prediction approach. Future benchmark metrics should include calibration error/Brier or log loss for probability-like outputs, top-1/top-k accuracy at the relevant geographic resolution, and selective risk/accuracy-versus-coverage curves. Threshold values must be learned on held-out data rather than guessed.

** 10. Linguistic versus named-entity/contextual geographic evidence

*Answer:* keep them as separate evidence classes all the way through scoring and explanation. Linguistic features can affect the dialect score. Named places, local brands, sports teams, roads, event names, account metadata, and similar clues belong to a separate contextual-geography channel. A later fused enrichment result may show both channels, but the explanation must expose separate subtotals/provenance so a local entity mention is never mislabeled as a dialect feature.

** 11. Minimum free-form text or speech

*Answer:* there is no universal minimum. Research on early dialect identification reports no absolute token-length threshold, and speech studies demonstrate usable but variable signal in very short segments, including sub-5-second evaluation regimes and 3-second experiments. Use a minimum *salient-evidence mass* plus calibration/abstention rule, not a hard global word or duration count. Length remains a useful covariate because more material creates more chances to observe discriminative features, but long non-salient input should still abstain.

** 12. Benchmark split for genuine generalization

*Answer:* speaker-disjoint is mandatory whenever speaker identity is available. Add geographic holdout so nearby or identical localities cannot leak region-specific vocabulary into both train and test, source/domain holdout so one platform/corpus style is not memorized, and time holdout where longitudinal data exists to expose concept drift. The 2026 VarDial speaker-bias study directly supports speaker-independent evaluation. The benchmark should report performance separately by resolution, source/domain, amount of salient evidence, and mobility/exposure complexity rather than only one global score.

** 13. Consent, deletion, retention, and publication for a first-party corpus

*Answer:* use purpose-separated consent and default to publishing derived aggregate knowledge rather than raw participant material. Residence/exposure fields should avoid exact addresses unless a research need later proves them necessary. Contact/account identifiers should be stored separately from corpus IDs. Text/audio contribution consent, model-training use, and public redistribution should be separate choices rather than one bundled permission.

Raw speech deserves stricter handling because it can remain identifying even after obvious metadata is removed. Before any irreversible/open publication, contributors must be told that third-party copies cannot reliably be clawed back. While data remains controlled by StarIntel, provide a deletion path keyed through a separate participant mapping; remove that linkage only when the applicable deletion window has ended. Define a finite raw-data retention period and re-review before extension. Longer retention of non-identifying aggregate salience/frequency statistics is easier to justify than indefinite retention of raw voice or free-form text. Common Voice's current privacy/terms model is useful evidence here: demographics are optional, account identifiers are not publicly exposed, and its ecosystem explicitly has to manage contributor deletion against released dataset versions.

* Remaining Empirical/Permission Checks

The conceptual questions above are answered well enough to inform a later design gate. What remains is measurement or permission rather than unresolved architecture:

- benchmark PQS load time, RSS, inference latency, proof size, and concurrent same-KB throughput at realistic weighted-dialect clause shapes;
- measure weighted-salience calibration and selective accuracy/coverage on speaker-disjoint, geographic-holdout, source-holdout, and time-holdout data;
- learn actual salience values and redundancy penalties from first-party/compatible corpora rather than hard-coding them from intuition;
- determine per-source production rights for any non-first-party material before promoting derived values into unrestricted =star-kb= bundles;
- contact the Harvard/Vaux/Golder rights/data holder if respondent-level HDS data is still desired;
- measure the evidence-mass thresholds at which text and speech should abstain.

These are empirical or permission gates. They do not require another conceptual architecture decision before design begins, but the research conclusion still requires operator approval.

* Research Conclusion

The follow-up evidence answers the prior conceptual open questions strongly enough to make the *weighted-salience PQS baseline* the research-supported first path for a future dialect design. That does not mean every final numeric weight or threshold is known: feature salience, confidence calibration, redundancy penalties, minimum evidence mass, and PQS scale behavior must be measured.

The strongest verified foundation already present in the StarIntel ecosystem is PQS for bounded, auditable reusable symbolic inference. MyDialect remains a useful interpretable survey baseline but its Harvard-derived data are license-constrained and state-aggregated. Geo-tagged social text demonstrates scalable geographic language signal but has weaker dialect-acquisition labels. Speech corpora provide additional phonetic evidence but differ substantially in style, license, and terms. Mobility research shows that residential/exposure history is materially richer than current location alone.

Probabilistic and neural-symbolic systems remain credible experimental escalations, not prerequisites. The evidence now favors first testing empirically derived feature salience and explicit evidence weights, with abstention/calibration, before adding cplint/ProbLog/DeepProbLog complexity.

The next gate is *operator review of this research*. Dialect-specific design remains =NOT STARTED=. No design file was created or modified and no implementation in =lost-rob0t/star-kb=, =starintel-server=, =prolog-query-server=, or =star-lang= is authorized by this document.

* Footnotes and Glossary

- *Dialect* :: A language variety associated with a community or population and characterized by patterns in vocabulary, grammar, pronunciation, discourse, or other linguistic features; it is not identical to an administrative region.
- *Dialect acquisition / exposure* :: The history of places, people, and language varieties that shaped a speaker's linguistic experience; current residence is only one possible component.
- *PQS* :: =prolog-query-server=, the existing CouchDB-backed SWI-Prolog expert-system runtime.
- *KB* :: Knowledge base, a named collection of facts and rules.
- *AST* :: Abstract syntax tree; here, the restricted structured JSON representation PQS accepts instead of arbitrary executable Prolog source.
- *Ground fact* :: A fact containing no logical variables.
- *Meta-interpreter* :: A Prolog program that interprets a restricted representation of facts/rules instead of directly executing arbitrary stored source code.
- *Release* :: An immutable logical version of a PQS knowledge base selected by an active-release manifest or explicitly pinned by a query.
- *Provenance* :: Evidence describing where a fact, rule, observation, model result, or proof came from and which source/version produced it.
- *Weight* :: A numeric multiplier representing the relevance/reliability of an evidence item or evidence source. It is not automatically a probability.
- *Salience* :: The discriminative strength of a feature for distinguishing regions or varieties. Prefer corpus-derived salience over intuition when data is sufficient.
- *Signed association* :: Evidence strength with direction: a feature may support one region while contradicting another.
- *Calibration* :: Agreement between reported confidence/probability and empirical outcome frequency; a 0.8 prediction should mean something measurable rather than merely being a score.
- *Abstention* :: Returning insufficient evidence instead of forcing a region prediction when the available signal is weak or conflicting.
- *Selective prediction* :: Evaluating accuracy/risk as a function of the fraction of cases on which the system chooses to make a prediction.
- *Evidence mass* :: The amount of sufficiently independent, weighted salient evidence available for a candidate; distinct from raw token count or audio duration.
- *Geotagged corpus* :: Text or speech associated with a geographic label. The label describes the collection geography and does not automatically establish dialect-acquisition origin.
- *Speaker-disjoint split* :: Evaluation where the same speaker cannot appear in both training and test sets.
- *Geographic holdout* :: Evaluation where selected geographic areas are excluded from training and used only for testing, reducing direct local memorization.
- *Neural-symbolic* :: A system combining learned neural components with explicit symbolic/probabilistic logic, such as DeepProbLog's neural predicates.
- *Noncommercial/share-alike* :: License conditions that can restrict commercial use and require derivatives to be distributed under compatible terms; exact obligations depend on the source license and use.
