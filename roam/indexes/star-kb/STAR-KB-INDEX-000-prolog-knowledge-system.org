* Scope

This index tracks the proposed StarIntel shared symbolic knowledge system: a source-controlled reusable corpus of restricted Prolog facts/rules, deterministic bundle publication into =lost-rob0t/prolog-query-server=, actor consumption through the query-server HTTP expert-system API, and dialect enrichment as the first reference consumer.

It does not make =prolog-rlm= the knowledge authority, does not make Git the runtime database, and does not move run/case evidence into the canonical corpus automatically.

* Implementation Order

After explicit design approval:

1. Create =star-kb= and its repository-wide agent/build policy.
2. Lock the restricted source-Prolog profile and provenance/source schemas.
3. Implement deterministic module and bundle compilation to the existing query-server safe JSON AST.
4. Prove a tiny =star.core.test= bundle against a test CouchDB/query-server deployment.
5. Reuse query-server staged releases, static analysis, pinned queries, proof trees, activation, rollback, conflict handling, and authentication rather than reimplementing them.
6. Add the generic Common Lisp query-server client to StarIntel server.
7. Create =star.dialect.en-us= as the first real shared bundle.
8. Add =dialect-enricher= as the first real actor consumer.
9. Begin first-party dialect survey/corpus acquisition with dialect-acquisition geography and respondent-level evaluation splits.
10. Benchmark learned-model evidence and probabilistic-logic options only after the symbolic baseline is measurable.
11. Add StarLang adapter integration after the generic query contract is stable.

* Known Research Gaps

- exact grammar for the restricted source-Prolog authoring profile;
- deterministic normalization/source-span strategy for clause identities;
- source/license policy for mixed-license bundles;
- calibrated semantics for dialect scores;
- first-party survey consent, retention, deletion, and publication rules;
- maximum bundle size before publication-time dependency flattening is inefficient;
- whether large requests require query-scoped ephemeral evidence contexts;
- whether safe tabled execution or probabilistic logic merits a runtime extension;
- compatibility/version-negotiation contract for StarLang and other future clients.

These gaps do not justify creating a parallel query server. They are bounded follow-up research/design questions around the existing runtime.

* First Reference Bundle

Candidate bundle:

#+begin_src text
star.dialect.en-us
  <- core.provenance
  <- core.confidence
  <- geography.core
  <- geography.us
  <- dialect.core
  <- dialect.en-us.lexical
  <- dialect.en-us.syntax
  <- dialect.en-us.scoring
#+end_src

The first actor output must preserve separate evidence classes for linguistic features, contextual geographic clues, explicit named-place/entity clues, and later learned-model scores. It returns candidate regions and explanation/provenance; it does not claim that dialect evidence proves a person's exact location.

* Footnotes and Glossary

[fn:canonical] *Canonical knowledge*: reviewed reusable knowledge intended to be shared across actors and releases, distinct from case/run observations.

[fn:runtime] *Knowledge runtime*: =prolog-query-server= plus its CouchDB database and active release manifests.

[fn:bundle] *Bundle*: a versioned dependency closure of source knowledge modules compiled into one query-server knowledge-base release in the proposed v1 architecture.

[fn:aradr] *ARADR pass*: the repository's research/design workflow for producing durable reviewable research and candidate architecture artifacts without silently treating implementation or lifecycle state as human approval.
