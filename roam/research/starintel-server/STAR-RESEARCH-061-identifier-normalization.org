** Hard empirical findings (probe-backed)

1. *Soft-404 traps*: TikTok, Twitch, and t.me return HTTP 200 for nonexistent handles. HTTP status alone must never drive existence assertions; require embedded-ID/API corroboration.
2. *YouTube oEmbed* rejects /@handle URLs (404 at all casings). Resolve handles via page rel=canonical to /channel/UC... or Data API channels.list?forHandle=. First channelId in page JSON may be a featured channel — use the canonical link element.
3. *Unauthenticated resolution works (2026-09-08)*: GitHub /users/<login>, Mastodon /api/v1/accounts/lookup, Bluesky resolveHandle + plc.directory, YouTube page scrape. Requires credentials: Reddit (403 on datacenter IP), X (error 215 unauth), Twitch Helix, IG/FB Graph, TikTok Display API.
4. *Case-insensitive resolution verified live*: YouTube, X, Instagram, TikTok, GitHub (canonical casing returned), Mastodon (canonical casing returned), Bluesky resolveHandle, t.me.

** Ingest implications for starintel-server#146

1. Key equality and IDs on provider-issued immutable identifiers, never handles. Reddit is the documented exception: username is lifetime identity; preserve original casing; never lowercase-fold Reddit usernames at storage.
2. Alias sets: store (platform, canonical_id, raw_handle, canonical_handle_form, first_seen, last_seen, source) with provenance on every alias row. Handle drift/recycling on X/GitHub/Telegram/Bluesky makes historical alias retention mandatory.
3. Layered normalization: (a) syntactic marker stripping (@, u/, r/) never enters canonical equality; (b) case folding only where verified case-insensitive AND ASCII; (c) NFC for Unicode display strings; ASCII-only username spaces make NFC a no-op there; Unicode rules for YouTube/Reddit/IG/TikTok remain UNVERIFIED — do not fold, key on IDs.
4. Normalized-username equality must never auto-merge two accounts; auto-merge may bind only immutable provider IDs, with corroboration for recycled-handle platforms.
5. Record normalization_profile and normalization_version per observation so policy changes never silently rewrite historical canonical IDs.

** Contract split evaluation (draft position)

- =starintel-doc/spec= owns the semantic contract: fields (platform, canonical_id, canonical_username, raw_username, normalization_profile, normalization_version), equality semantics, alias/provenance record shape.
- =starintel-server ingest= applies normalization before canonical ID construction/dedupe/index/routing; pure function over (platform, raw, profile) -> {canonical_id, canonical_username, raw preserved, versions}.
- =collectors= preserve raw provider spelling and stable provider IDs; no collector-local normalization logic.
- Normalization actor is Prolog-first: the persistent SWI-Prolog session owns the normalization logic itself — platform rules, equality semantics, and normalization policy are expressed as Prolog rules/facts inside the supervised actor, backed by the in-progress Prolog actor library. The CL/Lisp side supervises, feeds observations, and applies results; it does not reimplement normalization in a second language.
- Platform policy tables (sigils, case rules, charsets, folding profiles) are Prolog facts/rules in the normalization actor, queryable and revisable declaratively; generated/embedded data is welcome only as Prolog-loaded policy content, never as a parallel non-Prolog policy engine.
