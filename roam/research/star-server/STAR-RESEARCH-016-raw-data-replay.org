* Research Question

Should replay from preserved raw inputs be a correctness invariant for important derived StarIntel intelligence?

* Finding

*STRONG KEEP.* Event-sourcing systems preserve an append-only history so application state can be reconstructed by replay. W3C PROV similarly models derivation and provenance needed to explain how outputs came from inputs.

For StarIntel, replay should mean preserving enough raw source material and transformation context to regenerate important derived documents and graph projections: raw bytes or immutable source references, request metadata, actor identity and version, parser and normalization versions, timestamps, transformation parameters, and deterministic identifiers. Snapshots can accelerate recovery, but they should not become the only surviving truth when reproducibility matters.

* Research Gaps

- Define the minimum replay envelope for each ingest class.
- Decide how external mutable sources are archived or content-addressed.
- Define version pinning and migration behavior when actor or parser code changes.
- Measure storage cost against replay guarantees.

* Footnotes and Glossary

- *Replay*: Regenerating derived state from preserved inputs and transformation history.
- *Replay envelope*: The minimum preserved data and version context required to reproduce a derived result.
