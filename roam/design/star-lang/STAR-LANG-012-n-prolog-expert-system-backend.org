* Objective

Provide StarLang with a smaller conservative Prolog execution target whose
capabilities are declared only when independently proven against an exact pinned
N-Prolog build. Use the external process boundary for strong replacement/hard
cancellation semantics while keeping the public language contract identical to
STAR-LANG-009.

* Approved Decision

StarLang SHALL implement N-Prolog through the final-owned system:

#+begin_example
star-logic-adapter-nprolog
#+end_example

N-Prolog is an approved initial concrete backend, not merely an experiment.
However, its runtime descriptor SHALL advertise only the exact subset proven by
conformance fixtures. It MUST NOT inherit capabilities because SWI-Prolog
supports a similarly named feature.

The backend is intended for workloads fitting a deliberately small portable
relational subset and benefiting from a simple supervised process boundary.

* Backend Boundary

#+begin_example
StarIntel objects/documents
        |
        v
identity-preserving projection
        |
        v
portable StarLang logic package + named operations
        |
        v
star-logic-adapter-nprolog
        |
        v
StarIntel-owned framed process wrapper
        |
        v
pinned npl worker
        |
        v
normalized answers + optional proofs + usage
#+end_example

Native terms, interpreter/process handles, clause database objects, or arbitrary
executable goals MUST NOT cross the portable boundary.

* Identity-Preserving Projection

Every projected source record SHALL remain traceable to authoritative StarIntel
state through at least:

- object/document ID;
- schema/type identity and version;
- provenance/source references;
- relation/document references needed by the package;
- StarLang session fact identity;
- source revision/generation where required;
- verification/proof metadata required by a claimed proof profile.

Projection state is disposable and reconstructible from authoritative inputs and
the session journal. It is not a second canonical datastore.

* Approved Portable Subset Principle

The N-Prolog adapter begins with the smallest subset needed by canonical StarLang
relational fixtures.

Capabilities MAY include only when proven:

- facts and rules;
- first-order unification;
- conjunction;
- finite disjunction with specified wrapper behavior;
- terminating recursion under declared budgets;
- explicitly mapped arithmetic/comparison operations;
- bounded answer enumeration;
- named operation wrappers;
- separately proven finite-domain constraint behavior.

The initial contract SHALL NOT claim:

- SWI tabling or incremental tabling;
- SWI module/library semantics;
- SWI exception identity;
- LISA agenda/salience/RETE semantics;
- proof semantics without an explicit proof-emitting wrapper.

If a package requires an unsupported stronger profile, materialization fails
before execution rather than approximating or silently switching backend.

* Approved Semantic Profiles

Initial target profiles are:

#+begin_example
star.logic.query/1
star.logic.portable-prolog/1
star.expert.relational/1
#+end_example

Any stronger profile requires exact observable semantics and independent fixtures
against the pinned N-Prolog build.

* Named Operations Only

Portable source uses =solve=, =solutions=, =exists?=, and =explain= through
compiler/package-declared named operations.

Forbidden:

- arbitrary predicate names supplied at runtime;
- arbitrary executable source strings;
- arbitrary consult/load paths;
- prompt/LLM-produced executable Prolog;
- transparent fallback from unsupported SWI packages;
- direct mutation of canonical StarIntel state.

* Framed Process Protocol

The initial transport SHALL use a pinned =npl= child process behind a
StarIntel-owned framed request/response wrapper.

Protocol kinds cover at least:

#+begin_example
hello
loadPackage
openSession
applyDelta
invoke
nextResult
cancel
closeSession
health
shutdown
#+end_example

Each request carries explicit protocol, correlation, session, and operation
identity sufficient to reject stale or cross-session responses. Framing is
versioned and output is bounded/schema-validated.

* Worker Model

The safe initial rule is one active query per worker. Concurrency comes from a
supervised worker pool instead of concurrent mutable interpreter state inside one
worker until stronger semantics are proven.

A worker is discarded after hard cancellation, malformed protocol output, engine
crash, package mismatch, uncertain reset state, framing corruption, or failed
health handshake.

No killed or uncertain worker is reused.

* Startup Handshake and Package Identity

The adapter records and validates:

- adapter version;
- wrapper protocol version;
- N-Prolog version;
- executable hash/build identity;
- supported API/profile versions;
- fixture-proven capabilities.

Every executable package/bootstrap is digest-locked and records package ID,
version, package digest, mapping digest, compiler version, required profiles,
required capabilities, engine compatibility, and named operations.

Untrusted StarLang source never supplies raw package bytes.

* Session Facts

Portable =assert!= and =retract!= operate on stable StarLang fact identity.
Native representation is private and must preserve:

- immutable projected source facts;
- journaled session mutations;
- isolation between logical sessions;
- STAR-LANG-009 idempotency semantics;
- replay from normalized deltas;
- distinction between portable =retract!= and arbitrary native pattern retraction.

If reliable mutable session behavior is not fixture-proven for a profile, the
capability is omitted rather than simulated ambiguously.

* Results and Enumeration

Results normalize into STAR-LANG-009 answer records. =solutions= follows explicit
StarLang answer limit, duplicate policy, and ordering policy; native enumeration
order is not portable unless a stronger profile defines it.

The wrapper bounds answer count, output bytes, result size, wall time, and proof
data when enabled. Malformed native terms/output become typed failures rather
than partially trusted values.

* Cancellation

The process boundary is intentionally a reliable hard-stop mechanism.

#+begin_example
cooperative wrapper cancellation if proven
        |
        v
terminate worker process
        |
        v
spawn fresh pinned worker
#+end_example

A runtime descriptor that cannot prove cooperative cancellation advertises only
hard process cancellation.

* Failure Contract

Normalize at least:

- normal no-answer;
- invalid named operation;
- parameter/type mismatch;
- unsupported profile/capability;
- package/bootstrap mismatch;
- executable version/hash mismatch;
- projection failure;
- timeout/resource limit;
- cancellation;
- malformed framed response;
- engine crash;
- proof unavailable;
- reset/isolation failure.

Native diagnostic text is bounded metadata, never portable failure identity.

* Proof Normalization

No generic native proof capability is assumed.

A named operation may claim proof support only when a StarIntel-owned package or
wrapper explicitly emits enough derivation evidence to normalize into:

#+begin_example
star.logic.derivation/1
#+end_example

The adapter MUST NOT derive a proof graph from incidental trace/debug output.

* Constraint Support

Finite-domain or CLP(FD)-like capabilities are independently tested against
N-Prolog. SWI capability claims are irrelevant.

A constraint profile requires fixtures for domains, arithmetic semantics,
propagation/result behavior, bounded enumeration, failure, timeout/cancellation,
and normalized outputs. Until those gates pass, the descriptor omits the
capability.

* Target Capability Set

After fixture proof, N-Prolog may advertise:

- typed projected facts;
- identity-preserving StarIntel projection;
- relational named queries over its portable subset;
- bounded terminating recursion where proven;
- bounded answers;
- process isolation;
- hard cancellation through worker replacement;
- wrapper-dependent normalized proof;
- narrowly fixture-proven constraint profiles.

It does not initially advertise tabling, incremental tabling, production agenda,
salience, or persistent RETE working memory.

* Security Invariants

1. Only StarIntel-owned framed commands reach the worker.
2. Raw user goals are never executed.
3. Packages/bootstrap code are digest-locked.
4. Projection preserves authoritative identity/provenance.
5. Canonical source documents remain immutable.
6. Mutable session state is isolated.
7. Output is bounded, framed, parsed, and schema-validated.
8. Worker filesystem/environment exposure is minimized.
9. Killed or uncertain workers are replaced.
10. Secrets are excluded from generated packages, proofs, and fixtures.

* Approved Prototype Retirement

The N-Prolog backend SHALL be final-owned from its first implementation slice.

- No production =npl= launcher, framed protocol, package loader, projection layer,
  query dispatcher, cancellation manager, proof normalizer, or capability
  descriptor may be prototype-owned.
- Temporary prototype call sites may only forward into
  =star-logic-adapter-nprolog= and contain no independent backend semantics.
- New N-Prolog fixtures/tests belong to final adapter/expert test systems.
- Superseded prototype logic/process code is removed as its callers migrate.
- Final N-Prolog ASDF/Nix tests SHALL run without =starlang-prototype=.
- Repository-wide completion must prove whether the full StarLang port is done
  and delete =prototype/= when the proof passes.

* Implementation Order

1. final adapter system and pinned process wrapper;
2. exact version/hash/protocol/capability handshake;
3. digest-locked package/bootstrap loading;
4. one real identity-preserving StarIntel projection;
5. =solve=, =solutions=, =exists?= and normalized failures over the proven subset;
6. hard cancellation, replacement, stale-response rejection, and no-state-leak tests;
7. proof wrapper only after explicit evidence is available;
8. optional constraints only after independent fixtures;
9. delete superseded prototype implementation/tests during each migration slice.

* Acceptance Gate

Implementation is complete when:

1. =star-logic-adapter-nprolog= has final package ownership;
2. exact N-Prolog binary/version/hash is validated;
3. one real StarIntel object/document family projects with identity/provenance preserved;
4. only named operations are executable;
5. =solve=/=solutions=/=exists?= obey STAR-LANG-009 over the declared portable subset;
6. unsupported SWI-specific profiles fail before execution;
7. framed protocol corruption is rejected safely;
8. hard cancellation kills and replaces the worker;
9. mutable state does not leak between logical sessions;
10. proof is advertised only when an explicit wrapper emits sufficient evidence;
11. same-backend replay is deterministic;
12. descriptor advertises only independently fixture-proven capabilities;
13. no final N-Prolog path loads =starlang-prototype= or files under =prototype/=.

* Footnotes and Glossary

- *Portable subset* — Explicit fixture-proven N-Prolog semantics; never inferred from SWI compatibility.
- *Framed wrapper* — StarIntel-owned process protocol separating structured commands/results from arbitrary interpreter text.
- *Identity-preserving projection* — Relational representation that retains stable linkage to authoritative StarIntel identity and provenance.
- *Worker replacement* — Discarding an uncertain/killed N-Prolog process and starting a fresh pinned worker instead of attempting unsafe reuse.
- *Prototype retirement* — Removal of transitional prototype ownership as final N-Prolog systems become authoritative.
