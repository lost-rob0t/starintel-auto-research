* Current Dialect Research Gate

[[id:star-kb-research-003-dialect-enrichment-corpus-inference-evidence][STAR-KB-RESEARCH-003]] now answers the prior conceptual open questions while retaining the research-only gate. The research-supported first inference baseline is *weighted/salient evidence* rather than equal counting.

The current evidence decomposition is:

#+begin_src text
regional association
  * feature salience
  * source reliability
  * exposure relevance
  - redundancy/conflict penalties
#+end_src

Salience should be learned from corpus distributions where possible rather than assigned because a feature merely appears regional. A weighted score is not automatically a calibrated probability. Weak or conflicting evidence must be allowed to abstain.

The research now records these dispositions:

- geography should preserve multiple simultaneous resolutions rather than one state-only label;
- first-party acquisition/exposure history should prefer age-banded residence history over exact addresses, with under-18 residence carrying the strongest research-supported exposure priority;
- linguistic evidence and contextual/named-entity geographic evidence remain separate evidence classes through scoring and explanation;
- the Harvard/Vaux/Golder respondent-level corpus is not a dependency unless directly obtained with compatible terms;
- licensing and contractual obligations remain source-specific and are not assumed to disappear after aggregation or embedding;
- PQS currently serializes same-KB queries because =query_kb/4= holds the per-KB mutex across release resolution/snapshot work and inference;
- current PQS defaults cap a loaded KB/release at 10,000 knowledge documents and 16 MiB, so larger-corpus performance requires measurement rather than speculation;
- probabilistic logic is an escalation experiment, not a prerequisite; compare cplint/ProbLog externally against the frozen weighted-salience baseline first, and include DeepProbLog when neural predicates are actually under test;
- no universal word-count or audio-duration threshold is justified; inference should depend on accumulated salient evidence plus calibration and abstention;
- learned-model evaluation should be speaker-disjoint and should add geographic, source/domain, and time holdouts when the data support them;
- first-party collection should use purpose-separated consent, finite raw-data retention, deletion while the corpus remains controlled, and derived aggregate publication by default rather than raw identifying speech/text.

The dialect research conclusion remains =PENDING= operator review. No dialect actor design, corpus schema, frozen scoring formula, API contract, numeric weights, confidence thresholds, or implementation contract is authorized by this node.

* Remaining Empirical and Permission Checks

The conceptual architecture questions in STAR-KB-RESEARCH-003 are no longer open. The remaining work is measurement or permission:

- benchmark PQS load time, RSS, inference latency, proof size, and concurrent same-KB throughput at realistic dialect clause shapes;
- learn feature salience, signed regional association, redundancy penalties, and abstention thresholds from first-party or otherwise compatible corpora;
- calibrate weighted scores and measure selective accuracy/risk versus coverage on speaker-disjoint, geographic-holdout, source/domain-holdout, and time-holdout data;
- establish per-source rights before promoting non-first-party source material or derived values into unrestricted =star-kb= bundles;
- contact Harvard/Vaux/Golder data/rightsholders only if respondent-level HDS data is still desired;
- measure the amount of independent salient evidence needed before text or speech inference stops abstaining.

These are validation gates for a later design/implementation, not permission to start implementation now.

* Existing Design Decision Under Review

STAR-KB-001 V0.1 proposes:

- restricted readable Prolog as knowledge source;
- SWI-Prolog term parsing without consulting/executing source;
- JSON manifests for modules, bundles, source records, and generated releases;
- build-time dependency closure with one bundle -> one PQS KB release;
- alpha-normalized stable logical clause IDs;
- content-derived immutable release IDs;
- deterministic compilation to current PQS safe JSON AST;
- replay-safe staging and exact staged-set verification;
- PQS static analysis and pinned query/explain fixtures before activation;
- separate explicit activation with =strict:true= and caller-supplied CouchDB manifest =_rev=;
- rollback by reactivating a previously checked immutable release;
- synthetic =star.core.test= as the only V0.1 knowledge bundle;
- no production dialect corpus or StarIntel actor work in this first implementation slice.

This pre-existing design was not changed or approved by the dialect research pass.

* Footnotes and Glossary

- *ARADR control plane* :: The research/design/implementation-state documents recording what was researched, what is awaiting approval, and what implementation is active. Here it lives in =starintel-auto-research=.
- *PQS* :: =prolog-query-server=.
- *KB* :: Knowledge base, a named collection of facts and rules.
- *Bundle* :: Consumer-facing package of source modules plus transitive dependencies; the existing V0.1 design proposes publishing one bundle as one PQS release.
- *Release* :: Immutable version of one runtime KB.
- *Canonical knowledge* :: Reviewed reusable facts/rules, distinct from one investigation's observations.
- *Weight* :: Numeric evidence importance/reliability used in scoring; it is not automatically a probability.
- *Salience* :: How discriminative a feature is across candidate dialect regions or varieties.
- *Evidence mass* :: The amount of sufficiently independent weighted salient evidence available for a candidate, distinct from raw token count or audio duration.
- *Abstention* :: Returning insufficient evidence rather than forcing a region when evidence is weak, sparse, or conflicting.
- *Dialect enrichment* :: Analysis that attaches evidence-backed regional-language features or candidates to an input while preserving uncertainty; it is not synonymous with exact geolocation.
- *Implementation slot* :: The one active approved design copy under =roam/implement/<project>/= used to track actual implementation work.
