* Final Language Decision

Common Lisp is the sole approved Star-Lang implementation language.

Every alternate parser, compiler, semantic engine, dispatcher, and runtime implementation is DENIED.

The language and architecture decision is final. The implementation remains active until its acceptance ledger is complete.

The macro research audits the canonical =lost-rob0t/star-lang= source and proposes a closed, deterministic, hygienic macro-expansion phase. It is in =REVIEW= and does not change the approved implementation language or authorize procedural =.star= macros.

The logic research adds a Common Lisp =star-logic= capability layer above the internal =star-prolog= library and the proposed LISA-derived =star-rules= engine. =reason= forms compile to closed normalized logic-call nodes. Backend selection occurs before execution and is pinned for replay.

* Current Work Order

1. keep the Common Lisp workflow green;
2. replace raw parsed atoms and list-only position tracking with per-occurrence syntax objects, complete source spans, and origin chains;
3. split the compiler pipeline into explicit read, expand, core-validation, and semantic-compilation phases;
4. implement locked, bounded, hygienic declarative macros only after syntax identity and provenance are stable;
5. package the Common Lisp implementation as explicit ASDF systems;
6. replace shell-backed digest and retrieval calls with injected Common Lisp ports;
7. add one top-level Common Lisp test runner;
8. freeze canonical manifest and expansion fixtures;
9. validate direct and cl-gserver lifecycle equivalence;
10. add end-to-end replay and recovery tests;
11. extract stable Common Lisp packages after boundaries stabilize;
12. add the normalized =logic-call= IR and canonical JSON schema;
13. implement the =star-logic= runtime port and deterministic backend selector;
14. connect =star-logic.prolog= to =star-prolog= without exposing native Prolog terms;
15. add common logic conformance and performance fixtures before enabling =star-rules= routing.

* Invariants

- Star-Lang implementation code is Common Lisp only.
- Untrusted =.star= source never enters the Common Lisp reader.
- No unrestricted =EVAL= enters compilation or execution.
- Source macros do not execute arbitrary Common Lisp transformer code.
- Macro dependencies are exact-versioned and digest-locked.
- Macro expansion is hygienic, deterministic, resource-bounded, and source-traceable.
- Macros expand completely before semantic compilation and do not enter runtime IR.
- Normalized IR does not contain cl-gserver object types.
- Normalized IR does not contain native Prolog terms, LISA objects, sessions, sockets, or engine handles.
- Versioned JSON is an interchange format, not another implementation.
- Direct execution works without cl-gserver.
- Actor systems remain optional Common Lisp adapters.
- Logic backends are selected and pinned before execution; runtime load does not change engine semantics.
- Research nodes never extend the StarIntel schema.
- Auto-dig and Quasar consume contracts rather than defining them.
- Alternate implementation languages remain DENIED.
