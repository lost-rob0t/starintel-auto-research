* APPROVED Final Decision

Common Lisp is the sole approved implementation language for Star-Lang.

Common Lisp owns:

- the closed =.star= parser;
- source locations and origin chains;
- semantic validation;
- normalized IR construction;
- canonical manifest generation;
- lifecycle and delivery semantics;
- deterministic dispatch;
- durable recovery;
- document construction;
- direct execution;
- optional cl-gserver integration;
- the public Star-Lang API.

This is a final language and architecture decision. There is no active language-selection gate and no retained competing implementation.

This decision does not claim that every implementation acceptance criterion is complete. Remaining implementation hardening is tracked in [[https://github.com/lost-rob0t/starintel-auto-research/issues/47][issue #47]].

* DENIED Alternatives

** DENIED Racket

Racket is not a Star-Lang implementation target, conformance runtime, parser frontend, expansion oracle, tooling oracle, or fallback host. The Racket implementation path is not retained.

** DENIED Scheme and Guile

Scheme and Guile are not Star-Lang implementation targets, portability witnesses, fallback runtimes, or conformance implementations. Their implementation paths are not retained.

** DENIED Other Host Languages

C, C++, Rust, Python, JavaScript, TypeScript, Nim, Java, Go, and every other language are denied as implementations of the Star-Lang parser, compiler, semantic engine, dispatcher, or runtime.

External programs may exchange versioned JSON messages or call an API. Generated boundary bindings do not make those programs Star-Lang implementations.

* Final Architecture

#+begin_src text
.star source
    |
    v
Common Lisp closed parser
    |
    v
Common Lisp semantic compiler
    |
    v
Common Lisp normalized IR and runtime
    |
    +--> canonical JSON at system boundaries
    +--> cl-gserver adapter
    +--> transport adapters
#+end_src

The implementation remains Common Lisp from source parsing through execution. JSON is an interchange format, not a second implementation language.

* Hard Boundaries

1. Star-Lang source is not arbitrary Common Lisp source.
2. Untrusted source never enters the Common Lisp reader.
3. No unrestricted =EVAL= or reader evaluation enters compilation or execution.
4. Source identifiers remain strings until validated.
5. Core IR remains independent of cl-gserver object types.
6. Field access remains explicit; dot syntax is denied.
7. Actor readiness affects routing, not program validity.
8. Research nodes never become StarIntel object types, predicates, fields, or schema extensions.
9. Auto-dig and Quasar consume Star-Lang contracts and do not define its semantics.
10. No alternative language implementation is retained in the repository.

* Approval Rule

The Common Lisp selection is approved and final. Do not reopen language comparison, add another host implementation, or restore alternate-language conformance runtimes without a new explicit decision from nsaspy that directly reverses this approval.

* Result

Common Lisp language ownership and architecture are APPROVED.

Implementation completion remains =IMPLEMENTING= until the active acceptance ledger is complete.

Every alternate Star-Lang implementation language is DENIED.
