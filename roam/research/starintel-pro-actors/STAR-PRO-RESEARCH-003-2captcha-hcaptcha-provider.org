* Scope

2Captcha is a broad asynchronous task provider. Its value cannot be assessed from hCaptcha alone. Current official API navigation covers token systems, Web Application Firewall challenges, image and text recognition, coordinates, grids, rotation, draw-around, drag-and-drop, and multiple issuer-specific families.

Every task family has its own required fields and result schema. The generic =createTask= operation does not make task contracts interchangeable. Current hCaptcha uncertainty is capability-specific and must not disable unrelated verified families.

* Exact Capability Record

For every enabled task, record:

- provider task type;
- official source and retrieval date;
- issuer;
- family;
- variant;
- integration version;
- request operation;
- result operation;
- authentication;
- required and optional request fields;
- expected result kind and required result fields;
- proxy, cookie, user-agent, browser-session, same-network, and mobile requirements;
- delivery model;
- cancellation;
- idempotency;
- ambiguous-submission behavior;
- concurrency;
- billing;
- retention;
- execution and human-worker disclosure class;
- error contract;
- fixture fingerprint and freshness;
- live-probe requirements;
- unsupported variants;
- contradictions;
- state: =verified=, =experimental=, =degraded=, =invalidContract=, =disabled=, or =unsupported=.

One task's contract failure changes only that capability unless shared authentication, generic API health, balance, or security policy makes all tasks ineligible.

* Result-Kind Mapping

| Provider task family | Normalized result kind |
|----------------------+------------------------|
| Token systems | =token= |
| Score-producing systems | =assessment= or =token= according to exact contract |
| WAF or clearance systems | =cookie=, =proof=, or =token= according to exact contract |
| Image-to-text and question tasks | =textAnswer= |
| Coordinate and draw-around tasks | =coordinates= |
| Grid tasks | =selectionSet= |
| Rotation and drag-and-drop tasks | =interactionPlan= or =customTypedResult= |
| Other vendor-specific tasks | exact typed result declared by the capability |

The adapter rejects forbidden result-kind widening. Coordinates are not selections; a provider token is not downstream acceptance; a cookie is not a generic token.

* hCaptcha Contract State

Historical client material has referenced task names such as =HCaptchaTaskProxyless= and =HCaptchaTask=, while current official task navigation and contract availability have been inconsistent. The hCaptcha capability therefore remains =experimental= or =invalidContract= according to the latest fixture until one of these exists:

1. a current official task page with complete request and result schema;
2. a provider-supported sandbox fixture; or
3. a credential-gated, cost-bounded probe against an operator-owned hCaptcha integration.

No hCaptcha uncertainty changes the state of independently verified reCAPTCHA, Turnstile, GeeTest, Arkose, image, coordinate, grid, rotation, or other task capabilities.

* Human-Worker Disclosure

2Captcha describes automated service behavior with human-worker participation or escalation for difficult tasks. Unless exact capability evidence establishes a narrower execution class, register it as =humanAssistedVendor=.

Before dereferencing challenge context, target policy must explicitly permit that disclosure class. The provider may receive target URLs, site keys, prompts, challenge images, task instructions, proxy/network context, cookies, or other bounded data required by the exact task. Authenticated page content, full browser snapshots, private session material, and personal data are not sent by default.

* Proxy, Cookie, User-Agent, Session, Network, and Mobile Rules

Each task declares its exact context requirements. The broker rejects a task when:

- a proxy type or same-network binding is required but unavailable;
- cookies are required but disclosure is not authorized;
- user-agent fidelity is required but cannot be preserved;
- the source browser session cannot consume the result safely;
- the capability is mobile-specific and no supported mobile context exists;
- the provider task would widen from proxy-required to proxyless or vice versa.

Context values remain behind ephemeral references.

* Budget, Pricing, and Accepted-Result Cost

Record the current provider price with the exact task contract and retrieval date. Reserve cost before =createTask=. Reconcile only from provider evidence. Local cancellation or a failed downstream application does not prove that the provider did not charge.

Selection compares cost per downstream accepted result for the exact capability, not raw advertised task price or provider completion rate.

* Idempotency, Duplicate Delivery, Cancellation, and Ambiguity

The adapter journals =attemptId= before creation and records =taskId= immediately after a successful create response. Duplicate local or RabbitMQ messages attach to the same active task or replay its terminal normalized result.

No universal provider cancellation operation is assumed. Local cancellation stops polling, deletes unconsumed local result material, and reports =chargePossible=true= when the provider task may continue.

An ambiguous create without a recoverable =taskId= is not retried automatically. Fallback requires a terminal non-ambiguous prior state, new attempt ID, remaining budget, exact capability, and disclosure authorization.

* Error Contract and Capability-Local Drift

Normalize provider authentication, balance, invalid task, invalid fields, unsupported task, processing, unsolvable, timeout, service failure, malformed result, and callback-related errors. Every normalized failure records =retryable= and =chargePossible=.

Move only the affected capability to =invalidContract= when:

- a required field disappears;
- an unexpected result kind or required-field omission appears;
- the provider returns task-not-supported;
- the task page contradicts current fixtures;
- a capability probe fails its exact contract.

Shared client-key, balance, generic API, or provider outage may temporarily disable all 2Captcha tasks.

* Security and Retention

Never persist or publish client keys, result tokens, cookies, text answers, coordinates, selections, interaction plans, proxy credentials, cookie bundles, page data, authorization headers, callback secrets, or full provider request/response bodies.

Provider retention and human-worker exposure must be reviewed from current terms and task documentation before enabling a capability. Result values remain in the ephemeral secret store and are consumed by the authorized source runtime through one-read references.

* Required Fixtures and Tests

- generic create, processing, ready, balance, feedback, and every relevant error;
- one current request/result fixture for every enabled task family;
- token, assessment, cookie, proof, text, coordinates, selections, interaction plan, and custom typed results;
- forbidden family, version, variant, field, result-kind, proxy, and session widening;
- hCaptcha unsupported/experimental/invalid-contract transitions independent of other tasks;
- duplicate delivery and task replay;
- ambiguous create without task ID;
- local cancellation with possible provider charge;
- human-worker disclosure denial before secret dereference;
- budget exhaustion and cost reconciliation;
- client key, challenge context, provider response, and result redaction;
- capability-local drift;
- shutdown with active tasks;
- no callback listener in version one;
- no paid provider in continuous integration;
- per-family opt-in canaries on operator-owned systems only.

* Decision

Retain 2Captcha as a broad exact-capability and human-assisted provider candidate. Implement family-specific request mappers and result validators. Do not reject unrelated capabilities because hCaptcha is uncertain, and do not enable any task solely from an old software-development kit, marketing page, or shared =createTask= operation.

* Footnotes and Glossary

- *Human-assisted vendor* — A provider execution class in which human workers may inspect or solve submitted challenge material.
- *Task family* — One provider operation with a distinct request and result contract, such as Turnstile, reCAPTCHA v2, coordinates, or grid selection.
- *Capability-local drift* — A contract failure isolated to one exact task rather than a global provider rejection.
- *Ambiguous create* — A task-creation request whose provider-side outcome is unknown and may already be billable.
