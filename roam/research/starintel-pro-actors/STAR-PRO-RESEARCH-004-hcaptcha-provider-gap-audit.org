* Scope

This node corrects the invalid rule “a provider without hCaptcha is useless.” Anti-Captcha, CapSolver, and CapMonster Cloud may cover independently valuable reCAPTCHA, Turnstile, Arkose, GeeTest, Amazon Web Services Web Application Firewall, DataDome, Friendly Captcha, ALTCHA, MTCaptcha, Prosopo, image, coordinate, or custom tasks.

The broker registers exact capabilities. A missing or invalid hCaptcha contract changes only that row. It is not evidence against every other task.

A raw logo count or family count is not a coverage matrix. One row includes issuer, family, variant, integration version, required fields, result kind, source-session/network binding, execution class, disclosure class, and contract state.

* CapSolver Gap Analysis

Current official material documents selected automated anti-bot and CAPTCHA tasks but does not establish hCaptcha. Therefore:

- =captcha.hcaptcha.*= is =unsupported=;
- exact reCAPTCHA, Turnstile/Cloudflare, GeeTest, MTCaptcha, DataDome, AWS WAF, Arkose, and image tasks remain adapter candidates only when a current task page and fixture agree;
- automated execution can reduce human-worker disclosure, but exact provider data handling and retention still require review;
- task-specific proxy, cookie, user-agent, session, network, and mobile requirements must be recorded;
- cost and concurrency are capability-specific;
- shared authentication or provider health failure may disable all CapSolver tasks, while one mapper drift affects only that capability.

* Anti-Captcha Gap Analysis

Current official task indexes document a broad catalog including image-to-text, coordinates, reCAPTCHA, Arkose Labs FunCaptcha, GeeTest, Cloudflare Turnstile, Prosopo, Friendly Captcha, Amazon WAF, ALTCHA, and custom AntiGate tasks.

Anti-Captcha is a strong candidate when:

- a current exact task closes an uncovered capability or supplies operational redundancy;
- target policy permits human-worker disclosure;
- request/result, proxy, cookie, browser-session, network, billing, cancellation, and ambiguous-create behavior are documented;
- result typing matches the normalized broker union;
- mock fixtures pass.

Custom AntiGate tasks require separate design and security review. A programmable target-specific template can exceed a normal provider-neutral challenge contract and must not be enabled as a generic wildcard.

* CapMonster Cloud Gap Analysis

Current official material documents selected automated token and challenge tasks but not hCaptcha. Therefore:

- hCaptcha remains =unsupported=;
- reCAPTCHA, Turnstile, Arkose, GeeTest, Friendly Captcha, MTCaptcha, and other exact documented tasks remain candidates;
- a historical unsupported hCaptcha response says nothing about unrelated task mappers;
- automated execution does not eliminate provider disclosure, retention, context, or cost review;
- each task requires a current request/result fixture and exact context binding.

* Required Provider Capability Fields

Any adapter backlog row must record:

- provider and official source;
- retrieval date;
- issuer, family, variant, and integration version;
- request and result operations;
- authentication;
- required and optional request fields;
- result kind and required result fields;
- proxy, cookie, user-agent, browser-session, same-network, and mobile requirements;
- delivery, cancellation, idempotency, and ambiguous-create behavior;
- concurrency, billing, retention, and error contract;
- automated, human-worker, or mixed execution;
- disclosure implications;
- contract confidence, fixtures, live-probe requirements, unsupported variants, and contradictions;
- current capability state.

A provider marketing page is insufficient when the exact task contract is absent.

* Adapter Candidate Gate

Create a dedicated adapter design only when:

1. a current official task page defines the exact request and result schema;
2. the capability closes a measured coverage or redundancy gap;
3. authentication and secret placement are known;
4. result kind and context binding map exactly to the broker contract;
5. execution and disclosure class are known;
6. provider retention and target-data exposure are acceptable;
7. cancellation, idempotency, ambiguous create, cost, concurrency, billing, and errors are understood;
8. fake-provider request/result fixtures pass;
9. static manifest design contains no unverified active capability claims;
10. a credential-gated, cost-bounded owned-system canary is approved.

* Reconsidering an Absent Capability

A previously absent capability such as hCaptcha can move from =unsupported= only when all of these exist:

1. a current official provider page naming the task;
2. documented create and result operations;
3. documented required request and result fields;
4. documented authentication and error contract;
5. exact variant, result, proxy, session, network, mobile, execution, and disclosure rules;
6. a passing fixture or bounded owned-system probe;
7. a retrieval date and fixture fingerprint;
8. security and operator review.

A stale software-development kit or extension claim is insufficient.

* Candidate Evaluation Axes

Do not rank providers by hCaptcha alone or marketing breadth. Evaluate adapter candidates by:

- exact uncovered capability or redundancy value;
- contract clarity and contradictions;
- fixture freshness;
- source-context fidelity;
- exact downstream acceptance rate;
- execution and disclosure class;
- session and network compatibility;
- cancellation and ambiguous-create behavior;
- provider health and concurrency;
- deadline fit;
- cost per accepted result;
- operator policy.

This research does not select a universal provider. Runtime solver ranking remains the two-phase hard-eligibility and ranking process in [[id:star-captcha-000-broker-router][STAR-CAPTCHA-000]].

* Footnotes and Glossary

- *Capability gap* — An exact challenge row with no eligible validated solver or insufficient independent redundancy.
- *Adapter candidate* — Provider capability worth a dedicated design because it closes a measured gap and has a usable contract.
- *Global provider rejection* — Invalid practice of disabling every provider capability because one task family is absent or broken.
- *Custom AntiGate task* — Provider-programmed, target-specific human workflow requiring separate schema, disclosure, and authorization review.
