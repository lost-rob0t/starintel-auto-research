* Purpose

Provision a dedicated repository for the reusable Common Lisp[fn:cl] systems that the StarIntel[fn:starintel] actor platform depends on. The StarLang[fn:starlang] compiler and durable actor runtime[fn:actor-runtime] do not belong inside this research repository or inside =starintel-server=. This repository remains the design and evidence source; =starintel-server= later consumes released runtime systems from the new repository.

This decision closes the provisioning blocker for the Franklin County[fn:franklin] actor design so that no live data acquisition implementation begins here.

* Pre-creation Decisions

All pre-creation decisions from issue [[https://github.com/lost-rob0t/starintel-auto-research/issues/57][#57]] are resolved.

- [X] confirm repository name :: =lost-rob0t/star-lang=. Short, hyphen-separated, distinct from =starintel-*= research and server repositories.
- [X] confirm Apache-2.0 or alternative license :: GPL-3.0 selected. The runtime is a durable shared dependency; copyleft keeps derivative runtimes open and remains compatible with the broader StarIntel toolchain.
- [X] identify maintainers :: =lost-rob0t= as sole administrator initially. Maintainer expansion is deferred until the first reviewed contribution lands.
- [X] define ASDF[fn:asdf] package naming :: =star-<name>= and =starlang-<name>=, lowercase, hyphen-separated, matching the system names in this design verbatim. One ASDF system per directory at the repository root.
- [X] choose dependency locking and offline cache strategy :: dependencies are pinned in a lockfile generated from a clean Quicklisp dist. The dist tarballs are mirrored into a local cache and loaded via =CL_SOURCE_REGISTRY=. A clean, network-free load is a release gate enforced by CI[fn:ci].
- [X] define Nix[fn:nix] and Roswell[fn:roswell] entry points :: =flake.nix= provides =nix develop= with SBCL[fn:sbcl] and a source-registry pointing at the repository root. =docs/roswell.md= documents reproducible SBCL installation and the offline-cache workflow.
- [X] define SBCL-first CI matrix :: CI runs SBCL first and fails fast. The matrix is SBCL-only at provisioning time; other conforming implementations (ECL, ABCL) may be added as a non-blocking matrix lane after the core systems stabilize. CI enforces the Common Lisp-only implementation boundary by rejecting Racket, Scheme, Guile, Python, and other implementation-language files.
- [X] define branch, release, and changelog policy :: =main= is the protected release branch; all changes flow through pull requests. Releases are tagged =vX.Y.Z= following Semantic Versioning. =CHANGELOG.md= uses Keep a Changelog and is updated per release. Pre-release tags of the form =vX.Y.Z-rc.N= are permitted.
- [X] define upstream contribution and fork policy :: this repository is the canonical upstream for the =star-*= and =starlang-*= systems. Forks are welcome for experimentation; releases are cut only from =main=. Modified copies must not be vendored into other repositories. Cross-cutting design discussion belongs in =starintel-auto-research=, not here.
- [X] define source/license/SBOM[fn:sbom] inventory :: =SECURITY.md= holds the source, license, and software bill of materials inventory for every first-party system plus the SBCL, ASDF, Quicklisp, and Roswell toolchain. The inventory is updated per release.

* Tooling Entry Points

- ASDF is the build system. Each system is loadable with =(asdf:load-system :star-actor-protocol)=.
- SBCL is the primary implementation. The local scaffold loads all fifteen systems under SBCL 2.6.4.
- Roswell installs SBCL and loads systems reproducibly; the offline-cache workflow is documented in =docs/roswell.md=.
- Nix provides a reproducible offline environment via =flake.nix= (=nix develop=).

* Architecture Boundary

- This repository holds Common Lisp runtime implementation only.
- Design, research, and evidence remain in =starintel-auto-research=.
- =starintel-server= consumes released runtime systems; it does not implement StarLang semantics.
- Alternate implementation languages remain DENIED, matching the final language decision.
- Generated Python and TypeScript bindings may consume versioned JSON contracts at boundaries but do not implement StarLang.

* Footnotes and Glossary

[fn:starintel] StarIntel: a local-first, document-driven, actor-based intelligence platform that preserves, normalizes, connects, and searches fragmented public or authorized data while retaining evidence and provenance.

[fn:starlang] StarLang: the domain-specific language and runtime, implemented solely in Common Lisp, that defines the actor, document, and dataflow contracts used across StarIntel.

[fn:cl] Common Lisp (CL): a standardized, dynamically typed programming language (ANSI X3.226) used here as the sole approved implementation language for StarLang parser, compiler, dispatcher, and runtime code.

[fn:actor] Actor: a small independent software unit that owns its private state and processes one message at a time through a mailbox.

[fn:actor-runtime] Durable actor runtime: the execution layer that runs compiled StarLang actors and preserves enough state to recover and replay work after a crash.

[fn:asdf] ASDF: Another System Definition Facility, the de facto Common Lisp build system that compiles and loads systems from declarative =.asd= files.

[fn:sbcl] SBCL: Steel Bank Common Lisp, a high-performance open-source Common Lisp compiler and runtime; the primary implementation for this repository.

[fn:roswell] Roswell: a command-line tool that installs Common Lisp implementations and loads ASDF systems reproducibly.

[fn:nix] Nix: a declarative, reproducible package manager used here to provide an offline build and development environment through a flake.

[fn:sbom] SBOM: Software Bill of Materials, a structured inventory of components, their origins, and licenses used to track supply-chain provenance.

[fn:gpl] GPL-3.0: the GNU General Public License v3.0, a copyleft license requiring derivative works to remain open under the same terms.

[fn:ci] CI: Continuous Integration, the automated workflow that builds and tests every change on a pull request before it merges.

[fn:cl-gserver] CL-GServer (Sento): an in-process Common Lisp actor library providing mailboxes, dispatchers, event streams, and router pools. =star-sento-compat= adapts its model.

[fn:mailbox] Mailbox: the queue that holds messages destined for a single actor until the actor processes them one at a time.

[fn:supervisor] Supervision tree: a parent-child hierarchy of actors where a supervisor restarts failed children according to a declared strategy, common in Erlang/OTP-style systems.

[fn:journal] Write-ahead journal (WAL): an append-only log of durable state changes used to replay and recover work after a crash.

[fn:capability] Capability token: an unforgeable, transferable authorization object that grants a holder the right to perform a specific operation.

[fn:adapter] Adapter port: a boundary component that translates between an external transport (such as HTTP or a subprocess) and the internal StarLang message surface.

[fn:canonical-json] Canonical JSON: a deterministic JSON serialization with fixed key ordering and formatting used for reproducible, signed interchange at system boundaries.

[fn:provenance] Provenance: the recorded origin and history of a piece of data, including where it came from and how it was transformed.

[fn:franklin] Franklin County: the jurisdiction (Franklin County, Ohio) whose public-data actor design required these reusable Common Lisp systems and therefore motivated provisioning this repository.
