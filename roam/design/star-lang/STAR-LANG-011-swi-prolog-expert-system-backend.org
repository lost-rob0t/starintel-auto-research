* Objective

Use SWI-Prolog as StarLang's full relational reasoning backend where workloads
need recursive queries, tabled evaluation, bounded enumeration, and approved
constraint solving. Preserve StarIntel identity/provenance across the relational
projection and expose only compiler-declared named operations rather than raw
Prolog execution.

* Approved Decision

StarLang SHALL implement SWI-Prolog through the final-owned system:

#+begin_example
star-logic-adapter-swi
#+end_example

SWI-Prolog is the primary backend for relational expert reasoning requiring:

- recursive named operations;
- tabled evaluation;
- bounded multi-answer queries;
- identity-preserving StarIntel projection;
- approved constraint profiles such as CLP(FD);
- process-isolated execution;
- typed normalized results/failures;
- cancellation and worker replacement;
- replay under an exact backend/package/build contract.

SWI SHALL NOT be presented as a transparent LISA replacement. Production agenda,
salience, persistent RETE working memory, and activation semantics belong to
production-rule profiles and are not implied by successful relational queries.

* Backend Boundary

#+begin_example
StarIntel objects/documents
        |
        v
identity-preserving projection
        |
        v
closed StarLang logic package + named operations
        |
        v
star-logic-adapter-swi
        |
        v
pinned SWI worker / MQI boundary
        |
        v
normalized answers + proofs + usage
#+end_example

Native SWI module handles, predicate indicators, variable/term references, query
handles, threads, or arbitrary executable goals MUST NOT cross the portable
boundary.

* Identity-Preserving Projection

Relational projection is disposable runtime state, not canonical StarIntel data.
Every projected source fact SHALL retain enough mapping information to recover:

- authoritative object/document ID;
- schema/type identity and version;
- source/provenance references;
- relation/document references required by the package;
- StarLang session fact identity;
- source revision/generation where freshness matters;
- verification metadata required by proof policy.

Conceptual native predicates may represent objects, fields, relations, and
provenance, but their exact names/layout are adapter-private and covered by the
mapping digest.

The projection MUST be reconstructible from authoritative inputs plus the session
journal.

* Named Operations Only

StarLang source invokes compiler-declared operations through =solve=,
=solutions=, =exists?=, and =explain= under STAR-LANG-009.

Each operation has a fixed name, typed parameters, result schema, semantic
profile, package digest, and budget known at materialization time.

Forbidden execution includes:

- arbitrary source-provided module names;
- arbitrary predicate indicators;
- raw Prolog terms used as goals;
- =call/1= over user-controlled callable terms;
- arbitrary =consult=/load paths;
- prompt/LLM-produced executable Prolog strings;
- any backend operation that directly mutates canonical StarIntel state.

* Approved Semantic Profiles

Initial SWI target profiles include:

#+begin_example
star.logic.query/1
star.logic.tabled/1
star.logic.constraints/1
star.expert.relational/1
#+end_example

Additional stronger semantics such as incremental/subsumptive tabling or answer
subsumption require explicit capability IDs and fixtures.

* Recursion and Tabling

Recursive named operations are first-class SWI capabilities.

A package claiming tabled semantics SHALL record the exact tabled profile,
package identity, wrapper definitions, and engine build. Observable table
semantic changes require a profile version change.

N-Prolog compatibility is never inferred from SWI support.

* Constraints

SWI constraint libraries such as CLP(FD) may be used only behind named package
operations and an explicit versioned constraint profile.

Each claimed constraint profile requires fixtures for accepted input domains,
normalized result domains, bounded enumeration, normal failure, timeout,
cancellation, and exact dependency/build identity.

The portable StarLang API never exposes arbitrary native constraint goals.

* Session Facts

Portable =assert!= and =retract!= operate on stable StarLang session fact IDs.
The SWI adapter may use dynamic predicates, session modules, or another internal
representation, but:

- authoritative projected source facts remain immutable;
- session mutations are journaled;
- sessions cannot see each other's mutable state;
- native pattern =retract/1= is not the meaning of portable =retract!=;
- duplicate/idempotency behavior follows STAR-LANG-009.

* SWI Worker and MQI Protocol

The production adapter SHALL launch an exact pinned SWI worker or saved state and
establish an authenticated/isolated local communication boundary appropriate to
the supported SWI version, using MQI where the integration contract supports it.

The adapter SHALL:

1. record and validate SWI version/build identity;
2. perform capability/API handshake;
3. load only digest-locked StarIntel-owned packages;
4. invoke only named wrappers;
5. normalize streamed answers;
6. enforce answer/output/time/proof budgets;
7. cancel cooperatively where possible;
8. escalate through connection/process termination when necessary;
9. discard killed, dirty, mismatched, or uncertain workers;
10. prove reset before reusing a worker for another logical session.

Process isolation is the safe initial production baseline.

* Results and Enumeration

Native answer order is not portable unless a selected profile explicitly defines
it. =solutions= follows StarLang's explicit limit, duplicate, and ordering
policies. Deduplication and canonical ordering operate on normalized StarLang
answer identity rather than incidental SWI enumeration order.

Normal logical no-answer is not an exception. Backend exceptions, transport
failure, resource limits, timeout, cancellation, and package/profile mismatch
remain typed distinct failures.

* Proof Normalization

SWI does not automatically expose the full normalized proof graph required by
StarLang for arbitrary queries.

Proof-required operations SHALL therefore use StarIntel-owned proof-carrying
wrappers that explicitly emit sufficient derivation evidence.

That evidence is normalized into:

#+begin_example
star.logic.derivation/1
#+end_example

Potential node kinds include source/session facts, question answers,
clause applications, goals, bindings, assumptions, contradictions, conclusions,
and budget truncation.

The adapter MUST NOT invent proof steps from debug/trace output.

* Cancellation and Budgets

Target controls include wall time, answer count, output bytes, inference limits
where applicable, proof nodes/bytes, and process/memory limits where deployment
can enforce them.

Cancellation escalation is:

#+begin_example
cooperative query cancellation
        |
        v
MQI / connection termination
        |
        v
worker process termination
        |
        v
fresh pinned replacement
#+end_example

A terminated or uncertain worker is never returned to the reusable pool.

* Failure Contract

Normalize at least:

- normal no-answer;
- invalid named operation;
- invalid parameter/type;
- semantic-profile/capability mismatch;
- package or mapping mismatch;
- engine build mismatch;
- timeout/resource limit;
- cancellation;
- transport failure;
- worker crash;
- proof unavailable;
- projection failure;
- state/reset isolation failure.

Native exception text may survive only as bounded diagnostic metadata.

* Target Capability Set

After fixture proof, SWI may advertise:

- typed projected facts;
- identity-preserving StarIntel projection;
- relational named queries;
- recursion;
- tabling;
- approved CLP(FD) profiles;
- bounded streaming answers;
- process isolation;
- normalized proof only for packages/wrappers that provide evidence.

Incremental tabling is gated. Production agenda/salience/RETE working-memory
claims are not part of the initial SWI contract.

* Security Invariants

1. No raw user Prolog goal crosses the worker boundary.
2. Only digest-locked StarIntel-owned packages and named operations execute.
3. Projected source documents remain immutable.
4. Projection preserves identity/provenance authority.
5. Session mutable facts are isolated.
6. Query inputs are typed and normalized before invocation.
7. Output/proof data is bounded and schema-validated.
8. Worker filesystem/environment exposure is minimized.
9. Secrets are excluded from generated packages/proofs/fixtures.
10. Hard-cancelled or uncertain workers are discarded.

* Approved Prototype Retirement

The SWI backend SHALL be implemented directly in final systems.

- No production SWI process manager, MQI wrapper, projection engine, named-operation dispatcher, proof normalizer, or capability descriptor may be prototype-owned.
- Temporary prototype call sites may only forward into =star-logic-adapter-swi= and contain no independent Prolog execution logic.
- New SWI fixtures/tests belong to final adapter/expert test systems.
- Superseded prototype SWI or generic logic implementations are deleted as callers migrate.
- Final SWI ASDF tests and Nix checks SHALL run without loading =starlang-prototype=.
- Once repository-wide port verification proves no product path requires =prototype/=, that directory SHALL be removed rather than retained as a fallback.

* Implementation Order

1. final SWI adapter and pinned worker/MQI shell;
2. exact version/build/capability handshake and named wrapper smoke test;
3. one real identity-preserving StarIntel object/document projection;
4. =solve=, =solutions=, =exists?= and normalized failures;
5. recursive and tabled profile fixtures;
6. cooperative/hard cancellation, dirty-worker replacement, reset/no-leak tests;
7. proof-carrying wrapper and normalized derivation;
8. CLP(FD) only after relational conformance is green;
9. delete superseded prototype implementation/tests during each migration slice.

* Acceptance Gate

Implementation is complete when:

1. =star-logic-adapter-swi= has final package ownership;
2. one real StarIntel object/document family projects without losing identity/provenance;
3. only compiler-declared named operations are callable;
4. =solve=/=solutions=/=exists?= obey STAR-LANG-009;
5. recursive/tabled fixtures pass under exact package/profile/build identity;
6. unsupported production semantics fail before execution;
7. answer duplicate/order policy is normalized correctly;
8. proof-required fixture emits =star.logic.derivation/1= through explicit evidence;
9. cancellation escalation and worker replacement are tested;
10. state does not leak across logical sessions/workers;
11. same-backend replay is deterministic;
12. descriptor advertises only fixture-proven capabilities;
13. no final SWI path loads =starlang-prototype= or files under =prototype/=.

* Footnotes and Glossary

- *Identity-preserving projection* — Backend-private relational representation that remains stably traceable to authoritative StarIntel identity and provenance.
- *Named operation* — Compiler/package-declared query entrypoint with a fixed typed contract; never an arbitrary Prolog goal.
- *Proof-carrying wrapper* — StarIntel-owned predicate/package operation that explicitly returns derivation evidence for normalization.
- *Dirty worker* — SWI process whose state cannot be proven clean after cancellation, crash, mismatch, or protocol failure and must therefore be discarded.
- *Prototype retirement* — Removal of transitional prototype ownership as final SWI systems become authoritative.
