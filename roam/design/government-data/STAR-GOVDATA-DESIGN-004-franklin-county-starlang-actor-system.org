* REVIEW Objective

Build the best possible actor system for the complete Franklin County government-data pilot, keyed by Census GEOID =39049=.

The system must discover and continuously acquire every applicable public route defined by the Ohio coverage contract. It must preserve raw evidence, normalize data without destroying source meaning, expose uncertainty and gaps, and support replay and historical reconciliation.

The later violent-offender website is explicitly downstream and out of scope. This design is source-neutral. It does not classify people, determine dangerousness, rank individuals, or define publication rules.

* REVIEW Language Decision

Use StarLang for the complete application-level actor system:

- domain and supervision declarations
- actor definitions
- typed commands, events, results, and checkpoints
- authority ownership
- capability manifests
- routing and dispatcher declarations
- restart and overload policy
- workflows and acceptance gates
- adapter manifests and source-family bindings
- deterministic fixtures

Compile StarLang to Common Lisp. Use Common Lisp libraries for runtime primitives, network protocols, parsing, compression, hashing, persistence, and process control.

"StarLang entirely" therefore means that the Franklin application is authored and reviewed in StarLang. It does not mean reimplementing TLS, HTTP, ZIP, XML, PDF extraction, or operating-system process primitives in the language surface.

* REVIEW Repository Decision

The design and evidence remain in =starintel-auto-research=.

The reusable compiler and runtime should live in a new repository, provisionally named =lost-rob0t/star-lang=, with independently versioned ASDF systems. Franklin-specific profiles and source adapters remain separate from the generic runtime.

=starintel-server= later consumes released StarLang runtime systems and hosts the production government-data domain. It must not become the source repository for the language compiler.

Creating the runtime repository is an implementation prerequisite, not a prerequisite for completing this design.

* REVIEW Scope

** Included

- Franklin County government and county components
- countywide systems delegated to vendors
- county courts and clerks where public access is authorized
- county offices, boards, commissions, authorities, and dependent components
- state systems that index or publish Franklin County records
- official websites, APIs, feeds, bulk files, GIS services, document repositories, and public vendor systems
- current and historical discovery
- raw artifact custody and provenance
- route applicability and coverage assessment
- independent review
- refresh, migration detection, replay, and reconciliation

** Deferred

- public website implementation
- offender classification or scoring
- identity resolution beyond what a source explicitly publishes
- facial recognition
- private-data brokers
- bypass of authentication, CAPTCHA, fees, or access controls
- automatic public-records request sending
- automatic publication of person records
- production deployment

* REVIEW Actor Catalog

** Control actors

*** Franklin Domain Supervisor

Owns startup order, child generations, restart strategy, readiness, degradation, and terminal shutdown.

Uses =rest-for-one= across authority groups and =one-for-one= inside worker pools. A failed authority does not silently reuse stale handles or lease generations.

*** Franklin Ingress

Validates externally submitted StarLang commands and capability scopes. It rejects unknown schema versions, missing revision bindings, unbounded jobs, and direct canonical-write requests from adapters.

*** Franklin Run Coordinator

Creates immutable run revisions, expands the selected route plan into durable jobs, tracks cancellation, and reports run-level completion without treating mailbox state as durable work state.

*** Manifest Authority

Serializes actor, adapter, capability, normalization, and source-family manifest revisions. A running attempt binds exact manifest hashes.

*** Policy Snapshot Authority

Stores the exact applicability, acquisition, retention, review, and publication-neutral policy revisions used by each run.

** Identity actors

*** Jurisdiction Identity Authority

Is the sole writer for Franklin County's canonical government identity and validity intervals.

*** Component Registry Authority

Owns county departments, elected offices, boards, commissions, courts, clerks, authorities, dependent organizations, predecessors, successors, and unresolved components.

*** Domain Candidate Resolver

Produces candidate official domains, subdomains, redirects, certificate names, archived domains, and vendor links. It cannot verify them.

*** Delegation Verifier

Confirms whether an external vendor deployment is officially delegated by an authorized county or component source. Verification requires evidence and validity dates.

** Discovery actors

*** Search Plan Authority

Owns immutable route and subfamily search plans. Each plan records required queries, paths, discovery techniques, bounds, expiry, and prior negative findings.

*** Route Planner

Maps the sixteen Ohio route requirements to applicable Franklin components and expected source families.

*** Web Surface Enumerator

Enumerates homepages, robots files, sitemaps, feeds, calendars, developer pages, data inventories, downloads, linked portals, and machine-readable metadata under fixed depth and request limits.

*** Platform Fingerprint Pool

Detects ArcGIS, OGC, CKAN, Socrata, Legistar, Granicus, CivicClerk, Municode, eCode, ASP.NET forms, static directory indexes, embedded JSON applications, document repositories, and unknown platform signatures.

*** Historical Source Locator

Finds retired domains, archive captures, predecessor systems, old path structures, historical bulk files, and migration evidence.

*** Source Profile Proposal Pool

Combines discovery evidence into immutable source-profile and deployment-revision proposals. It cannot approve them.

** Acquisition actors

*** Adapter Registry Authority

Owns the exact adapter manifests eligible for Franklin runs, including capability grants, supported source families, limits, parser versions, and runtime hashes.

*** Acquisition Dispatcher

Routes durable job revisions to compatible adapters. It may not invent capabilities or loosen job limits.

*** Rate and Lease Authority

Owns host, vendor, tenant, credential, and source concurrency. Every attempt receives a lease generation and fencing token. Results from expired or superseded leases are rejected.

*** Generic Adapter Pools

Provide reusable HTTP metadata, HTML, feed, JSON, XML, CSV, spreadsheet, PDF, ArcGIS, OGC, static-directory, ASP.NET-form, embedded-JSON, browser-process, and archive adapters.

*** Ohio Adapter Pools

Implement stable Ohio-specific semantics only when generic adapters cannot express pagination, identifiers, temporal meaning, or record linkage correctly.

*** Process Worker Bridge

Runs browser, PDF extraction, OCR, archive, and other dependency-heavy tools as supervised subprocesses with explicit stdin/stdout protocols, resource ceilings, and no direct canonical-ledger access.

** Evidence actors

*** Raw Artifact Authority

Is the sole committer of immutable raw artifacts and non-retained-source records. Atomic commit precedes normalization.

*** Retrieval Event Authority

Owns request/response metadata, timestamps, locators, redirects, status, headers, byte counts, truncation, lease identity, and source-profile revision bindings.

*** Content Hash Worker Pool

Calculates approved cryptographic hashes and deduplication fingerprints without deciding canonical identity.

*** Artifact Metadata Extractor

Extracts content type, encoding, archive members, document metadata, page count, row count, geometry metadata, and parser warnings.

*** Provenance Validator

Rejects normalized records that cannot resolve to exact retrieval events, artifacts or explicit non-retained-source records, locators, hashes, adapters, and source revisions.

** Normalization actors

Each normalizer emits candidate StarIntel records and relations. None writes canonical government or assessment state directly.

*** Identity and Organization Normalizer

Normalizes offices, departments, boards, authorities, officials as explicitly published, organizational relationships, validity intervals, and source-provided identifiers.

*** Meeting and Legislation Normalizer

Handles agendas, packets, minutes, calendars, ordinances, resolutions, votes, recordings, and agenda-item relationships.

*** Finance and Procurement Normalizer

Handles budgets, audits, checkbooks, payroll, debt, grants, solicitations, bids, awards, contracts, purchase orders, vendors, and payments.

*** Property and Land Normalizer

Handles parcels, assessment, tax, recorder indexes, deeds where publicly available, ownership fields as source-published, and geospatial crosswalks.

*** Court and Docket Normalizer

Handles courts, case indexes, dockets, filings, dispositions, schedules, opinions, and clerk metadata without inferring guilt or offender status.

*** Election Normalizer

Handles offices, candidates, committees, campaign-finance records, precincts, ballots, and results.

*** Safety and Justice Normalizer

Handles public incident, jail, inspection, enforcement, and justice-system records while preserving source status, allegation, charge, disposition, and temporal distinctions.

*** Permit and Planning Normalizer

Handles permits, licenses, planning cases, zoning, development, environmental records, inspections, and code-enforcement records.

*** Records and Retention Normalizer

Handles public-records policies, request portals, retention schedules, contacts, fees, exemptions, and response metadata.

** Assessment actors

*** Route Assessment Authority

Is the sole writer for revisioned route assessments. An assessment binds the exact jurisdiction, route, subfamily, applicability contract, source profiles, search plan, evidence, gaps, policy snapshot, reviewer decision, and validity interval.

*** Applicability Decision Authority

Owns =applicable=, =not-applicable=, =unresolved=, and =superseded= decisions. =not-applicable= requires positive evidence and an expiry or validity condition.

*** Independent Review Authority

Reviews source verification, route coverage, negative findings, parser warnings, contradictions, and provenance without sharing the proposing actor's state or random seed.

*** Coverage Ledger Authority

Appends coverage events and materialized coverage views. It never reduces coverage to one boolean.

*** Gap Authority

Owns missing, inaccessible, ambiguous, authentication-required, fee-required, records-request-required, parser-unsupported, OCR-required, historical-gap, and source-retired gaps.

** Operations actors

*** Refresh Scheduler

Schedules source refresh, profile re-verification, negative-finding expiry, archive checks, and full reconciliation using durable schedule revisions.

*** Migration Detector

Detects redirects, domain changes, vendor changes, identifier changes, path migrations, schema drift, and source retirement.

*** Reconciliation Auditor

Compares pages, cursors, counts, dates, hashes, archive members, geometry totals, and normalized outputs to detect silent loss or duplication.

*** Quarantine Authority

Owns terminally failed attempts and malformed artifacts. Quarantine records preserve bounded diagnostic context and never echo protected credentials.

*** Health and Metrics Actor

Reports queue depth, oldest durable job, lease pressure, throughput, error classes, replay counts, artifact lag, normalization lag, review lag, and coverage freshness.

* REVIEW Proposed StarLang Surface

This is a required compiler extension, not a claim that the current compiler already accepts every form.

#+begin_src lisp
(domain franklin-county-government-data
  (:jurisdiction "gov:us:oh:franklin-county")
  (:geoid "39049")
  (:runtime star.actor/runtime-v1)
  (:policy ohio-government-data/policy-v1)

  (authority route-assessment
    (:state revisioned-journal)
    (:dispatcher :coverage)
    (:mailbox (bounded 2048 :overflow :reject))
    (:writes route-assessment-revision))

  (authority raw-artifact
    (:state content-addressed-artifact-store)
    (:dispatcher :evidence)
    (:mailbox (bounded 1024 :overflow :backpressure)))

  (pool platform-fingerprint
    (:size 16)
    (:dispatcher :network)
    (:restart (one-for-one :max 5 :within 60))
    (:capabilities (network-read dns-read tls-metadata-read)))

  (workflow acquire-route
    (receive acquire-route-command/v1)
    (bind-revisions jurisdiction profile search-plan policy adapter)
    (persist job-revision)
    (lease rate-and-lease)
    (attempt selected-adapter)
    (commit raw-artifact retrieval-event)
    (normalize candidate-records)
    (validate provenance)
    (propose route-assessment)
    (review independent-review)
    (append coverage-event)))
#+end_src

* REVIEW Message Contracts

All identifiers refer to immutable revisions unless explicitly named =logical-*=.

** =franklin-command/v1=

Required fields:

- command ID
- command kind
- jurisdiction ID and revision
- run ID and revision
- route and subfamily
- source-profile ID and revision where known
- deployment ID and revision where known
- search-plan ID and revision
- applicability-contract revision
- policy-snapshot revision
- adapter-manifest revision where selected
- fixed request, byte, object, time, depth, and concurrency bounds
- cancellation ID
- idempotency key
- issued-at timestamp

** =franklin-job/v1=

A durable logical job. It never contains a lease ID before lease issuance.

** =franklin-attempt/v1=

A single execution attempt binding:

- job revision
- attempt ID
- adapter manifest revision
- runtime build hash
- lease ID
- lease generation
- fencing token
- start deadline
- execution deadline

** =franklin-result/v1=

Binds job and attempt IDs, terminal status, artifact and retrieval-event IDs, checkpoints, counts, truncation, warnings, typed failures, and retry advice.

** =franklin-event/v1=

Append-only lifecycle, authority, coverage, review, migration, and health event.

** =franklin-checkpoint/v1=

Binds exact job, attempt, source, cursor, page, artifact, and adapter revisions. A checkpoint from an expired fencing token cannot advance durable state.

* REVIEW Delivery and State Semantics

- At-least-once dispatch.
- No exactly-once claim.
- Durable jobs exist outside actor mailboxes.
- Mailboxes are bounded.
- Idempotency is enforced at every authority write.
- Every retry is a new attempt.
- Fencing tokens prevent stale attempts from committing.
- Raw artifact and retrieval event commit before candidate normalization.
- Candidate records remain separate from canonical acceptance.
- Authority state replays before readiness.
- Cancellation uses one stable cancellation ID through all descendants.
- Partial results require explicit truncation and checkpoint state.
- Source retirement creates tombstones and successor links.

* REVIEW Dispatcher Plan

| Dispatcher | Work | Blocking permitted |
|------------+------+--------------------|
| =:control= | ingress, supervision, readiness, cancellation | no |
| =:authority= | serialized authority writes | short bounded storage calls only |
| =:network= | HTTP, DNS, feeds, APIs, downloads | yes, bounded |
| =:parse= | HTML, JSON, XML, CSV, document parsing | CPU bounded |
| =:evidence= | artifact commit, hashing, provenance | bounded storage and CPU |
| =:coverage= | assessments, reviews, ledger, gaps | no network |
| =:process= | browser, PDF, OCR, archive workers | supervised subprocess only |

* REVIEW Supervision

Root strategy: =rest-for-one= in this startup order:

1. control and policy authorities
2. identity authorities
3. discovery authorities
4. acquisition and lease authorities
5. evidence authorities
6. normalization pools
7. assessment authorities
8. operations actors

Worker pools use =one-for-one=. Authority restart budgets are stricter than worker budgets. Configuration-invalid, schema-unsupported, journal-corrupt, and capability-invalid failures stop the affected subtree and degrade readiness instead of restarting indefinitely.

* REVIEW Acceptance Gates

Franklin is not accepted merely because all jobs stopped running.

Required gates:

- every route and required subfamily has a reviewed terminal assessment revision
- every =not-applicable= decision has evidence and expiry or validity conditions
- every verified source binds official or delegated evidence
- every accepted normalized record resolves to complete provenance
- every source has current refresh and reconciliation strategy
- no successful attempt hides truncation, stale fencing, parser warnings, or missing artifacts
- replay from an empty mailbox and durable journal reproduces the same accepted authority state
- authority crash after artifact commit but before normalization recovers without duplicate canonical records
- source migration fixture creates successor links and preserves old locators
- expired negative findings reopen discovery
- independent review catches seeded false-positive official-domain and delegated-vendor candidates
- no future website or offender-specific assumption is embedded in the ingestion schema

* REVIEW Blockers

1. Parent government-data protocol is not revision-complete.
2. Current actor runtime does not yet provide every required bounded-mailbox, OTP-style supervision, durable replay, fencing, capability, and readiness primitive.
3. StarLang compiler does not yet expose the complete actor surface proposed here.
4. A dedicated StarLang runtime repository does not yet exist in the connected repositories.
5. Several document and browser formats require process adapters before pure Common Lisp replacements are justified.
6. Franklin source profiles and applicability decisions have not yet been researched to reviewed terminal state.

* REVIEW Non-Goals for Ecosystem Work

Improving the Common Lisp ecosystem does not justify unnecessary rewrites.

The project should:

- upstream portable fixes when maintainers are receptive
- create small reusable ASDF systems with narrow contracts
- retain compatibility layers instead of hard forks when possible
- fork only after a documented semantic or maintenance blocker
- pin exact revisions and preserve licenses
- publish deterministic conformance suites
- avoid making Franklin-specific behavior part of generic libraries

* REVIEW Decision

Proceed with StarLang as the authored actor language and Common Lisp as the implementation substrate.

Create the reusable runtime as an independent library repository before production implementation. Use the Franklin pilot as the first complete conformance target for supervision, durable execution, provenance, adapter isolation, revisioned review, and replay.
