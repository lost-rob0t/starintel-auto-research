* Question

Which host should own parsing, compilation, diagnostics, local execution, and recovery while generated manifests, actors, messages, documents, and bindings stay language-neutral?

Every candidate must preserve the same email-enumeration fixture, typed documents, persistent/transient distinction, actor/tool/agent boundaries, named stages, normalized plan, three candidates, two found addresses, one persisted final review, inspectable expansion, and benchmark entry point.

* Implemented Evidence

** Common Lisp

The existing Common Lisp prototype already covers the shared fixture plus the closed =.star= parser, normalized IR, semantic checks, canonical JSON, generated bindings, lifecycle envelopes, deterministic dispatch, transport settlement, standalone execution, optional cl-gserver binding, remoting, durable journals, and document constructors.

** Embedded Racket

This pass adds an equivalent Racket runtime and test suite under =prototypes/star-lang/racket/embedded/=. It preserves document validation, registries, normalized plans, deterministic execution, persistence rejection, expected output, and a smoke benchmark.

** Dedicated Racket Language

This pass adds an installable =#lang starintel= collection, an example module, tests, and =raco expand= evidence. The dedicated language reuses the embedded runtime so the experiment isolates reader/module packaging rather than creating a second execution engine.

** Guile Scheme

This pass adds a Scheme baseline using =syntax-rules=, vectors, and association lists. It preserves the same normalized plan and final output while showing where portability becomes implementation-specific.

** Continuous Integration

=.github/workflows/star-lang-comparison.yml= installs Racket and Guile, checks form balance, runs both Racket modes, captures language expansion, and runs the Scheme suite. Smoke timing remains diagnostic only; hosted CI does not justify performance claims.

* Findings

** Common Lisp

Strengths:

- complete existing runtime evidence rather than a fixture-only prototype;
- conditions and restarts match resumable operator workflows;
- closed parser already prevents Common Lisp reader leakage;
- direct integration with existing StarIntel Common Lisp components;
- runtime-neutral IR and standalone execution already exist.

Costs:

- source tooling must be built;
- current files need normal ASDF packaging;
- some digest and URL adapters still shell out;
- the closed surface needs generated grammar and language-server support.

** Racket

Racket has the strongest language construction, module, expansion, and editor-tooling path. It is the best conformance and syntax oracle. It is not selected as the production host because it would duplicate the existing StarIntel runtime, actor integration, lifecycle machinery, and recovery implementation.

** Scheme

Scheme proves the declarative core can remain small. It loses its portability advantage at structured diagnostics, modules, networking, clocks, recovery, and actor integration. A production implementation would become Guile-specific or require a larger portability layer than the language core.

* Decision

Select Common Lisp as the Star-Lang implementation host.

Retain Racket as a conformance implementation, syntax/expander oracle, and possible language-service frontend. Retain Scheme as a minimal portability witness.

Common Lisp is the host, not the wire format. Normalized IR, canonical JSON manifests, generated bindings, and =star-message-v1= remain portable contracts.

* Hard Boundaries

1. Star-Lang source is not arbitrary Common Lisp.
2. No unrestricted =EVAL= or reader evaluation enters the source path.
3. Source identifiers remain strings until validated.
4. Core IR retains runtime-neutral operations.
5. =send= becomes =tell= only in the cl-gserver adapter.
6. Research nodes never become StarIntel object types, predicates, fields, or schema extensions.
7. Field access remains explicit; dot syntax is not introduced.
8. Auto-dig and Quasar consume Star-Lang contracts; neither defines them.
9. Actor liveness affects routing, not program validity.
10. The portable manifest remains the cross-language source of truth.

* Falsifiers

Reopen host selection if Common Lisp cannot preserve exact source spans and origin chains, cannot become a normal testable system, leaks host values into portable artifacts, or if Racket demonstrates at least a 30 percent reduction in maintained compiler/runtime code while preserving the same execution, recovery, adapters, and artifacts.
