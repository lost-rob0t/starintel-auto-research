* Decision

Quasar Actor Studio MUST show both browser actor definitions and Common Lisp native actor instances.

Native actor visibility MUST be implemented as a realization of the already-defined =LocalLispActorRuntime= discovery contract. Quasar MUST NOT create a second actor framework, duplicate Sento supervision, or serialize live Lisp actor objects into the browser.

The first approved slice is *read-only native inventory + inspectable runtime metadata*. Lifecycle control may be added later only through explicit capability contracts.

* Architecture

#+begin_example
                        Quasar Actor Studio
                               |
                +--------------+--------------+
                |                             |
                v                             v
      BrowserActorRuntime            LocalLispActorRuntime
                |                             |
                v                             v
     BUILTIN_ACTORS + custom         actor.list / actor.inspect
        browser manifests                     |
                                              v
                                  native actor projection registry
                                              |
                                              v
                                         Sento actors
#+end_example

The Actor Studio merges two presentation sources but preserves two authorities.

* Common Lisp Native Actor Registry

Quasar MUST maintain an explicit registry/projection of native actors that are intentionally public to the UI.

The registry is not a replacement for Sento. It is metadata attached to Quasar-owned actor creation/lifecycle boundaries.

Each public actor entry MUST include:

#+begin_src json
{
  "schema_version": "1.0",
  "actor_id": "quasar.native.control-plane",
  "runtime_id": "quasar.local.sbcl",
  "runtime_kind": "local-native",
  "origin": "quasar-control-plane",
  "role": "command-authority",
  "label": "Quasar control plane",
  "path": "/user/quasar-control-plane",
  "parent_id": null,
  "state": "running",
  "capabilities": ["inspect"],
  "metadata": {}
}
#+end_src

Required semantics:

- =actor_id= is a stable Quasar identity, not a printed Lisp object and not a random Sento path;
- =runtime_id= identifies the connected Lisp runtime instance/class;
- =runtime_kind= is =local-native= for this design;
- =origin= is an authority/source discriminator controlled by the adapter, never by browser actor manifest content;
- =role= is a stable semantic class such as =command-authority=, =supervisor=, =router=, =worker=, =normalizer=, or =forwarder=;
- =path= is diagnostic runtime metadata and MUST NOT become the durable actor identity;
- =state= is projected runtime state and MUST not be guessed by the browser;
- =capabilities= defines which UI controls may be rendered;
- =metadata= is explicitly allowlisted and scrubbed.

* Registration Lifecycle

The registry MUST be updated at the same boundaries that create/replace/stop Quasar-owned actors.

At minimum:

1. =start-control-plane= registers =quasar.native.control-plane= after successful actor creation;
2. =stop-control-plane= marks/removes the actor before or during actor-system shutdown;
3. =start-melissa-subsystem= registers the Melissa supervisor, router, workers, normalizer, forwarder, and bridge entries that are intentionally public;
4. Melissa worker replacement updates the same stable worker slot identity rather than leaking random replacement names as new durable actors;
5. =stop-melissa-subsystem= removes or marks stopped subsystem entries deterministically.

A stale registry entry claiming =running= after actor termination is a correctness failure.

* Stable Identity Rule

Random Sento actor names may remain useful runtime paths, but stable Quasar actor IDs MUST be deterministic at the semantic slot level.

Example Melissa identities:

#+begin_example
quasar.native.melissa.supervisor
quasar.native.melissa.router
quasar.native.melissa.normalizer
quasar.native.melissa.forwarder
quasar.native.melissa.worker.0
quasar.native.melissa.worker.1
...
#+end_example

If worker 1 is restarted, its =actor_id= remains =quasar.native.melissa.worker.1= while =path= and an optional generation counter may change.

* Protocol Contract

The native actor projection MUST travel through the existing Common Lisp control-plane command envelope rather than an unrelated ad-hoc REST island.

First-slice commands:

#+begin_example
actor.list
actor.inspect
#+end_example

=actor.list= returns a bounded array of public descriptors.

=actor.inspect= accepts a stable =actor_id= and returns the descriptor plus bounded allowlisted runtime detail.

If the existing capability-discovery surface exposes command names, these commands MUST appear only when available.

Recommended list response:

#+begin_src json
{
  "runtime": {
    "runtime_id": "quasar.local.sbcl",
    "runtime_kind": "local-native",
    "connected": true
  },
  "actors": [
    {
      "schema_version": "1.0",
      "actor_id": "quasar.native.control-plane",
      "origin": "quasar-control-plane",
      "role": "command-authority",
      "label": "Quasar control plane",
      "state": "running",
      "capabilities": ["inspect"]
    }
  ]
}
#+end_src

The response MUST be bounded by actor count, string lengths, metadata depth/size, and total encoded response size.

* LocalLispActorRuntime Adapter

The browser MUST gain one adapter responsible for native actor discovery.

Responsibilities:

- discover whether =actor.list= is supported;
- request actor inventory through the existing control-plane client transport;
- normalize protocol descriptors into Actor Studio view models;
- attach trusted origin/runtime labels based on the transport/adaptor, not remote display strings alone;
- refresh after reconnect and relevant runtime lifecycle events;
- expose disconnected/error states without deleting browser actor definitions;
- never expose a JavaScript source editor for native instances.

The adapter should be the concrete realization of the existing =LocalLispActorRuntime= contract rather than a new parallel API family.

* Actor Studio Presentation

Actor Studio MUST render a unified list with explicit runtime/origin distinctions.

Minimum visible categories:

- =Browser / built-in=;
- =Browser / custom=;
- =Common Lisp / native=.

For a native actor, the detail surface SHOULD show:

- label;
- stable actor ID;
- runtime;
- role;
- lifecycle state;
- parent actor;
- runtime path;
- declared capabilities;
- safe metadata;
- connection state.

The code editor MUST be absent or replaced by a read-only runtime overview for native actors.

Native actors MUST NOT be clonable into browser JavaScript by default. A future explicit export/template feature would require a separate design because an actor instance is not equivalent to source code.

* Browser Standalone Requirement

This feature MUST preserve Quasar's standalone browser behavior.

When the Lisp runtime is unavailable:

- browser built-ins remain listed and runnable according to current rules;
- browser custom actors remain editable/runnable according to current rules;
- the native category reports disconnected/unavailable;
- no fake cached native actor is presented as currently running;
- no browser fallback claims to provide native supervision semantics.

* Native Action Capability Rule

The first slice MUST expose only read-only inventory/inspection unless an actor explicitly advertises a tested control capability.

The UI MUST NOT render pause/resume/restart/send controls merely because the actor exists.

Future controls require:

- an explicit capability name;
- a versioned command contract;
- authorization semantics;
- lifecycle/error semantics;
- actor-type support definition;
- regression tests.

* Event and Refresh Strategy

The first slice may refresh inventory:

- on Actor Studio open;
- on runtime connection/reconnection;
- after an explicitly known native lifecycle operation;
- on a bounded manual refresh.

If Quasar already has a suitable runtime event stream, later implementation may publish actor lifecycle events through it. A new watcher/daemon is not required for this feature because the Lisp process already owns actor lifecycle.

* Metadata Safety Boundary

Native inspection MUST use an allowlist.

Never expose by default:

- Lisp object printer output containing implementation details;
- closures/functions;
- mailbox message bodies;
- credentials, API keys, tokens, headers, or connection strings;
- filesystem secrets or environment variables;
- arbitrary plugin objects;
- stack traces containing sensitive values;
- unbounded actor state.

Safe fields include stable identifiers, role, state, parent relationship, sanitized path, generation/restart counters, bounded queue depth when intentionally supported, and capability names.

* quasar / quasar-ui Source-of-Truth Gate

Before implementation modifies the UI, maintainers MUST determine whether =quasar/frontend= or =quasar-ui= is the canonical source for the current Actor Studio code.

Implementation MUST land in the canonical source and use the existing synchronization/migration mechanism for the other copy. Two independently edited actor contracts are rejected.

* Adversarial Review

** A. Browser actor spoofs a native actor

Attack: a custom browser actor chooses ID =quasar.native.control-plane= and label =Common Lisp native=.

Failure mode: UI visually grants native authority based on manifest-controlled strings.

Decision: runtime/origin trust is attached by the adapter/source collection, not inferred from =actor_id= prefix or label. Duplicate IDs across authority domains are either namespaced internally or rejected at merge time with explicit conflict UI.

** B. Registry leaks secrets

Attack/failure: =actor.inspect= serializes actor slots, closures, config objects, environment variables, transport credentials, or mailbox content.

Decision: descriptors and inspection data are constructed from an explicit allowlist. No generic =slot-value= dump or object printer is permitted.

** C. Stale actor shown as running

Failure: worker restarts or subsystem shutdown leave stale metadata.

Decision: registry mutation occurs at create/replace/stop boundaries. Tests intentionally restart and stop actors and assert inventory state.

** D. Random actor path becomes durable identity

Failure: Melissa worker replacement produces a new random path and the UI treats it as a brand-new semantic actor every restart.

Decision: stable semantic =actor_id= is separate from diagnostic =path=. Optional =generation= records replacement without changing stable identity.

** E. UI exposes unsupported controls

Failure: presence in the actor list causes generic pause/restart buttons that Sento actors do not uniformly support.

Decision: controls are capability-driven. First slice is read-only inventory/inspect.

** F. Internal actor topology overexposure

Attack: actor enumeration reveals implementation actors that should not be operator-facing.

Decision: only explicitly registered public actor projections are returned. The system does not recursively dump all Sento internals.

** G. Native inventory breaks standalone Quasar

Failure: Actor Studio assumes =actor.list= exists and crashes or disables all actors when the Lisp control plane is offline.

Decision: native inventory is an optional runtime source. Browser actor surfaces remain independently functional.

** H. N+1 inspect storm

Failure: UI lists 1,000 actors then individually calls =actor.inspect= for every row.

Decision: =actor.list= returns all fields required for the list view in one bounded response. Inspection is on-demand for a selected actor.

** I. Unbounded actor count or metadata DoS

Failure: a plugin/subsystem registers excessive actor entries or giant strings and freezes the UI.

Decision: registry and protocol enforce per-runtime actor-count bounds, string/metadata bounds, pagination or truncation semantics when required, and total response-size limits.

** J. quasar and quasar-ui drift

Failure: one UI copy gains native actors while the other keeps browser-only assumptions.

Decision: implementation must use the documented source-of-truth/sync path and add a drift check where practical.

* Required TDD and Verification Gates

Implementation is TDD-first.

** Common Lisp tests

1. startup registers =quasar.native.control-plane=;
2. list descriptor is valid, bounded, and JSON-safe;
3. actor path is diagnostic and stable ID is independent of path;
4. stopping control plane removes/marks native actor unavailable;
5. Melissa startup registers intended public actor roles;
6. Melissa worker replacement preserves stable worker slot ID and changes generation/path as expected;
7. Melissa stop removes/marks subsystem actors stopped;
8. inspect rejects unknown actor ID with a stable protocol error;
9. metadata scrub test proves credentials/config secrets are absent;
10. actor list appears in capability discovery only when installed.

** Frontend tests

11. Actor Studio merges browser built-ins, browser custom actors, and native descriptors;
12. native actor receives a trusted Common Lisp/native badge from source authority;
13. native actor has no editable JavaScript source control;
14. browser custom actor cannot spoof trusted native origin;
15. disconnected native runtime leaves browser actors usable;
16. reconnect refreshes native inventory;
17. list rendering does not trigger per-row inspect requests;
18. duplicate/conflicting identifiers fail visibly rather than silently overwriting entries.

** Real-stack E2E

19. start the actual Common Lisp control plane and Vite UI;
20. open Actor Studio;
21. assert the native =Quasar control plane= actor is visible;
22. assert it is marked Common Lisp/native and read-only;
23. if Melissa is enabled in the test fixture, assert its supervisor/worker entries appear;
24. stop/disconnect the runtime and assert browser actors remain available while native state becomes unavailable.

** Exact-head verification

Before merge:

- rebase/reconcile onto current =quasar= main;
- run Common Lisp unit/integration tests;
- run frontend unit/component tests;
- run the real Lisp/Vite Playwright gate;
- run existing actor-manager and target/Melissa regressions;
- run repository startup/native-library CI gates;
- verify exact PR head SHA after the final test run.

* Non-Goals

- No second actor framework.
- No generic Sento object dump API.
- No replacement of browser actors.
- No requirement that Quasar browser mode always have a Lisp runtime connected.
- No actor source-code extraction from running Lisp actors.
- No arbitrary actor message console in the first slice.
- No pause/resume/restart controls without explicit capability contracts.
- No direct graph mutation by native actor inventory/inspection endpoints.
- No independent duplicate implementation in =quasar-ui= and =quasar/frontend=.

* Rejected Alternatives

- *Only add hard-coded Lisp rows in React.* Rejected: lies about runtime state and does not discover real actors.
- *Dump every Sento actor by traversing internals.* Rejected: unstable API, unsafe exposure, no product-level semantics.
- *Represent Lisp actors as JavaScript actor manifests.* Rejected: actor instances and browser source manifests are different authority/types.
- *Create a separate actor database just for the UI.* Rejected: duplicates lifecycle authority and creates staleness problems.
- *Move all browser actors to Lisp before showing anything.* Rejected: unnecessary scope expansion and breaks the standalone requirement.
- *Enable generic lifecycle buttons immediately.* Rejected: capability and authorization semantics are not yet sufficiently specified.

* Implementation Order After Approval

1. add failing Common Lisp native-registry/protocol tests;
2. implement minimal registry/projection and =actor.list=/=actor.inspect=;
3. register control-plane actor;
4. integrate Melissa registration/replacement/stop boundaries;
5. add failing frontend adapter/Actor Studio tests;
6. implement =LocalLispActorRuntime= adapter and merged presentation model;
7. render native read-only runtime details and origin badges;
8. add real-stack E2E;
9. reconcile =quasar-ui= through the canonical sync path;
10. adversarial/exact-head verification before merge.
