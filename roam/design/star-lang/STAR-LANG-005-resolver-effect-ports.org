* Decision

StarLang SHALL remove direct process execution from resolver semantics by
introducing injected fetch and digest ports.

The architecture is:

#+begin_example
source import request
        |
        v
resolver core
  |         |
  |         +--> digest port --> compatibility or native digest adapter
  |
  +------------> fetch port  --> compatibility or native HTTPS adapter
        |
        v
verified content-addressed cache
        |
        v
closed StarLang reader -> compiler -> runtime
#+end_example

The compiler, macro expander, deterministic dispatcher, and runtime SHALL NOT
own fetch/digest effect ports. Resolver/build operations own them.

* Port protocol

The first implementation may use CLOS generic functions or function-bearing
structures. The semantic contract is more important than the dispatch mechanism.

** Digest port

Required operations:

#+begin_src lisp
(digest-file port pathname :algorithm :sha256)
(digest-octets port octets :algorithm :sha256)
#+end_src

Requirements:

- SHA-256 is required by protocol v1;
- result is canonical =sha256:<64 lowercase hex digits>=;
- unsupported algorithms signal a typed resolver dependency/configuration
  failure;
- the port never decides whether a digest matches an import declaration;
- expected/actual comparison remains resolver-core policy.

** Fetch port

Required operation, conceptually:

#+begin_src lisp
(fetch-to-file port
               url
               temporary-path
               :maximum-bytes maximum-source-bytes
               :maximum-redirects 5
               :connect-timeout 10
               :read-timeout 10
               :deadline 60
               :proxy nil)
#+end_src

The initial interface SHOULD fetch to the caller-owned temporary pathname rather
than return an unbounded body. This preserves current atomic cache promotion and
lets adapters enforce limits while streaming.

Return metadata is portable data:

#+begin_src lisp
(:requested-uri "https://specs.example/library.star"
 :final-uri "https://cdn.example/library.star"
 :status 200
 :bytes 4096
 :redirect-count 1
 :headers (...))
#+end_src

The resolver must not depend on a Dexador response object, socket, stream, or
implementation-specific condition.

* Resolver context

Resolver entry points SHALL accept an explicit context object or equivalent
keyword group carrying effects and policy.

Conceptual shape:

#+begin_src lisp
(make-resolver-context
 :fetch-port fetch-port
 :digest-port digest-port
 :allow-network nil
 :cache-directory cache
 :maximum-source-bytes (* 16 1024 1024)
 :maximum-redirects 5
 :connect-timeout 10
 :read-timeout 10
 :deadline 60
 :proxy nil)
#+end_src

Nested import resolution inherits the same context. It must not recreate
adapters or consult ambient process state.

* Default behavior

During Phase 1, compatibility defaults MAY wrap the existing =curl= and
=sha256sum= behavior so callers remain backward compatible.

However:

- those process calls live only in compatibility adapter functions/modules;
- resolver-core functions invoke only the port protocol;
- fake ports are first-class for tests;
- compatibility adapters are explicitly transitional.

After Phase 2, native Common Lisp adapters become defaults and normal resolution
no longer requires shell executables.

* Cache algorithm

The content-addressed cache algorithm remains stable.

#+begin_example
expected digest
  -> canonicalize digest
  -> compute final digest-addressed cache pathname
  -> if final file exists:
       enforce size
       digest through digest port
       return only on exact match
       otherwise delete invalid cache file
  -> require network permission before fetch
  -> allocate temporary path in same cache directory
  -> fetch port writes bounded content to temporary path
  -> enforce final source size defensively
  -> digest temporary path through digest port
  -> reject mismatch
  -> rename temporary path to final digest-addressed path
  -> parse only verified final content
#+end_example

Temporary cleanup runs on every failure path.

* Network-disabled invariant

=:allow-network nil= has a strict meaning:

- no fetch-port operation may occur;
- a valid digest-addressed cached artifact may be reused after size and digest
  verification;
- a missing remote artifact signals =network-disabled-error=;
- local =:path= imports remain available because they are filesystem resolution,
  not remote fetch.

Tests SHALL use a fetch port that fails if invoked to prove this property.

* Security policy

** URL and redirects

- only =https://= import URLs are accepted;
- each redirect location is parsed and checked before the next request;
- a redirect to HTTP or another scheme fails;
- maximum redirects is explicit and finite;
- TLS certificate verification cannot be disabled by StarLang source.

** Proxy

The resolver SHALL NOT silently inherit =HTTP_PROXY=, =HTTPS_PROXY=, or a client
library's default proxy. A proxy is used only when supplied through trusted
resolver configuration.

** Bounds

- response byte limit is enforced while receiving data;
- connect timeout is finite;
- read timeout is finite;
- overall fetch deadline is finite;
- size and digest are checked again before final cache promotion.

** Integrity ordering

Remote bytes SHALL NOT reach StarLang parsing, macro expansion, semantic
validation, or compilation until expected digest verification succeeds.

* Failure contract

Public resolver failures remain StarLang conditions.

Phase 1 should preserve existing categories and introduce only categories that
add stable meaning. Recommended hierarchy additions:

#+begin_example
loader-error
  dependency-error
  import-error
  digest-error
  network-disabled-error
  fetch-error
    redirect-policy-error
#+end_example

Adapter/library conditions may be attached under =:details= or cause metadata
but SHALL NOT be required by callers to classify a resolver failure.

* Phase 1 implementation slice

Implement in =lost-rob0t/star-lang= without adding external Common Lisp
libraries:

1. add resolver context/effect-port protocol;
2. create compatibility digest adapter around current =sha256sum= behavior;
3. create compatibility fetch adapter around current bounded =curl= behavior;
4. replace direct calls from cache/import/root resolver logic with port calls;
5. propagate one context through recursive imports;
6. add fake digest/fetch adapters for deterministic tests;
7. prove offline cache hits never call fetch;
8. prove remote cache misses call fetch only when network is enabled;
9. preserve source size, digest, cache promotion, provenance, and error behavior;
10. keep all current tests green under ASDF and Nix.

Phase 1 does NOT satisfy the shell-removal completion gate because compatibility
adapters still execute processes.

* Phase 2 implementation slice

After Phase 1 is green:

1. add an Ironclad SHA-256 adapter;
2. add a bounded native HTTPS adapter, with Dexador as the current candidate;
3. explicitly disable ambient proxy behavior;
4. enforce HTTPS on each redirect hop;
5. stream to the resolver-owned temporary file under the byte limit;
6. update ASDF and Nix dependencies;
7. test timeout, redirect, TLS-policy, oversize, cache-hit, cache-miss, digest
   mismatch, and cleanup paths;
8. switch defaults to the native adapters;
9. delete shell compatibility adapters when parity is green;
10. add CI proving normal resolver tests do not require =curl= or =sha256sum=.

* Packaging

Effect protocol and resolver semantics should be independently loadable from
concrete adapters.

Target dependency direction:

#+begin_example
star-resolver-core
  -> star-resolver-port

star-resolver-digest-ironclad
  -> star-resolver-port + ironclad

star-resolver-http
  -> star-resolver-port + selected HTTP client

starlang-compiler
  -> resolved graph / compiler IR
  -X-> HTTP client
#+end_example

The exact final ASDF system names may be aligned with the package-extraction
pass. The invariant is that compiler-only loading does not drag in networking.

* Compatibility

Existing public entry points =load-star-file= and =load-star-url= should remain
callable with their current keywords during migration. New effect configuration
may be optional keywords or an explicit resolver-context keyword.

No source-language syntax change is required.

* Approved Prototype Retirement

The prototype implementation is temporary migration scaffolding, not a supported
long-term runtime tier.

- No new resolver behavior may be implemented only under =prototype/=.
- When a resolver behavior has a final-system owner, prototype callers SHALL be
  redirected to that owner and the duplicate prototype implementation SHALL be
  deleted in the same migration slice whenever practical.
- Compatibility wrappers may exist only while tracked callers still require
  them; wrappers MUST contain no independent resolver policy.
- Final resolver, compiler, runtime, and adapter ASDF systems MUST NOT depend on
  =starlang-prototype= or load files from =prototype/=.
- Once the final resolver path passes its direct ASDF, Nix, offline-cache,
  security, and aggregate conformance gates, the corresponding prototype
  resolver files and shell compatibility paths SHALL be removed rather than
  retained as a second implementation.
- Repository-wide prototype retirement is verified by the dedicated StarLang
  completion/removal issue created from the 2026-08-29 operator approval.

* Acceptance

Phase 1 is conformant when:

1. resolver-core code contains no direct =uiop:run-program= call;
2. current shell behavior exists only behind compatibility ports;
3. recursive imports inherit one resolver context;
4. fake ports can resolve local/cached/remote test graphs deterministically;
5. =:allow-network nil= prevents every fetch-port call;
6. digest mismatches are rejected before parsing;
7. cache promotion remains verified-temp-file then rename;
8. existing source span/import-origin diagnostics remain intact;
9. existing StarLang tests remain green;
10. Nix remains green with no new dependency in Phase 1.

Phase 2 is conformant when:

1. native Common Lisp SHA-256 and HTTPS adapters are green;
2. default resolver execution no longer invokes =curl= or =sha256sum=;
3. redirect/TLS/proxy/timeout/byte-limit tests exercise the native adapter;
4. ASDF/Nix dependency direction keeps networking out of compiler-only systems;
5. the shell-removal item in the implementation ledger may then be marked done;
6. no final resolver system depends on =starlang-prototype= or =prototype/=.

* Deferred work

- publisher signatures and trust roots;
- OCI registry transport;
- distributed artifact mirrors;
- package registry discovery;
- HTTP caching semantics beyond the digest-addressed StarLang cache;
- changing the source-level import syntax;
- moving network access into runtime actors.

* Footnotes and Glossary

- *Effect port* — Injected protocol by which pure resolver policy invokes a concrete side effect.
- *Resolver context* — Trusted configuration and effect bundle inherited through one resolution graph.
- *Compatibility adapter* — Transitional implementation that preserves current behavior behind the new port boundary.
- *Native adapter* — Common Lisp implementation of an effect, such as Ironclad SHA-256 or bounded HTTPS transport.
- *Compiler-only closure* — ASDF/Nix dependency set sufficient to compile already resolved StarLang graphs without an HTTP client or network execution.
- *Prototype retirement* — Removal of the transitional =prototype/= implementation after final-system ownership and conformance are proven.
