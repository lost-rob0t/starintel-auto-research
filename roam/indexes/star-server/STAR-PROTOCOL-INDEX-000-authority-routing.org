* Key Current Decisions Under Review

1. Generalize =star://= to =star://<authority>/<kind>/<resource-path>=.
2. Move actors to =/actor/<domain>/<actor-name>= and remove runtime location from canonical identity.
3. Define a STAR application protocol above ZeroMQ, RabbitMQ, HTTP, and local transports.
4. Make StarRouter the authority-aware identity/control-plane router.
5. Let =starintel-gserver= register its own authority and authoritative resource/service paths.
6. Keep RabbitMQ as StarIntel's durable distributed actor/document dataflow.
7. Move FediWatch durable target intake and document output to RabbitMQ while retaining optional STAR identity/control routing.

* Footnotes and Glossary

- *Authority routing* — Resolving the authority component of a canonical STAR URI to an authorized registered runtime route before forwarding a protocol operation.
- *Identity/control plane* — STAR URI, registration, discovery, and routed request semantics that do not themselves provide durable document storage.
- *Durable dataflow* — RabbitMQ-backed distributed work/document/event delivery with explicit acknowledgement and retry semantics.
