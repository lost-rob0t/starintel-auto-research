* Status

This note is retained as a historical analysis of the original JavaScript prototype. Its architecture decision is superseded by [[file:STAR-RESEARCH-006-cl-discord-self-common-lisp-port.org][STAR-RESEARCH-006 cl-discord-self Common Lisp Port]].

The detailed runtime architecture is defined by [[file:../../design/star-server/STAR-DISCORD-001-cl-discord-self-runtime.org][STAR-DISCORD-001 cl-discord-self Runtime Architecture]].

The former law-enforcement-only deployment assumption is rejected. It is not an eligibility requirement for the library, the actor, or the runtime.

* Corrected Decision

=cl-discord-self= is a reusable Common Lisp library that anyone may run, inspect, modify, and integrate subject to its license and the platform rules applicable to their own account and deployment.

The first supported profile is intentionally read-only:

- receive Gateway events;
- retrieve bounded message history and referenced resources;
- retrieve attachment data within configured limits;
- preserve raw events and typed models;
- maintain session, reconnect, rate-limit, and checkpoint state;
- expose deterministic replay and compatibility fixtures.

The initial profile does not include:

- sending messages;
- invoking interactions or application commands;
- command or task automation frameworks;
- unsolicited messaging;
- mass-account operation;
- automatic fingerprint rotation;
- anti-abuse bypass behavior.

These exclusions define the current implementation scope. They are not a claim that only a government, company, or approved class of operator may use the code.

Broader Discord client functionality may be designed later as a separate compatibility profile or project. That future work is not part of the current approval and must not block the read-only runtime.

Common Lisp is an implementation and maintenance choice, not a security boundary. Abuse resistance must come from explicit capabilities, bounded operations, rate handling, secret isolation, and deployment policy rather than assumptions about the language or size of its user base.

* Policy Boundary

The reusable library owns Discord protocol behavior, transport contracts, models, events, rate limits, and session state.

Deployment-specific policy belongs above the library. A StarIntel actor may impose target scopes, dataset rules, credential leases, expiration, audit records, and publication controls without making those controls mandatory for every independent user of =cl-discord-self=.

The architecture therefore separates:

1. a public protocol library;
2. an optional application or client built on that library;
3. StarIntel-specific collection, normalization, storage, and publication policy.

* Supersession

Use =STAR-RESEARCH-006= for the current port decision. Use =STAR-DISCORD-001= for the implementation architecture.

The original prototype audit and defect inventory remain available in Git history, but this note no longer defines the active architecture or an LEO-specific access model.
