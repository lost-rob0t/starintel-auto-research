#+title: STAR-PRO-CAPTCHA-004 Self-Sourced Local Solver Fabric
#+description: Review-only StarIntel Pro Actors design for a local-first CAPTCHA solver fabric with synthetic corpus generation, model registry, benchmark gates, OCR/audio/vision/geometric solvers, bounded multi-step policies, abstention, manual fallback, and disabled-by-default paid providers.
#+status: REVIEW
#+filetags: :starintel:design:starintel-pro-actors:captcha:local:actors:rabbitmq:ml:ocr:vision:audio:synthetic-data:uml:

* Decision

Build a local-first =CaptchaLocalSolverFabric= behind the existing [[id:star-captcha-000-broker-router][CaptchaBrokerActor]].

The fabric is not one solver. It is a set of independently registered capability actors with exact benchmark evidence. The broker routes to local capabilities before external paid providers when the request, target policy, challenge family, result kind, binding, deadline, and confidence policy all match.

External provider adapters remain available as separately controlled capabilities, but the default operator policy for this design is =externalProvidersEnabled: false=. Unsupported or low-confidence local work must abstain, fall back to a source-acquisition alternative, enter manual review, or fail closed rather than silently buying a solve.

Common Lisp owns authorization, policy, actor lifecycle, capability routing, transport, deadlines, secret references, and downstream verification. ML-heavy inference and training run in separately supervised local workers, initially Python, over the existing actor/RabbitMQ boundary.

* Goals

- minimize recurring per-solve CAPTCHA cost;
- keep challenge material local whenever possible;
- self-generate labeled training and evaluation data;
- use cheap specialized solvers before expensive reasoning models;
- preserve exact capability registration and abstention;
- keep paid providers outside the default hot path;
- preserve the existing StarIntel broker, actor index, RabbitMQ, policy, and ephemeral-secret design;
- make every promoted model reproducible and rollbackable.

* Non-Goals

- a public arbitrary-target solve endpoint;
- browser fingerprint fabrication;
- arbitrary JavaScript generation or execution by a model;
- a wildcard “solve any CAPTCHA” capability;
- uncontrolled retention of live challenge material;
- training dependencies inside the Common Lisp server process;
- copying proprietary vendor implementations or making live vendor challenge harvesting a required corpus source.

| =CaptchaCorpusActor= | Common Lisp control + generator workers | deterministic synthetic sample jobs, imports, manifests, provenance |
| =CaptchaTrainerActor= | Common Lisp control + Python training worker | offline train/fine-tune jobs; never in solve hot path |

The existing =CaptchaBrokerActor= remains authoritative for top-level authorization and exact provider/solver eligibility. The local router is not a second broker.

* Control and ML Boundary

The Common Lisp side owns:

- actor identity and supervision;
- target policy and authorization context;
- exact capability selection;
- artifact-reference issuance;
- RabbitMQ envelope and correlation IDs;
- deadlines and cancellation;
- model registry authority;
- benchmark promotion state;
- result references and one-read leases;
- downstream verification;
- audit and redacted telemetry.

The Python worker side owns only bounded model operations:

- load a named hash-pinned model/runtime;
- read a bounded artifact reference;
- perform inference or an offline train/evaluation task;
- return a typed candidate result plus confidence/metrics;
- release local buffers and temporary files.

Workers never decide target authorization and never receive raw provider credentials.

* Artifact-Reference Rule

Images, audio, model weights, corpora, and large intermediate artifacts do not travel as ordinary RabbitMQ message bodies.

Messages carry short references with bounded leases:

#+begin_src json
{
  "artifactRef": "artifact://ephemeral/captcha/input/01KZ...",
  "mediaType": "image/png",
  "sha256": "...",
  "sizeBytes": 48123,
  "expiresAt": "2026-08-09T15:30:00Z"
}
#+end_src

The worker validates hash, size, media type, and lease before loading the artifact.

* Local Solve Request

The local router receives an already-authorized attempt from the broker.

#+begin_src json
{
  "messageType": "captchaLocalSolveRequest",
  "requestId": "01KZ...",
  "attemptId": "01KZ...-local-01",
  "capabilityId": "captcha.text.distorted.alnum.v1",
  "challenge": {
    "family": "textRecognition",
    "variant": "distortedAlphanumeric",
    "inputRef": "artifact://ephemeral/captcha/input/01KZ...",
    "instruction": null,
    "requiredResultKind": "textAnswer"
  },
  "policy": {
    "minimumConfidence": 0.92,
    "maximumSteps": 1,
    "allowManualFallback": true,
    "allowExternalFallback": false
  },

}

The exact capability ID selects the worker/model candidate set. Workers do not infer permission from the image itself.

* Exact Local Capability Examples

Initial capabilities are examples and remain =experimental= until benchmark gates pass.

| Capability | Worker | Result kind | Initial state |
|------------+--------+-------------+---------------|
| =captcha.text.distorted.alnum.v1= | text OCR ensemble | =textAnswer= | experimental |
| =captcha.audio.shortDigits.en.v1= | faster-whisper pipeline | =textAnswer= | experimental |
| =captcha.image.semanticGrid.selection.v1= | vision scorer/classifier | =selectionSet= | experimental |
| =captcha.synthetic.slider.offset.v1= | geometry solver | =coordinates= | experimental |
| =captcha.synthetic.iconSequence.v1= | puzzle policy | =interactionPlan= | experimental |
| =captcha.synthetic.jigsaw.simple.v1= | geometry/puzzle policy | =interactionPlan= | experimental |

Do not register hCaptcha, reCAPTCHA, Turnstile, Arkose, GeeTest, or any other vendor brand as a local capability merely because a generic model can recognize a visually similar synthetic task. Vendor integration/result binding remains a separate exact contract.

* Text Solver Design

=CaptchaTextSolverActor= uses an ensemble rather than trusting one OCR engine.

Pipeline:

1. validate input artifact and image bounds;
2. run a bounded preprocessing set chosen by exact capability configuration;
3. run PaddleOCR candidate recognition;
4. run Tesseract candidate recognition;
5. optionally run a small specialized character recognizer when registered;
6. normalize candidates under the capability's alphabet/length constraints;
7. calculate calibrated confidence from engine confidence, agreement, and benchmark calibration;
8. store the answer only if threshold passes;
9. otherwise abstain.

The actor must cap preprocessing variants to prevent combinatorial work.

* Audio Solver Design

=CaptchaAudioSolverActor= uses a short-form ASR configuration.

Pipeline:

- decode bounded audio formats;
- normalize sample rate and amplitude;
- optional bounded denoise/VAD;
- transcribe with a pinned faster-whisper model;
- normalize against capability vocabulary;
- preserve alternate hypotheses for confidence calculation only;
- store final typed answer when threshold passes;
- abstain on weak or conflicting hypotheses.

No raw audio is persisted after the ephemeral artifact lease unless the source class explicitly permits corpus retention.

* Vision Solver Design

=CaptchaVisionSolverActor= supports exact semantic-selection families.

It may use:

- a family-specific classifier;
- OpenCLIP-style image/text similarity;
- a licensed detector/segmenter after separate dependency review;
- an ensemble of the above.

For a grid task, the worker receives pre-segmented tile coordinates when the source runtime can provide them reliably. Otherwise, segmentation itself is an exact capability requirement and must be benchmarked.

The result is a =selectionSet= of tile identifiers, not arbitrary click coordinates, whenever the source runtime already owns tile geometry.

This separation prevents visual model coordinate drift from becoming a browser-control bug.

* Geometry Solver Design

=CaptchaGeometrySolverActor= covers deterministic puzzle families using OpenCV-style operations.

Candidate primitives:

- template matching;
- feature matching;
- edge/contour extraction;
- cross-correlation;
- image difference;
- geometric transform estimation;
- bounded search over slider/alignment offsets.

Every primitive is internal implementation detail. The registered capability still states the exact puzzle family and result schema.

* Multi-Step Puzzle Policy

=CaptchaPuzzlePolicyActor= is the only local solver allowed to request iterative source observations.

It receives a bounded action schema defined by the capability, for example:

#+begin_src json
{
  "allowedActions": [
    {"type": "clickTile", "tileIds": [0,1,2,3,4,5,6,7,8]},
    {"type": "submit"},
    {"type": "abstain"}
  ],
  "maximumSteps": 6
}
#+end_src

It cannot emit:

- arbitrary URLs;
- JavaScript;
- shell commands;
- unrestricted mouse coordinates when a symbolic action exists;
- new network requests;
- new credentials or cookies;
- actions outside the exact capability schema.

Sequence:

#+begin_src plantuml
@startuml
participant "CaptchaRunActor" as Run
participant "PuzzlePolicyActor" as Policy
participant "Source Runtime" as Source

Run -> Policy : observationRef + exact action schema
Policy --> Run : bounded action candidate + confidence
alt confidence sufficient
  Run -> Source : apply typed action
  Source --> Run : next observationRef + verification state
  alt terminal success
    Run -> Policy : terminal feedback
    Policy --> Run : interactionPlan / success metadata
  else more steps allowed
    Run -> Policy : next observationRef + historyRef
  end
else low confidence
  Policy --> Run : abstain
end
@enduml
#+end_src

The source runtime remains the only component that applies browser/UI actions.

* Corpus Actor

=CaptchaCorpusActor= owns corpus manifests, not model training.

Supported source classes:

| Source class | Default retention | Use |
|--------------+-------------------+-----|
| =synthetic= | durable | primary training/evaluation source |
| =openBenchmark= | durable if license permits | external evaluation and optional training when permitted |
| =firstPartyFixture= | durable | integration and regression |
| =operatorLabeled= | durable only with explicit provenance | hard-case augmentation |
| =authorizedCanary= | ephemeral by default | generalization measurement |

Corpus generation jobs must include generator version and seed.

#+begin_src json
{
  "messageType": "captchaCorpusGenerateRequest",
  "jobId": "captcha-corpus-job:01KZ...",
  "generatorId": "starCaptchaGen.imageSelection.v1",
  "count": 10000,
  "seed": 1729,
  "outputSplit": "train",
  "variationProfile": "wide-v1",
  "manifestPolicy": "contentAddressed"
}
#+end_src

The generated manifest is immutable and content-addressed. A changed generator creates a new corpus version.

* Synthetic Generator Requirements

Every generator must expose:

- deterministic seed control;
- exact ground truth;
- source image/font/audio license metadata;
- renderer configuration;
- difficulty parameters;
- region annotations when applicable;
- process/action annotations when applicable;
- a human-solvability smoke test profile;
- train/validation/test leakage controls.

Difficulty is a first-class variable. The benchmark should include easy, medium, hard, and out-of-distribution renderer profiles rather than only one random setting.

* Trainer Actor

=CaptchaTrainerActor= coordinates offline jobs only.

It accepts immutable corpus/model/config references and produces a new candidate artifact plus training report.

#+begin_src json
{
  "messageType": "captchaTrainRequest",
  "trainingJobId": "captcha-train:01KZ...",
  "baseModelRef": "model://open/local-vlm/base@sha256:...",
  "corpusManifestRef": "artifact://captcha/corpus/manifest@sha256:...",
  "trainingConfigRef": "artifact://captcha/train/config@sha256:...",
  "requestedCapabilityId": "captcha.synthetic.iconSequence.v1"
}
#+end_src

Training completion does not register a runtime capability. The new model enters =candidate= state and must pass benchmark promotion.

* Benchmark Actor

=CaptchaBenchmarkActor= runs frozen suites and writes signed/hashed evidence records.

Required suites:

- deterministic unit fixtures;
- held-out synthetic renderer split;
- held-out asset pool split;
- difficulty-stratified suite;
- imported open benchmark when permitted;
- first-party integration fixtures;
- opt-in authorized canary suite for final generalization evidence.

Required metrics vary by result kind:

| Result kind | Required metrics |
|-------------+------------------|
| =textAnswer= | exact accuracy, character error rate, calibration, abstention |
| =selectionSet= | exact-set accuracy, precision, recall, calibration, false-action rate |
| =coordinates= | hit rate, pixel/normalized error, false-action rate |
| =interactionPlan= | task completion, steps, invalid-action rate, timeout rate, false-action rate |

All capabilities also record p50/p95 latency, memory, CPU/GPU utilization, and cost estimate.

* Promotion State Machine

#+begin_src plantuml
@startuml
[*] --> candidate
candidate --> experimental : deterministic fixtures pass
candidate --> rejected : fixtures fail
experimental --> shadow : frozen benchmark threshold passes
shadow --> verified : shadow/canary evidence and review pass
shadow --> degraded : regression or weak calibration
verified --> degraded : benchmark drift or runtime regression
verified --> disabled : operator action or artifact/security issue
degraded --> verified : repaired model passes full gate
degraded --> disabled : repeated failure
experimental --> invalidContract : output schema/runtime drift
verified --> invalidContract : output schema/runtime drift
invalidContract --> candidate : replacement artifact submitted
disabled --> candidate : explicit re-evaluation
@enduml
#+end_src

Broker eligibility requires =verified= unless operator policy explicitly permits =experimental= for an owned test environment.

* Local Routing

The local router applies hard eligibility first:

1. exact capability ID;
2. model state;
3. required result kind;
4. input media/schema;
5. model/runtime availability;
6. deadline fit;
7. worker concurrency;
8. policy confidence threshold;
9. source-session/action requirements;
10. license/deployment policy.

Only then may it rank local candidates by:

1. benchmark acceptance/success rate;
2. false-action rate;
3. calibration quality;
4. latency;
5. compute cost;
6. operator preference.

Local inference cost is not assumed to be zero. Telemetry tracks estimated CPU/GPU time and amortized training cost, but there is no per-solve external provider charge.

* Fallback Policy

Default order:

1. exact verified local specialized solver;
2. exact verified local generic solver;
3. exact experimental local solver only when test policy explicitly permits;
4. alternate authorized source-acquisition path when one exists;
5. manual review if permitted;
6. external provider only when =externalProvidersEnabled=true= and the broker's existing authorization/disclosure/budget rules pass;
7. terminal unsupported/abstained result.

A local solver may not automatically toggle external providers on.

* Manual Review Boundary

Manual review is not a hidden “human solver service.” It is an explicit local operator queue with:

- target and purpose visible;
- disclosure class =localOperator=;
- bounded artifact lease;
- no durable cookie/token display unless required and authorized;
- result typed through the same result union;
- timeout and cancellation;
- full audit without raw sensitive result persistence.

* Operations

Recommended initial deployment:

- one Common Lisp local-router actor;
- one long-lived OCR worker pool;
- one audio worker pool loaded on demand;
- one vision worker pool with small models resident;
- one geometry worker pool;
- zero resident large VLM workers until a hard task arrives;
- training workers disabled in the production solve service by default;
- benchmark workers run offline or on a low-priority queue.

Worker supervision must include memory ceilings and crash restart limits. A repeatedly crashing model is disabled by the registry/circuit rather than continuously restarted.

* Queue Separation

Do not mix hot-path solve work with training.

Suggested logical queues:

- =captcha.local.solve.text=
- =captcha.local.solve.audio=
- =captcha.local.solve.vision=
- =captcha.local.solve.geometry=
- =captcha.local.solve.puzzle=
- =captcha.local.benchmark=
- =captcha.local.train=
- =captcha.local.corpus=

Actual exchange/queue names remain deployment configuration and are not domain semantics in the portable message schema.

* Cancellation and Deadlines

All local attempts are cancellable.

- router journals =attemptId= before dispatch;
- duplicate delivery attaches to the same attempt;
- worker checks deadline before loading heavy models/input;
- training and benchmark jobs use separate long deadlines;
- cancellation stops future actions even if an inference call cannot be interrupted immediately;
- late worker results are discarded after the attempt terminal state;
- ephemeral input/result leases are revoked on terminal cancellation.

* Security Invariants

1. The broker's existing authentication, =captcha:solve= capability, target policy, purpose, and disclosure checks run before the local router.
2. Local worker identity is authenticated to the actor fabric.
3. Input artifacts are bounded by size, media type, hash, and lease.
4. Model artifacts are hash-pinned and come only from approved model-registry entries.
5. Training corpus provenance and licenses are recorded.
6. Model output is constrained to an exact typed schema.
7. Puzzle policy actions are capability-specific and bounded.
8. The source runtime applies actions; ML workers do not control browsers directly.
9. Sensitive final answers/tokens/cookies use the ephemeral secret store and opaque references.
10. Live authorized challenge captures are ephemeral unless retention is explicitly approved.
11. External providers stay disabled by default in this design.
12. No solver is promoted from confidence score alone; held-out benchmark evidence is mandatory.

* Failure Modes

| Failure | Behavior |
|---------+----------|
| OCR engines disagree | lower confidence or abstain |
| model artifact hash mismatch | disable model; security event |
| worker crashes | fail attempt or retry another exact local candidate within deadline |
| model exceeds memory ceiling | kill worker; mark model degraded/disabled |
| invalid output schema | exact capability =invalidContract= |
| benchmark regression | demote capability and restore rollback model |
| corpus manifest drift | reject training/benchmark job |
| low confidence | abstain; do not guess |
| multi-step invalid action | reject action; count false-action metric; usually terminate local run |
| deadline expired | cancel local work and revoke leases |
| no local capability | apply explicit fallback policy |

* Test Plan

Continuous integration uses no paid provider and no live third-party challenge.

Required tests:

- local router exact-capability matching;
- external provider disabled-by-default behavior;
- text-answer fixture success and disagreement abstention;
- audio fixture success and low-confidence abstention;
- selection-set fixture success and false-selection rejection;
- geometry coordinate tolerance;
- multi-step action-schema enforcement;
- arbitrary action/URL/JavaScript rejection;
- artifact size/media/hash/expiry enforcement;
- worker duplicate delivery and idempotent terminal replay;
- cancellation before load, during inference, and after late result;
- model hash mismatch;
- model registry promotion/demotion/rollback;
- deterministic corpus regeneration from seed;
- train/validation/test style-pool isolation checks;
- corpus license/provenance validation;
- benchmark threshold failure;
- result-secret redaction;
- RabbitMQ messages contain references rather than raw large media;
- worker crash circuit behavior;
- shutdown with active solve jobs and offline training jobs.

* Implementation Slices

** Slice 1 — Corpus and benchmark skeleton

- add corpus manifest schema;
- add deterministic generator interface;
- add benchmark suite schema;
- add model registry actor and states;
- implement fake model worker;
- prove promotion/rollback without ML dependencies.

** Slice 2 — Text and audio

- PaddleOCR worker;
- Tesseract worker or subprocess adapter;
- text ensemble/calibration;
- faster-whisper short-audio worker;
- synthetic text/audio corpus generators;
- benchmark thresholds and abstention.

** Slice 3 — Geometry and semantic vision

- OpenCV geometry worker;
- OpenCLIP or approved small semantic classifier worker;
- grid/selection generator;
- slider/alignment generator;
- selection/coordinate benchmark metrics.

** Slice 4 — Multi-step policy

- synthetic icon sequence/jigsaw/interaction generator;
- bounded action schema;
- iterative observation protocol;
- specialized local VLM/policy candidate;
- process-supervision benchmark;
- strict false-action gate.

** Slice 5 — Production local-first routing

- register only verified local capabilities;
- rank local before external provider;
- keep external providers default-off;
- add manual/source fallback policy;
- collect accepted-result, latency, compute, and abstention telemetry;
- compare cost per accepted solve against existing provider baselines.

* Research-to-Design Decisions

| Research finding | Design consequence |
|------------------+-------------------|
| synthetic process-labeled data is practical | corpus generator and trainer are first-class actors |
| interactive puzzles require closed-loop state | multi-step policy gets bounded iterative observation protocol |
| general multimodal agents remain inconsistent | specialized exact solvers route before generic reasoning |
| OCR/audio/CV are cheap locally | persistent lightweight workers handle common families |
| provider integration test keys exist | CI tests broker/source flow without paid solves |
| local model errors can cause destructive UI actions | action schema, false-action metric, source-runtime application, abstention |
| model training/runtime stacks evolve independently of server | Common Lisp control and Python worker boundary |
