* Scope

This note corrects the previous hCaptcha-only audit. CapSolver, Anti-Captcha, and CapMonster Cloud must not be rejected as whole providers merely because their current catalogs do not advertise hCaptcha. They may still cover reCAPTCHA, Turnstile, Arkose, GeeTest, Amazon Web Services Web Application Firewall, DataDome, Friendly Captcha, ALTCHA, MTCaptcha, image tasks, or custom tasks.[fn:waf]

The broker registers exact capabilities. Missing one family is a capability gap, not a global provider verdict.

* CapSolver

The current supported-task and pricing surfaces list a broad set of token and anti-bot families but do not list hCaptcha. The architecture implication is:

- do not implement or advertise =captcha.hcaptcha.*=;
- evaluate CapSolver where StarIntel lacks verified Turnstile, reCAPTCHA, GeeTest, MTCaptcha, DataDome, AWS WAF, or Cloudflare challenge coverage;
- require an exact official task page and request/result fixture for every enabled capability;
- record whether the provider is fully automated, human-assisted, or mixed for disclosure policy.

* Anti-Captcha

The current official task index documents:

- image-to-text and image-to-coordinates;
- reCAPTCHA v2/v3 and Enterprise;
- Arkose Labs FunCaptcha;
- GeeTest;
- Cloudflare Turnstile;
- Prosopo;
- Friendly Captcha;
- Amazon WAF;
- ALTCHA;
- custom AntiGate tasks.

This is a materially useful broad catalog. An Anti-Captcha adapter should be prioritized when these capabilities remain uncovered or when operational redundancy is required. Custom AntiGate work needs additional scrutiny because programmable target-specific templates can exceed a normal normalized CAPTCHA contract.

* CapMonster Cloud

The current catalog advertises multiple token and puzzle families but not hCaptcha. The same exact-capability rule applies. Historical unsupported-task reports for hCaptcha remain valid only for the hCaptcha row; they are not evidence against every other task.

* Adapter Selection Gate

A provider receives a new adapter design only when:

1. a current official task page defines request and result schemas;
2. the capability closes a measured coverage or redundancy gap;
3. authentication and error contracts are documented;
4. result kind and context binding map to the normalized broker protocol;
5. execution and disclosure class are known;
6. cost, concurrency, cancellation, and ambiguous-create behavior are understood;
7. mock fixtures pass;
8. a bounded owned-system canary is approved.

* Reconsidering a Missing Capability

A previously absent capability such as hCaptcha can be added only when all of these exist:

1. a current official provider page naming the task;
2. a documented create request and result request;
3. a documented result field and variant behavior;
4. a documented authentication method and error table;
5. a successful fixture or live canary against an operator-owned test page;
6. a recorded contract retrieval date and fixture fingerprint.

A stale software-development kit alone is insufficient.[fn:sdk]

* Provider Ranking

Do not rank providers by count of marketing logos. Rank by:

- uncovered exact capabilities;
- contract clarity and drift history;
- result acceptance rate;
- disclosure class;
- session and network-binding compatibility;
- cancellation and ambiguous-submission behavior;
- cost and concurrency;
- operational redundancy value.
