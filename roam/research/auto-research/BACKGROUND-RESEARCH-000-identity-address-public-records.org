* Executive Finding

*KEEP AS A SOURCE FAMILY.* Identity resolution should be assembled from multiple source-backed observations rather than from one synthetic person profile. Ohio is a strong first mirror target because the Secretary of State publishes raw daily county voter-registration snapshots and statewide daily packages, retained for at least twenty-two months. Those snapshots can support temporal address and registration observations while preserving exact source releases.

Property, recorder, business-registration, professional-license, court, and other public records should contribute independent identity observations. A name match alone must remain a candidate. Promotion to a person identity requires corroborating attributes and preserved contradiction state.

* Source Findings

** Ohio daily voter-registration snapshots

The Ohio Secretary of State DATA Act portal publishes the county voter-registration files exactly as supplied by the county boards of elections. Each county produces a prescribed daily snapshot, statewide single-day packages contain all eighty-eight counties, and files remain available for a minimum of twenty-two months. Large searches are delivered as bulk downloads.

This is suitable for a local mirror with immutable release metadata:

- snapshot date
- county
- election-period association where applicable
- source archive name and locator
- retrieval timestamp
- byte length
- content hash
- parser version
- row count
- prior-release relationship

The mirror should derive change observations rather than overwrite a person record. Address, name, registration-status, and other changes should produce temporal assertions with source lineage.

** County auditor and recorder records

County property and recorder systems can associate names and organizations with parcels, deeds, mortgages, releases, and recorded instruments. These systems are jurisdiction-specific even when several counties share a vendor platform.

For the Franklin County pilot, the Auditor property-search system and Recorder public-record search are official source candidates. Their exact request and result contracts require a dedicated live protocol probe before runtime capability is advertised.

** State business records

The Ohio Secretary of State exposes business search, downloadable business reports, cancelled and dissolved entity reports, and a business-data portal. Business records can provide organization names, filing events, statutory-agent observations, addresses, and entity lifecycle events.

A background-report pipeline should retain the business entity as a separate object and create sourced relations from a person or address to that entity. It should not flatten an officer, filer, agent, or incorporator role into generic employment.

* Identity Resolution Rules

Identity evidence should be typed by source and strength.

| Signal | Default use |
|--------+-------------|
| exact full name only | candidate generation |
| name plus same city or county | weak corroboration |
| name plus stable address overlap | stronger corroboration |
| name plus date-of-birth or age-compatible court data | stronger corroboration |
| unique source identifier tied across releases | strong within-source continuity |
| conflicting middle name, birth date, or geography | explicit contradiction |

No source is allowed to silently merge two candidate people. The resolver must preserve alternate candidates and the evidence that caused each candidate to exist.

* Mirroring Decision

** Mirror immediately

- Ohio daily voter-registration snapshots
- Ohio statewide daily voter packages
- Ohio business downloadable reports once exact report endpoints and schemas are profiled

** Query and cache by jurisdiction

- county property systems
- county recorder systems
- state and local professional-license systems where no bulk release exists

** Derive locally

- address-history assertions
- first-seen and last-seen intervals
- person-to-address candidate relations
- business-to-address relations
- cross-source identity confidence
- contradictory identity assertions

* Required Acquisition Metadata

Every mirrored or queried observation needs:

- source-profile ID and revision
- source-release or query ID
- source-native identifier
- source URL or locator
- retrieved-at timestamp
- observed source update timestamp where published
- content hash or immutable response artifact
- parser and normalizer versions
- normalized fields
- record validity or effective dates when supplied
- source caveats

* Research Gaps

- Profile the exact downloadable Ohio business-report endpoints, schemas, cadence, and historical availability.
- Profile Franklin County Auditor and Recorder request/result contracts.
- Enumerate other states with bulk voter files and the temporal history available in each state.
- Define the minimum independent signals required before two cross-source person candidates merge.
- Define protected-address handling for source records that intentionally suppress an address.

* Footnotes and Glossary

- *Identity observation*: A source-backed statement about a person or organization that does not by itself prove cross-source identity.
- *Candidate merge*: A proposed assertion that two source records refer to the same real-world entity.
- *Temporal assertion*: A claim whose validity or observation time is recorded separately from ingest time.
- *Mirror*: A locally preserved copy of a public dataset release with immutable provenance and replay metadata.
